# F 线 · 一线手机端 UX Flow Analysis（结构 8）

按仓库 `.claude/skills/ux-flow/SKILL.md` Phase 1 先做分析，再出方案；对照 `.claude/rules/fool-proof-design.md` 五条规则与 `docs/ux/ai-chat-standard.md` 一线硬约束 H1–H5。原型页面 `/crew/mobile`（375×812 外壳，`src/crew/CrewMobile.vue`）。

## UX Flow Analysis

### 用户画像
- 操作员 — 文化程度参差、戴手套、站在产线边，单手拿手机 — 每道工序做完要报一笔（称重 / 数量），不想找菜单。
- 仓管 — 年纪偏大、不熟软件（客户原话：「告诉他这个东西你要收多少就行了」）— 收货、核库存，按系统提示去库里看。
- 质检员 — 熟悉产品、不熟系统 — 现场发现不合格要马上报给质量经理。

### 用户旅程
| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|---|---|---|---|
| 1 | 顶栏只有一位数字员工（按岗位自动对应），中间大麦克风「按住说话」，下面「今天要办的」 | 不选人，直接看今天的事 | 知道今天要报哪几张工单 / 核哪几样库存 |
| 2 | 每件事一张卡：产品名 + 工单号 + 计划量 + 已报工序 | 点一张卡 | 进入这件事，不用再找工单 |
| 3 | 标题「称重报工 — 产品名（工单号）」，工序下拉（默认最近一道）、重量大字输入 | 选工序、输重量 | 输错格式时字段旁说怎么改，已填的不清空 |
| 4 | 「下一步：看一眼再确认」唯一主按钮 → 确认卡逐行列出要写入的内容 | 看一眼，点「确认并办理」 | 写入成功显示「已办成」及记录号；未接接口的明确显示「原型演示，未执行」 |
| 5 | 结果 + 「回到今天要办的」 | 点返回 | 回到清单，继续下一件 |

### 摩擦点清单
| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|---|---|---|
| F1 | 管理端有五位数字员工，一线要先「选人」才能办事，选错就找不到功能 | HIGH | 内联 UX 规则：每屏只暴露当前步骤需要的信息；任务原文结构 8 |
| F2 | 进 App 后要自己找工单 / 物料，工单号长、相似产品多 | HIGH | fool-proof Rule 2（上下文必带身份信息） |
| F3 | 数字输入小、单位不明，容易把 130 写成 13 或填成「盒」 | HIGH | 内联 UX 规则：数字输入 ≥ 24px；fool-proof Rule 1 |
| F4 | 报错只说「提交失败」，重填一遍 | MED | 内联 UX 规则：错误恢复「发生了什么 + 怎么解决」，保留已填 |
| F5 | AI 直接替人写入，或写了一半不知道成没成 | HIGH | ai-chat-standard H2 / H3 / H5；fool-proof Rule 4 |
| F6 | 只能打字，戴手套不方便 | MED | ai-chat-standard H1（语音优先） |
| F7 | 加载时出现看不懂的骨架屏 | LOW | ux-flow：一线不熟悉 skeleton 语义 |

### 每个摩擦点的设计回应
- F1 → 按登录人岗位只给一个入口：操作员 → 数字计划员，仓管 → 数字仓管，质检员 → 数字质检员。手机端没有「切换员工」。**如实说明（F-17）**：这个对应现在是代码常量（`crew-config.ts` 的 `DEMO_ROLES[*].mobile`），不是工厂配置；做成工厂级配置列在缺口清单 D4。本厂停用了这位员工时，手机端显示「本厂没有启用数字 X，找管理员」，不给入口（F-6）。
- F2 → 「今天要办的」直接列真实事项：操作员 = 今天计划开工的黑湖工单（产品名 + 工单号 + 计划量 + 已报工序）；仓管 = 近 7 天在生产但原料库存快照全为 0 的产品；质检员 = 今天的工单。点卡即进入，单件事不再二次选择。
- F3 → 重量输入框 56px 高、28px 大字，单位写在标签里（kg），只收数字和最多两位小数；格式错时按钮不可点（Rule 1 预先显示边界）。
- F4 → 错误文案在字段旁：「只填数字，最多两位小数，例如 130.5」；接口失败显示「没建成：原因。没有执行任何写操作。」，已填内容保留。
- F5 → 主按钮「下一步：看一眼再确认」→ 确认卡逐行显示（与管理端同一 `CrewPreview` 组件，H3 每行都显示）→ 点「确认并办理」才调接口（H2）。同一事项重复提交会被拦下（服务端按 sourceKey 幂等，Rule 4）。结果分「已办成（带记录号，回读核实）/ 没办成 / 结果不明 / 原型演示，未执行」，不假装办成。
- F6 → 进屏默认是 72px 大麦克风「按住说话」（H1）；打字框在底部作为次要入口。原型不录音（语音识别是缺口）。
- F7 → 手机端加载只用文字「正在读取数据…」，不用骨架屏。

### 本原型的写入边界（实话）
- 仓管「核实原料库存」、质检员「质量异常」：确认后经 E 线协同任务接口真写 `test-f-20261112`，记「已交办」，不扣额度；任务完成、回读核实后才记「已办成」并扣 1 个额度（R29）。
- 「今天要办的」按快照日计（R28），快照日在页面上写明。
- 操作员「称重报工」：A 线第六批称重接口在飞，合并前只出预览，确认后记「原型演示，未执行」，不计额度。

### 375 宽下的尺寸核对（ai-chat-standard 手机规则）
按钮 ≥ 44px（主按钮 48px）、芯片 ≥ 40px、正文 16px、左右 16px、输入框 44px 圆角 8、一屏一个主按钮、不横向滚动。实际读数见 `impl-F.md`「审计退回」一节。真实 375 宽下只显示手机屏本身，没有外框和管理端抬头（F-7）。
