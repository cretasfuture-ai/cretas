## 第一组：智能体框架（与 F 交叉）

**G1 一级菜单要不要彻底换成「以事为中心」？**
- A（推荐）一级只留 今天 / 数字班组 / 待办 / 发现的问题，业务单据整体放进第二层「业务办理」（可展开），设置下沉。客户第一眼看到的是事和数字员工。
- B 保留现在的模块菜单，只在最上面加 今天 / 数字班组 / 待办 三项。改动小，但第一眼仍像 ERP。
- C 两套菜单可切换（智能体视图 / 传统视图），按账号记住。照顾老用户，维护两套。

**G2 「等我确认」放哪？**
- A（推荐）放在「待办」里做第一个页签，和审批、指派任务合成一个「要我动手」的入口；F 的收件箱页面不变，只是入口合并。
- B 「等我确认」单独一级菜单（F 的收件箱），「待办」只放审批和任务。数字员工更显眼，但人要看两处。**这是 F 线的现行做法**（F-crew-map 第 2 行：「数字员工的待确认事项单独进等我确认，不混进 OA 审批」）。
- 注：A 只合入口，不合列表；页签内仍是 F 的收件箱原样，所以 A、B 的区别只在侧栏是一个入口还是两个。

**G13 「发现的问题」（G）和「主动汇报」（F `/crew/reports`）是一页还是两页？**
- A（推荐）一页，Owner 是 F：一级菜单「发现的问题」直接打开 F 的主动汇报，F 把类型筛选扩到 G 列的 10 类（缺料、交付、出成、成本、质量偏离、临期、设备、排产、对账、数据缺口），规则提醒也作为「数字 X 发现」进来；G 的 `/g/issues` 骨架退成需求说明。人只看一处，问题都有「谁发现的」。
- B 两页：主动汇报只放数字员工推送的，「发现的问题」放规则预警和源头异常页的汇总。实现简单，但同一件事（如出成下降）可能两边都出现。
- C 不设「发现的问题」，各模块异常页保留在原菜单，主动汇报做总入口。
- **已裁定 R27**：合成一页（同 A）。按来源分类显示：数字员工汇报 / 规则预警 / 对账差异 / 数据缺口；汇报仍可转待办，关闭必须写结论。页面归属与实现批次随下一批主侧栏改组定（D 实现，F、G 配合）。

**G3 首页「今天」按什么切换？**
- A（推荐）按登录人岗位自动选一个视图，可切换到其他岗位（老板、厂长默认看全部）。
- B 只按登录人权限显示，不给切换。
- C 一页把所有岗位的事都列出来，用筛选收窄。

**G4 「AI 问答 / 数据分析」还单列吗？**
