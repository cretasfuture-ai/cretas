# 统一原型 · 页面规格模板（所有线共用，章节名和顺序不许改）

每个页面/功能一个小节，按下面 8 项写。写不出来的项写「未查明」并说明缺什么，不许编。

## 〈页面或功能名〉
所属线：A 生产链 / B 成本分析 / C 采购销售库存 / D 首页与分析
使用的角色：谁在什么场景下打开它

### 1 一句话目的
用户在这里要完成什么。写不成一句话，说明这个页面职责不清，要拆或并，并在第 4 项说明。

### 2 现状问题（带证据）
只写能指到证据的：入口重复、按钮用途不明、对象不清（这个按钮作用于整张列表、某一行还是某个共用配置）、信息堆叠、文字排版乱、多个 AI 入口。每条写：现象 / 证据（截图路径或文件:位置或页面操作步骤）/ 为什么是问题。

### 3 目标信息层级
按五区组织：导航与任务 → 当前对象 → 主操作与筛选 → 业务内容 → 详情与 AI。
写清首屏必须回答的 3 个问题，以及每个区域放什么、不放什么。长说明默认折叠，原因进问号提示。

### 4 按钮与入口清单
表格：按钮名（动词+对象，行内按钮两个字）/ 作用对象 / 点击结果 / 放在哪个区 / 处置（保留·改名·合并到X·删除）。重复入口必须合并并写理由。每页同类操作只能有一个入口。

### 5 AI 处理点
逐项写，没有就写「本页不需要 AI」并说明为什么：
- 触发位置与按钮文案（说清目的，例：「解读这条计划」「核对缺料」；不许只写「AI 分析」）
- 当前对象（AI 在回答哪一条记录/哪个筛选范围）
- 输入依据（用到哪些字段、哪些接口，缺什么就明说）
- 代码确定的部分：口径、计算、数量、取消单/零值/缺失的区分，一律由代码算并校验，不靠提示词
- 模型生成的部分：解释、归因线索、下一步核对方向、缺资料时找谁补
- 输出形态：结论 → 依据（可点击定位原单/节点）→ 建议动作 → 预览 → 确认执行 → 回读结果
- 三种状态分开显示：回答完成 / 草稿已保存 / 业务已完成
- 异常态：缺数据、无权限、依据过期、模型不可用时给什么、用户能做什么
- 模型路由：本地模型优先，不可用时规则分析仍能运行；界面不显示设备名和模型名
- ⛔ 不做什么：不改事实数字、不替用户执行未预览的写操作、不超出该账号本来就有的权限

### 6 不该用 AI 的地方
确定性规则、固定公式、筛选排序、状态流转，写明由什么代替。

### 7 验收用例
5–8 条能在真实浏览器里点通的操作，每条含「保存 → 刷新 → 回读」或「下钻 → 返回保持筛选」；含 1–2 条阴性对照（该被拦的真的被拦、缺数据真的显示缺）。

### 8 依赖与数据缺口
依赖哪些其他页面/接口；哪些数据现在没有（保持真实空态，不猜不补）。
