## 生产计划 · 列表
所属线：A 生产链
使用的角色：生产经理、计划员。每天开工前看今天要做什么、哪条计划卡住了；班中跟进执行状态。

### 1 一句话目的
筛出需要处理的计划，并对其中一条执行下一步（录入、小结、档案）。

### 2 现状问题（带证据）
1. 现象：建单方式下拉箭头放在"单据工具"右边，看上去像单据工具的下拉；点开后"描述建单""返工建单"同时出现在标题栏和下拉菜单里，同一功能有两个入口。证据：S5；页面 DOM 读取到 `选择建单方式 ⌄` 的 x=1371，在 `单据工具` x=1297 的右边。问题：作用对象读错，违反"同类操作只有一个入口"。
2. 现象：执行分析的问号（aria-label"执行分析说明"）紧挨"新建计划"，离"执行分析"较远。证据：同一次 DOM 读取，`?` x=1279，在新建计划 x=1123 与单据工具之间。问题：用户会以为问号说明的是新建计划。

5. 现象：单据工具菜单是"导入/导出、撤销审批、状态概览"。证据：S4。问题："撤销审批"和侧栏"报工撤回"页、行内"申请撤销小结"说的是同一类审批，用词有"撤销/撤回"两种。

### 3 目标信息层级
首屏要回答的三个问题：今天有哪些计划没完成？哪条卡住了，卡在什么地方（缺料、未领料、待小结）？我对这一条下一步点哪里？

- 导航与任务：侧栏"计划执行 › 生产计划"。工作区标签（味美/六膳门）显示在顶栏，不放在列表里。
- 当前对象：列表页不放"当前计划"选择器（已定）。标题写"生产计划 · 共 N 条"，工作区为六膳门时写"生产工单"。
- 主操作与筛选：右上只有一个主按钮"新建计划"（右侧带下拉：描述建单、返工建单），然后是"单据工具"，最后是"执行分析 ?"。三个控件分成三组，问号紧挨所属按钮。筛选行放：搜索、状态（默认"未完成"）、日期、重置；打印和显示列放在表格工具里。
- 业务内容：紧凑表格。首屏固定列：计划号、成品、计划量/单位、计划日期、状态、"下一步"（由代码按状态计算，例如"待领料""待录入""可小结"）、操作。"原料参考""批次日期""生产类型"放在显示列里，默认可以收起。
- 详情与 AI：点计划号打开右侧详情（不跳页）；"解读这条计划"在详情抽屉标题右侧，打开后是统一的悬浮窗。"执行分析"作用于当前筛选，结果也在同一个悬浮窗里，窗口标题写明对象（"当前筛选 · 23 条"或"计划 PLAN-…"）。
- 不放：工序画布、BOM、配方版本的平级入口；"工序图"小链接。

### 5 AI 处理点
- 触发位置与文案："分析当前筛选"（右上，带问号，说明"只看当前筛选结果，最多逐条解读 20 条"）。单条计划的解读写在"行内操作"一节，不在列表头重复。
- 当前对象：当前筛选条件（状态、日期、关键词）与命中的条数。悬浮窗标题显示筛选摘要。
- 输入依据：计划列表接口返回的字段（计划号、成品、计划量/单位、状态、计划日期、锁定工序/配方版本、实际数量）；领料单状态（`/production/material-flow` 的数据）。缺料事件数据在本会话为空，要明说"没有缺料事件记录"，不能写成"不缺料"。
- 代码确定的部分：按状态计数；计划量按单位分组合计（不同单位不相加）；超期判断（计划日期早于今天且未完成）；"下一步"枚举；取消单单独计数，不进入在制合计；缺失的实际数量显示"—"，并标注"未录入"。
- 模型生成的部分：哪些计划要先处理的排序理由；卡住的原因线索（例如"已领料但还没录入"）；下一步去哪个页面核对。
- 输出形态：结论（例如"3 条超期，其中 2 条已领料未录入"）→ 依据（列出计划号，点击定位到行）→ 建议动作（"去录入""去领料"）→ 不带写入操作。
- 三种状态：回答完成（悬浮窗标"已回答"）；本页不产生草稿；本页不产生业务完成态。
- 异常态：列表为空时不调用模型，直接显示"当前筛选无计划"；模型不可用时显示代码统计的结果，并说明"文字解读暂不可用"；依据过期（筛选改了）时显示"上次分析的是旧筛选"，并给"改用当前筛选"按钮。
- 模型路由：本地模型优先；不可用时只出规则统计。界面不显示设备名和模型名。
- ⛔ 不改任何数量；不批量改状态；不替用户点"更新到当前配方"。

### 6 不该用 AI 的地方
筛选、排序、分页、状态计数、超期判断、"下一步"列，全部由代码规则算。建单表单校验用原有表单规则。

### 7 验收用例
1. 在 spec 会话把状态筛选改为"全部"、输入关键词 → 点计划号打开详情 → 关闭 → 筛选、关键词、滚动位置都还在。
2. 点"新建计划"右侧 ⌄ → 下拉里只有描述建单、返工建单；标题栏里不再有这两个按钮。
3. 悬停或聚焦"分析当前筛选"旁的问号 → 说明写清对象是当前筛选；Esc 能关闭。
4. 点"分析当前筛选" → 悬浮窗标题显示筛选摘要和条数 → 改筛选 → 悬浮窗提示"旧筛选"，并出现"改用当前筛选"。
5. 测量行高：数据行 32–33px；操作列只看到"录入 小结 档案 更多"。
6. 阴性：筛选到 0 条 → 点"分析当前筛选" → 不发模型请求，直接显示空态。
7. 阴性：计划实际数量为空 → 汇总显示"未录入"，不显示 0。

### 8 依赖与数据缺口
依赖：计划列表接口、领料单接口、缺料事件接口、悬浮窗组件（`CretasUI` 与 Nuxt 悬浮窗）。缺口：六膳门工作区没有"计划"层，只有工单（来源 157 张），列表要按工作区切换对象名；spec-a 会话只有 1 条计划，覆盖不到分页和多状态的视觉验收，要用 test-iab-chain 或模拟数据会话。

## 生产计划 · 新建（新建计划 / 描述建单 / 返工建单）
所属线：A 生产链
使用的角色：计划员；返工建单由质量或生产经理在出现返工时发起。

### 1 一句话目的
用一种方式创建一条计划草稿，核对成品、数量、日期和要锁定的工序/配方版本后保存。

### 2 现状问题（带证据）
1. 现象：三种建单方式同时出现两组入口。证据：S5。问题：见列表第 1 条。
2. 现象：新建表单里是否显示"将锁定的工序/配方版本"本轮未打开核对（为了不误点保存）。证据：无。问题：未查明，要在实现前用 spec 会话打开表单确认。
3. 现象：生产批次页另有"描述建批"（S8），说法和"描述建单"相近但对象不同。问题：容易以为是同一个功能（见批次一节）。

### 3 目标信息层级
首屏三个问题：做什么产品、做多少（单位）？哪天做？会用哪个工序/配方版本？
- 当前对象：抽屉标题"新建计划"；返工建单时标题写"返工计划 · 来源批次 X"。
- 主操作：抽屉底部"保存计划"（主色）、"取消"。
- 业务内容：成品（SKU 搜索）→ 数量＋单位（只能选这个 SKU 允许的单位）→ 计划日期 → 版本区（只读，写"将锁定：工序 vN / 配方 vM（产品当前生效版本）"；产品还没有已发布版本时写"该产品还没有已发布的工序配置"，可以保存但会标"待配置"）。
- 详情与 AI：描述建单在抽屉顶部的输入框里，是独立任务，不和解读放在一起。

### 4 按钮与入口清单
| 按钮名 | 作用对象 | 点击结果 | 放在哪个区 | 处置 |
|---|---|---|---|---|
| 新建计划 | 新计划 | 空白表单 | 列表主操作 | 保留 |
| 描述建单 | 新计划草稿 | 用一句话生成表单草稿，进入同一个表单核对 | 新建下拉 | 保留，只留在下拉里 |
| 返工建单 | 新返工计划 | 选来源批次后预填 | 新建下拉 | 保留，只留在下拉里 |

| 取消 | 这张草稿 | 有未保存内容时先确认 | 抽屉底部 | 保留 |

### 5 AI 处理点
- 触发位置与文案："描述建单"（问号说明："把一句话整理成计划草稿，保存前要你核对"）。
- 当前对象：这一张新草稿。
- 输入依据：用户的描述文字；SKU 主数据（名称、编码、允许单位）；产品当前生效的工序/配方版本号。
- 代码确定的部分：SKU 匹配必须唯一，否则列出候选让人选；单位必须在 SKU 允许的单位里；数量必须是正数；日期必须能解析；版本号从接口读，不由模型填。
- 模型生成的部分：从描述里抽出成品、数量、日期的候选；有歧义时生成追问。
- 输出形态：草稿表单（字段旁标"来自描述"）→ 用户核对 → 保存 → 回读。
- 三种状态：草稿已生成（没有保存）；计划已保存（业务完成）；两种状态用不同标签。
- 异常态：SKU 没有唯一匹配时，字段留空并列出候选；模型不可用时提示"请手工填写"，表单照常能用。
- ⛔ 不自动保存；不选版本；不创建 SKU。

### 6 不该用 AI 的地方
表单校验、单位换算、版本锁定、返工来源批次的数量上限，都由代码处理。

### 7 验收用例
1. spec 会话：新建 → 选 SKU → 填数量 → 版本区显示将锁定的版本 → 保存 → 刷新 → 列表里有这条计划，详情里的版本和保存前一致。
2. 描述建单输入"明天做 120 公斤调味鸡腿" → 草稿字段标"来自描述" → 取消 → 列表没有新增记录。
3. 阴性：选一个没有已发布工序的 SKU → 版本区显示"还没有已发布的工序配置"，不会显示别的产品的版本。
4. 阴性：单位填一个 SKU 不允许的单位 → 被拦下，不能保存。
5. 返工建单：选来源批次 → 预填数量不超过可返工量 → 取消 → 来源批次没有变化。

### 8 依赖与数据缺口
依赖：SKU 接口、产品工序/配方当前版本接口、计划保存接口。缺口：本轮没打开新建表单，表单里现有字段和版本显示未查明；六膳门工作区是黑湖只读来源，不提供新建工单（保持只读，入口要隐藏，不能做成禁用的假按钮）。

## 生产计划 · 行内操作（录入 / 小结 / 档案 / 更多）
所属线：A 生产链
使用的角色：班组长、生产经理，对某一条计划做执行动作。

### 1 一句话目的
对这一条计划执行下一步：录入生产数据、核对结单、看档案，其他低频操作放在"更多"里。

### 2 现状问题（带证据）
1. 现象："更多"里有 9 项，没有分组，危险操作（停产、取消计划）和普通操作混在一起。证据：S2。问题：行内低频操作太多，高风险操作没有隔开。
2. 现象："更新到当前配方"会改变计划锁定的版本，却和"复制为新计划"排在同一层。证据：S2。问题：违反原则 6（已开工的计划不能被静默换版本），点之前必须看到差异预览。
3. 现象："工序配置"（更多里）、"工序图"（产品名旁，S3）、"预览工序路线"按钮（DOM aria-label）三个入口都指向工序。问题：重复，而且只有"工序配置"会带上来源计划（见联动一节）。
4. 现象：按钮完整的用途写在 aria-label 里（"继续逐道录入这条计划的生产数据""核对该计划的实际产出、耗用与结单条件""查看该计划的生产档案及核算明细"），界面上只显示两个字。证据：页面 DOM 读取。问题：这个做法已达标，保留。

### 3 目标信息层级
首屏三个问题（对这一行）：现在是什么状态？下一步点哪个？有没有危险操作？
- 行内直接显示 3 个按钮＋更多：录入、小结、档案、更多。按状态启用或禁用，原因写在悬停说明里（例如"未领料，暂不能录入"）。
- "更多"分三组，组间加分隔线：
  1. 查看与解读：解读、工序
  2. 编辑：改排产、复制、派工
  3. 状态变更（红字，点了要二次确认）：换版本、撤销小结、停产、取消
- 详情与 AI："解读"打开悬浮窗，窗口标题写"计划 PLAN-…"。

### 4 按钮与入口清单
| 按钮名 | 作用对象 | 点击结果 | 放在哪个区 | 处置 |
|---|---|---|---|---|
| 录入 | 本行计划 | 打开逐道工序录入（报工＋实耗） | 行内 | 保留 |
| 小结 | 本行计划 | 结单核对：实际产出、耗用、退料是否齐全 | 行内 | 保留 |
| 档案 | 本行计划 | 生产档案与核算明细（只读），里面有"成本依据"，跳到 B 线 | 行内 | 保留 |
| 解读 | 本行计划及其锁定版本 | 悬浮窗"解读这条计划" | 更多·第 1 组第 1 项 | 由"解读计划"改名，提到第一位 |
| 工序 | 本行计划锁定的版本（可切换到产品当前版本对照） | 进入工序画布，显示来源计划条 | 更多·第 1 组 | 由"工序配置"改名；合并"工序图"和"预览工序路线" |
| 改排产 | 本行计划 | 编辑日期、数量、车间 | 更多·第 2 组 | 由"编辑排产信息"改名 |
| 复制 | 本行计划 → 新草稿 | 打开预填的新建表单 | 更多·第 2 组 | 由"复制为新计划"改名 |
| 派工 | 本行计划各工序 | 分配工序操作员 | 更多·第 2 组 | 由"分配工序操作员"改名 |
| 换版本 | 本行计划的锁定版本 | 先显示新旧版本差异和受影响的领料单，确认后才保存 | 更多·第 3 组 | 由"更新到当前配方"改名；已报工的计划禁用，悬停说明原因 |
| 撤销小结 | 本行计划的小结 | 提交撤回申请，进入报工撤回审批 | 更多·第 3 组 | 由"申请撤销小结"改名；"撤销/撤回"统一为"撤回" |
| 停产 | 本行计划 | 二次确认后改状态 | 更多·第 3 组 | 保留 |
| 取消 | 本行计划 | 二次确认；已领料时提示先退料 | 更多·第 3 组 | 由"取消计划"改名 |

### 5 AI 处理点
- 触发位置与文案：更多 → "解读"，悬浮窗标题"解读这条计划"，旁边问号："只解读这一条计划和它锁定的版本；改备注要先预览、确认后才保存。"
- 当前对象：计划号＋锁定的工序 vN / 配方 vM。
- 输入依据：计划字段；锁定版本的 BOM 行；关联领料单（需求、已发、实耗、退回、单位、状态）；报工记录。用的是 `tools/ledger-facts.cjs` 生成的事实。
- 代码确定的部分：沿用 ledger-truth 的口径。0 和缺失分开；取消单不计待发；关单保留历史；已发、实耗、退回各取各的字段；不同单位分组；同基准用量核对（"用量核对：3 项一致"）；版本是否一致（领料单生成版本和计划当前版本比对）。
- 模型生成的部分：解释现在卡在哪里；只能从系统开放的 reviewCodes 里选核对项；建议下一步找谁（仓库、班组）。
- 输出形态：结论 → 依据（领料单号、报工号可点击定位）→ 建议 → 可选动作"改备注"→ 显示修改前后差异 → 确认保存 → 独立回读，显示保存回执。
- 三种状态：回答完成；备注草稿（只预览，未保存）；备注已保存（回执）。三种状态分开显示。
- 异常态：没有领料单时显示"尚无领料记录"，不推断耗用；依据过期（计划被别人改了）时标旧依据并给"重新解读"；没有权限改备注时隐藏改备注动作。
- ⛔ 不改数量和版本；不替用户点"换版本"或"撤销小结"；回答里不能把已发说成实耗。

### 6 不该用 AI 的地方
按钮按状态启用或禁用、换版本时的影响范围（哪些领料单受影响）、小结的结单条件，都由代码规则判断。

### 7 验收用例
1. test-iab-chain 会话：计划 C4066E2A → 更多 → 解读 → 依据里出现 MR-LOCAL-1793805380552（BOM v4）和 10kg / 18pcs / 250g 分组 → 点领料单号能定位 → 返回后列表筛选不变。
2. 解读 → 改备注 → 预览前后差异 → 取消 → 刷新 → 备注没有变（确认前没有写入）。
3. 在 spec 会话：改备注 → 确认 → 刷新 → 回执和计划备注一致。
4. 阴性：已报工的计划 → 更多 → "换版本"是禁用状态，悬停说明"已开工，不能换版本"。
5. 阴性：状态为取消的计划 → 录入、小结都是禁用状态。
6. 更多 → 工序 → 画布顶部显示"来源计划 PLAN-… · 锁定工序 vN / 配方 vM" → 返回计划 → 回到原来的筛选。

### 8 依赖与数据缺口
依赖：ledger-facts、计划解读接口、报工撤回接口、工序画布。缺口：录入、小结弹窗本轮没打开，内部字段未查明；六膳门工单的行内操作只有"查看"一类（来源只读），录入、小结、换版本都不适用，要隐藏。

## 领料（领料单 / 退料记录）
所属线：A 生产链
使用的角色：仓管员（备料、拣货、调拨、签收）、班组长（申请、退料）。

### 1 一句话目的
按计划生成领料单，跟踪从发料到签收、退料、关单，核对实际发出的物料。

### 2 现状问题（带证据）
1. 现象："领料工具"菜单里只有一项"退料记录"，页面顶部已经有"退料记录"页签。证据：S7。问题：同一入口出现两次，而且"工具"这个名字说明不了用途。
2. 现象：首屏状态列先是空的，过几秒才出现"已签收/已取消/已关单"，中间没有加载占位。证据：S6 与随后的截图（同一页面约 6 秒后）。问题：用户会以为这些单没有状态。
3. 现象：行内"更多"只有一项"关单"。证据：页面 DOM 读取，菜单项为 `["关单"]`。问题：只有一项就不该收进"更多"。
4. 现象：没有搜索框，只有状态筛选；状态筛选放在刷新按钮的左边。证据：页面文本"状态 刷新 生成领料 领料工具 ?"。问题：单据多了以后找不到某张单。
5. 现象：详情里的"实用"列在已签收、未报工时显示 0。证据：MR-LOCAL-1793805380552 详情文本"实用 0"。问题：分不清"已记录为 0"和"还没报工"（ledger-truth 把这种 0 定义为已记录的零值，但用户看不出来）。
6. 已达标：详情顶部写"生成依据：BOM v4 · 当前计划：BOM v4。本单明细与生成依据分别保留，实际耗用以领料记录为准。"

### 3 目标信息层级
首屏三个问题：哪些领料单在等我处理（待拣、在途、待签收）？哪张单和计划版本不一致？退料关单了没有？
- 当前对象：列表页没有单一对象；从计划跳过来时，顶部显示"来自计划 PLAN-…（只看这一条）"，带"看全部"按钮。
- 主操作与筛选：右上"生成领料"（主色，打开后第一步就是选计划）；筛选：搜索单号或计划号、状态、需料日期。
- 业务内容：页签"领料单 | 退料记录"。列：单号、状态、计划、生成版本（与当前版本不一致时标橙色"版本不同"）、物料行数、需料日期、申请人、操作。
- 详情与 AI：详情抽屉按物料行列出需求、已发、实耗、损耗、退回、单位；状态是"未报工"时，实耗显示"未报工"而不是 0。AI 入口是"核对这张领料单"（抽屉标题右侧）。

### 4 按钮与入口清单
| 按钮名 | 作用对象 | 点击结果 | 放在哪个区 | 处置 |
|---|---|---|---|---|
| 生成领料 | 选定的一条计划 | 按计划锁定的 BOM 算出需求，生成领料单草稿 → 核对 → 保存 | 右上主操作 | 保留；表单第一项必须是"计划"，不默认带上一次的计划 |
| 领料工具 | — | 只有"退料记录" | — | 删除（理由：和页签重复） |
| 刷新 | 列表 | 重新取数 | 筛选区右端 | 保留 |
| 搜索 | 列表 | 按单号、计划号过滤 | 筛选区 | 新增 |
| 详情 | 本行领料单 | 右侧抽屉 | 行内 | 保留 |
| 打印 | 本行领料单 | 打印 | 行内 | 保留 |
| 关单 | 本行领料单 | 确认退料后关单 | 行内（直接显示，不收进更多） | 改位置 |
| 拣货／调拨／签收／退料 | 本行领料单 | 原有流转动作 | 详情抽屉底部，按状态只显示当前一步 | 保留，本轮未逐个打开 |

### 5 AI 处理点
- 触发位置与文案：详情抽屉右上"核对这张领料单"，问号："只核对这张单：需求、已发、实耗、退回是否对得上；数字由系统算，解读只给核对方向。"
- 当前对象：领料单号＋生成版本。
- 输入依据：领料单物料行（需求、已发、实耗、损耗、退回、单位、状态）、计划锁定版本、调拨和签收批次。
- 代码确定的部分：完全沿用 ledger-facts 的规则（见 `docs/ledger-truth-delivery.md` 的口径表）；生成版本和当前版本是否一致；库存守恒（调出没签收时目标仓不增加）。
- 模型生成的部分：只能从系统开放的 reviewCodes 里选；解释为什么"已发≠实耗"、应该去报工还是退料。
- 输出形态：结论 → 依据（物料行、批次号可点击）→ 建议去哪一步 → 本页没有 AI 写入动作。
- 三种状态：本页只有"回答完成"。
- 异常态：单位缺失时这一行标"单位未填，不能合计"；模型不可用时只显示代码核对表。
- ⛔ 不改数量；不替用户签收、关单；不推算实耗。

### 6 不该用 AI 的地方
需求量计算（BOM × 投入量）、拣货联动（原料改 8kg 时辅料自动变为 200g）、单位别名（件/pcs）、状态流转、库存扣减，都是代码规则。

### 7 验收用例
1. test-iab-chain：领料 → 详情 MR-LOCAL-1793805380552 → 实耗列显示"未报工"（或带明确的标记）而不是没有说明的 0 → 关闭 → 列表筛选不变。
2. 从计划行跳到领料 → 顶部显示"只看这一条计划"→ 点"看全部"→ 显示全部 3 张单。
3. spec 会话：生成领料 → 选计划 → 需求按锁定 BOM 算出 → 取消 → 列表没有新增。
4. 阴性：取消单 MR-…（已取消）→ 详情里没有"待发"，也没有任何发料动作。
5. 阴性：首屏加载中，状态列显示加载占位，不显示空白。
6. 退料记录页签 → 刷新 → 页签仍是"退料记录"。

### 8 依赖与数据缺口
依赖：领料、调拨、签收接口；ledger-facts；仓库批次。缺口：六膳门工作区"领料"是"可查看"，黑湖快照里的实际领退料单（例如 OUT202610240004）只能读不能写，要按只读列表展示；黑湖物料还没有到工序的分摊依据（融合方案第四节），领料只能对到工单，不能对到工序。

## 生产批次
所属线：A 生产链
使用的角色：班组长、质量。按批次查实际产量、耗用和追溯。

### 1 一句话目的
查一个已开工的实际批次产了多少、用了什么、能追溯到哪里。

### 2 现状问题（带证据）
1. 现象：页面顶部有一大段说明条，直接写英文状态码"IN_PROGRESS / COMPLETED""PENDING / 待开工状态"，没有折叠。证据：S8；页面文本"这里是「生产批次」管理 — 已开工的实际「批次」（IN_PROGRESS / COMPLETED…）"。问题：长说明占首屏，而且出现原始状态码。
2. 现象：主操作是"创建批次"，下拉里有"描述建批"。证据：S8。问题：和计划的"录入"（逐道录入会产生批次）是否重复，未查明；"描述建批"和"描述建单"名字相近，容易混。
3. 现象：test-iab-chain 会话里计划 C4066E2A 已经领料、签收，但批次列表是 0 条。证据：页面文本"共 0 条记录"。问题：计划和批次之间没有可见的关联，用户不知道批次去哪了。
4. 现象：说明条里的"生产管理 → 生产计划"是个链接，又是一个跳转入口。问题：轻微；改成问号说明里的一句话。

### 3 目标信息层级
首屏三个问题：今天有哪些批次在做？哪个批次产量或耗用异常？这个批次属于哪条计划、用的哪个版本？
- 当前对象：列表；从计划跳过来时，顶部条写"计划 PLAN-… 的批次"。
- 主操作：右上"创建批次"只在"有计划但走手工批次"的场景保留（见第 8 项待裁定）；说明收到问号里。
- 业务内容：列：批次号、计划号（可点）、产品、计划量、实际量（未录入显示"—"）、来源工序、版本、状态（中文）、负责人。
- 详情与 AI：详情抽屉有页签：报工流水、实耗、追溯。AI 入口"解读这个批次"。

### 4 按钮与入口清单
| 按钮名 | 作用对象 | 点击结果 | 放在哪个区 | 处置 |
|---|---|---|---|---|
| 创建批次 | 新批次 | 表单 | 右上 | 保留，待裁定是否并入计划"录入" |
| 描述建批 | 新批次草稿 | 一句话生成草稿 | 创建批次下拉 | 保留；问号说明它和"描述建单"的区别 |
| 说明条 | — | — | — | 删除，内容放进标题旁的问号 |
| 搜索／状态／重置 | 列表 | 过滤 | 筛选区 | 保留 |
| 计划号（列内链接） | 关联计划 | 打开计划详情抽屉 | 行内 | 新增 |
| 详情 | 本行批次 | 抽屉 | 行内 | 保留 |
| 撤回 | 本行批次的报工 | 发起整单撤回申请 | 详情抽屉 | 保留（入口统一到这里和计划"撤销小结"） |

### 5 AI 处理点
- 触发位置与文案：批次详情右上"解读这个批次"。
- 当前对象：批次号。
- 输入依据：批次字段、报工流水、实耗、计划锁定版本的标准用量。
- 代码确定的部分：达成率 = 实际 ÷ 计划（计划为 0 或缺失时不算）；实耗和标准用量同基准对比；单位分组。
- 模型生成的部分：偏差原因的线索，以及要核对哪道工序的报工。
- 输出形态：结论 → 依据（报工号可点击）→ 建议。
- 三种状态：只有"回答完成"。
- 异常态：没有报工时直接说"该批次尚无报工"，不调用模型。
- ⛔ 不改报工；不发起撤回。

### 6 不该用 AI 的地方
状态显示（中文映射）、达成率、追溯链拼接。

### 7 验收用例
1. 计划详情 → 点"批次" → 跳到批次列表，顶部条显示该计划 → 返回 → 计划列表筛选还在。
2. 批次列表首屏没有长说明条；问号悬停能看到"批次与计划的区别"。
3. 状态列全是中文，没有 IN_PROGRESS 这类原文。
4. 阴性：没有报工的批次 → "解读这个批次"直接显示"尚无报工"。
5. 阴性：计划量为 0 的批次 → 达成率显示"—"，不显示 0% 或无穷大。

### 8 依赖与数据缺口
依赖：批次接口、报工流水接口。缺口：味美的计划"录入"和批次是什么关系未查明（test-iab-chain 中有领料但批次为 0）；六膳门没有"批次"对象，只有工单、任务、报工，批次页在六膳门工作区应显示"该工作区没有批次对象，请看工单任务"，而不是空表。

## 报工撤回审批
所属线：A 生产链
使用的角色：生产经理（审批人）、班组长（申请人，看进度）。

### 1 一句话目的
审核一份报工撤回申请：撤回什么范围、会回退哪些流水，然后批准或驳回。

### 2 现状问题（带证据）

### 5 AI 处理点

- 导航与任务：侧栏"工序与标准 › 工序配置"。从侧栏进来时不带计划上下文，先选产品。
- 当前对象（一行，不重叠）：产品名 · 版本标签（只能是三种之一："草稿 · 基于 vN""已生效 vN""锁定版本 vN · 来源 计划/工单 X"）· 来源（味美本地 / 黑湖快照修订号）。从计划进来时，这一行左边有"← 返回计划 PLAN-…"，右边是"切换到产品当前版本对照"。
- 主操作（右上）：编辑态是"保存草稿"（主色）和"发布"；只读态（锁定版本、黑湖来源）是"建立本地草稿"（六膳门）或者什么都没有。版本、导出、配方版本侧栏、生成工序都收进"工具与版本"。
- 业务内容：左边是可收起的工艺目录树（两个工作区都有）：工序列表、标准投入、待指定用料（计数）、执行异常（计数）；中间是画布；画布内的节点有投入口、产出口、单位关系，辅料、包材默认折叠成"辅料 · 1 种"摘要。
- 详情与 AI：选中节点后右侧打开节点详情（配置态：投入、产出、用料（BOM 行）、报工规则；执行态：报工、实际领退料、成本依据）；"解读这个配置"悬浮窗，选中节点时自动带上节点。
- 不放：产出研判的三句话（只保留一句，由代码判断）；重复的"生产计划/配方版本"浮条。

### 5 AI 处理点
- 触发位置与文案："解读这个配置"（问号："解释当前版本的工序、用料和发布检查；选中节点时只看这个节点。生成新草稿请用'生成工序草稿'。"）。
- 当前对象：产品＋版本标签（草稿 / 生效 vN / 锁定 vN）＋可选的选中节点。
- 输入依据：工艺定义（节点、边、端口、单位关系）、BOM 行、发布校验结果（连通性、循环、单位、物料身份）；六膳门还要加来源快照修订号、未绑定 BOM 行、任务映射分类（342/91/27）。
- 代码确定的部分：发布校验（未连通、循环、单位缺失、物料重复）；待指定用料的条数；当前路线对得上的任务数；草稿和生效版本的差异；历史版本有没有确认。
- 模型生成的部分：用业务语言解释校验结果；建议先补哪一项；需要谁提供资料（工艺员、黑湖管理员）。
- 输出形态：结论（例如"60 条标准用料没有指定投料工序"）→ 依据（点一下在目录树和画布里定位）→ 建议 → 可选动作"把这行用料挂到工序 X"→ 预览草稿差异 → 确认保存草稿 → 回读。
- 三种状态：回答完成；草稿已保存（还没发布）；已发布（业务生效）。三种状态分开显示。
- 异常态：历史版本未确认时，解读只能说"当前参考"，不能说成历史事实；没有生成权限时隐藏"生成工序草稿"；模型不可用时只显示代码校验清单。
- ⛔ 不自动发布；不改黑湖来源；不把执行事实写回定义；不猜拓扑。

### 6 不该用 AI 的地方
发布校验、自动布局、单位换算、版本差异、受影响计划的清单、目录树计数。

### 7 验收用例
1. 侧栏进入"工序与标准" → URL 里没有 chainPlanId，当前对象行提示"请选择产品"。
2. 计划行"更多 → 工序" → 当前对象行显示"锁定版本 v3 · 来源计划 PLAN-…" → "返回计划" → 列表筛选不变。
3. spec 会话：拖动节点 → 保存草稿 → 刷新 → 位置恢复，版本标签是"草稿 · 基于 v3"。
4. 阴性：删掉一条连线 → 发布 → 被拦下，提示未连通的节点。
5. 发布影响预览：已报工的计划在"不更新"一栏。
6. 六膳门：工单 S20260005-001-001 → 顶部写"历史工艺版本未确认" → 节点"出料"产出写"未取得历史工艺版本"。
7. 选中节点 → "解读这个配置"悬浮窗标题带节点名 → 取消选中 → 标题回到整个配置。
8. 页面上只能找到一个"配方版本"入口、一个"返回计划"入口。

### 8 依赖与数据缺口
依赖：味美工艺定义和 BOM 接口；六膳门 local-workflows（`private/local-workflows.json`）和黑湖快照；发布校验。缺口：黑湖 157 张工单都没有锁定的历史工艺版本；60 行 BOM 没有投料工序；3 行 BOM 的产品没有返回路线；91 个任务所属产品当前没有路线；27 个任务的工序不在当前路线里。这些都按真实空态显示，不补。

## BOM（用料明细、版本、配方、出成标准）
所属线：A 生产链（成本依据交给 B 线）
使用的角色：工艺员维护标准用量；计划员核对计划用的是哪版配方；质量维护出成标准。

### 1 一句话目的
在工序配置里核对、维护每个节点的标准用料（原料、辅料、包材）、配方版本和出成标准。

### 2 现状问题（带证据）
1. 现象：配方侧栏状态显示原始英文"v1 · ARCHIVED … v4 · ACTIVE · 计划绑定"。证据：配方版本侧栏文本。问题：原始枚举。
2. 现象：原料标准数量显示"111.111111 kg"。证据：同一侧栏文本"本机练习 · 鸡腿原料 111.111111 kg"（由产出基数 100kg、得率 90% 反推）。问题：精度没有约定，看起来像算错了。
3. 现象：侧栏顶部有"创建 BOM 草稿"，画布有"保存当前配置"。证据：侧栏文本、S9。问题：BOM 草稿和画布草稿是不是同一份，界面上没有说明（融合方案要求"树、画布、用料清单读同一个定义"）。
4. 现象：六膳门侧栏单独有一个"BOM 用料依据"菜单（已接入）。证据：六膳门侧栏文本"BOM 用料依据 | 已接入"。问题：违反原则 3（BOM 是节点的用料明细，不应有平级入口）。
5. 现象："标准出成率"页（`/production/yield-standard`）在本次观察时一直停在"正在加载应用…"，超过 28 秒。证据：三次读取页面文本都是"白垩纪 AI Agent 正在加载应用…"，标签标题已变成"标准出成率"。问题：页面打不开（可能和融合代理同时改代码有关，要复查）；工序库里还有一列"标准出成率 未配置"，同一个数据两处显示。
6. 已达标：侧栏写"标准配方与计划绑定版本同时核对，已开工计划保留其版本"；原料、工序辅料、包材分成三组；辅料单位写"g / kg"。

### 3 目标信息层级
首屏三个问题：这个产品（或节点）标准上要投什么、投多少、按什么基数？现在看的是哪个版本，和计划锁定的一样吗？出成标准是多少，谁维护？
- 入口：只能从画布进入。①选中节点 → 右侧详情"用料"页签（这个节点的 BOM 行）；②工具与版本 → "用料明细"侧栏（整个产品，按节点分组，最后一组是"待指定工序"）。
- 当前对象：产品 · 版本（中文："生效中 / 已归档 / 草稿"）· 是否是计划锁定的版本。
- 业务内容：每行写物料、类别（原料/辅料/包材，来源没有分类时写"未分类"）、标准数量（按单位规定精度，最多 3 位小数，鼠标悬停看完整值）、单位/基数、损耗、绑定工序、来源行 ID（六膳门）。
- 出成标准：放在"工序与标准 › 出成标准"页签，每行写工序、标准出成率、维护人、生效时间，旁边单独写"实测参考"（只读，从报工算）；工序库的"标准出成率"列改成从这里读，只读显示。
- 详情与 AI：在画布上用"解读这个配置"即可，BOM 侧栏不再单独放 AI 入口。

### 4 按钮与入口清单
| 按钮名 | 作用对象 | 点击结果 | 放在哪个区 | 处置 |
|---|---|---|---|---|
| 用料明细 | 当前产品当前版本 | 侧栏 | 画布·工具与版本 | 由"配方版本"改名（版本切换在侧栏里） |
| 版本切换（侧栏内） | 产品的 BOM 版本 | 只读查看历史版本 | 侧栏顶部 | 保留，状态改中文 |

### 5 AI 处理点
本页（侧栏）不单独放 AI，统一用画布的"解读这个配置"，选中节点时带上节点的 BOM 行。理由：同一页只放一个 AI 入口（原则 4）。代码负责：同基准用量核对、单位、精度、"待指定工序"计数；模型只解释。

### 6 不该用 AI 的地方
标准数量换算（产出基数、得率）、包材"每单位成品"的折算、单位映射、出成率的计算。黑湖 unitQty / parentBaseQty 不能直接当成 g/kg，必须由人确认单位映射，AI 不能猜。

### 7 验收用例
1. 选中工序节点 → 详情"用料"页签显示这个节点的辅料（25 g/kg）→ 工具与版本 → 用料明细 → 同一行，同一个值。
2. 侧栏版本状态全是中文；鸡腿原料显示"111.111 kg"，悬停看到完整值。
3. spec 会话：节点里改辅料用量 → 保存草稿 → 刷新 → 用料明细侧栏显示新值，版本标签是"草稿"，计划锁定的版本没有变。
4. 六膳门：旧路由"BOM 用料依据" → 跳到用料明细 → "待指定工序"一组 60 行，"缺少产品路线"3 行。
5. 阴性：出成标准改值 → 没确认就关闭 → 刷新 → 值没变。
6. 阴性：计划锁定 v4，产品当前是 v5 → 计划里的"工序"入口默认显示 v4，并提示"产品当前已是 v5"。

### 8 依赖与数据缺口
依赖：BOM 接口、出成标准接口、工艺定义。缺口：标准出成率页本轮没加载出来，现有字段未查明；黑湖 BOM 的单位和分类没有确认映射；"实测出成率"要从报工算，六膳门可以算到工单级，工序级要看任务和报工的投入产出字段，未查明。

## 计划 → 画布 → BOM 联动
所属线：A 生产链
使用的角色：计划员和工艺员在"计划用的是哪个版本"这个问题上协作。

### 1 一句话目的
从一条计划进入它锁定的工艺版本核对，必要时把它换到产品当前版本（先预览影响），并能原路返回。

### 2 现状问题（带证据）
1. 现象：从计划到工序有三个入口（工序图、预览工序路线、更多 → 工序配置），只有最后一个带来源计划。证据：S2、S3、DOM aria-label。问题：重复入口，而且对象不一致。
2. 现象：联动参数（chainPlanId 等）会残留，从侧栏再进工序页时还在。证据：画布一节第 1 条。问题：计划上下文串到无关的会话里。
3. 现象：画布打开的是"产品共用配置"，来源条写"锁定工序 v3 / 配方 v4"，但画布里编辑的是当前生效版本（"已启用 v3"）。证据：S9。问题：v3 = v3 只是碰巧一样；如果不一样，用户在锁定版本的语境里编辑的其实是当前版本，原则 6 有风险。
4. 现象：看板说这条计划"免工序"（生产总览一节第 1 条），画布说锁定工序 v3。问题：计划和工序的绑定关系有两种说法。
5. 已达标：发布后，未报工的计划跟着更新；旧领料单保留 BOM v2（in-app-chain 验收）；领料详情同时写生成版本和当前计划版本。

### 3 目标信息层级
首屏（进入画布时）三个问题：这是哪条计划锁定的哪个版本？产品当前版本是不是比它新？我在只读查看还是在编辑草稿？
- 规则：
  1. 从计划进入 → 默认只读打开"锁定版本 vN"。当前对象行写"来源计划 X · 锁定 vN · 只读"。
  2. 当前版本比锁定版本新时，显示"产品当前为 vM · 对照差异"。
  3. 要编辑，必须点"编辑产品草稿"，当前对象行会变成"产品草稿 · 基于 vM · 不影响计划 X，除非发布并更新它"。
  4. 发布时的影响预览列出：会跟着更新的未报工计划、不变的已报工计划、受影响的领料单（旧单保留原版本）。
  5. 计划行的"换版本"是唯一能改计划绑定的入口，点之前必须看到差异预览。
  6. 返回时回到计划列表原来的筛选；联动参数只在这次跳转里有效，不保存到会话。

### 4 按钮与入口清单
| 按钮名 | 作用对象 | 点击结果 | 放在哪个区 | 处置 |
|---|---|---|---|---|
| 计划行·工序 | 计划锁定的版本 | 只读画布 | 计划行更多 | 保留（唯一入口） |
| 对照差异 | 锁定 vN 和当前 vM | 显示差异 | 画布当前对象行 | 新增 |
| 编辑产品草稿 | 产品 | 切换到编辑态 | 画布右上（只读态） | 新增 |
| 换版本 | 计划绑定 | 差异预览 → 确认 → 回读 | 计划行更多·第 3 组 | 由"更新到当前配方"改名 |
| 返回计划 | 来源计划 | 返回列表 | 当前对象行左侧 | 保留（唯一） |
| 工序图／预览工序路线 | — | — | — | 删除 |

### 5 AI 处理点
- 触发位置与文案：画布"解读这个配置"；当前对象是锁定版本时，回答开头写"你在看计划 X 锁定的 vN"。
- 代码确定的部分：版本差异、受影响计划和领料单的清单、已报工与否。
- 模型生成的部分：用业务语言解释换版本的影响和要核对的地方。
- 其他各项同"工序画布"一节。
- ⛔ 不替用户换版本或发布。

### 6 不该用 AI 的地方
版本绑定、差异计算、受影响范围。

### 7 验收用例
1. 计划 C4066E2A → 工序 → 只读"锁定 v3" → 返回 → 筛选不变 → 侧栏进工序 → 没有计划上下文。
2. spec 会话：编辑产品草稿 → 发布 v4 → 影响预览列出未报工计划 → 确认 → 刷新 → 已报工计划仍是 v3。
3. 计划行"换版本"→ 差异预览 → 取消 → 刷新 → 绑定没有变。
4. 阴性：已报工计划 → 换版本是禁用状态。
5. 领料单详情：生成版本和当前版本不一致时标"版本不同"。

### 8 依赖与数据缺口
依赖：计划锁定版本字段、工艺历史版本只读接口（未查明能不能按版本号读到历史画布）。缺口："只读打开锁定版本"需要能读历史版本的定义，现在的画布似乎只打开当前生效版本（"已启用 v3"），能不能读历史版本未查明。

## 六膳门工单执行（生产报工 / 工序任务）放进同一动线
所属线：A 生产链
使用的角色：六膳门生产经理核对黑湖里一张工单做到哪了、报了什么、用了什么料；成本核对人员从这里下钻。

### 1 一句话目的
在同一个"计划执行"入口里，按工单看它的工序任务、逐笔报工、实际领退料和成本依据，全部只读、可追溯到黑湖原记录。

### 2 现状问题（带证据）
1. 现象：六膳门路由 `/production/plans`（菜单"生产计划"）显示的标题是"产品"，内容是"产品 217 / 工单 157 / 报工 428 / 工序 29 / BOM 条目 83"五个资源页签，并且同样的资源区在 `/processes` 页面画布下方又出现一次。证据：两个页面的文本都有"产品 217 工单 157 报工 428 工序 29 BOM条目 83"。问题：页面按外部资源表组织，不是按任务；同一个资源区重复出现，信息堆叠。
2. 现象：工单用一个原生下拉框选择，里面有 157 项。证据：DOM `select.options.length = 157`；S10 右上的选择框。问题：数量一多就没法查找。
3. 现象：六膳门侧栏还是原来的 12 个生产菜单平铺（生产计划、缺料异常、生产进度大屏、生产批次、标准出成率、生产看板、报工审批、领料、SKU 管理、工序、生产分析、BOM 用料依据），每项标"已接入／可查看／待整理"。证据：侧栏文本。问题：和味美的"计划执行 / 生产总览 / 工序与标准 / 生产分析"四组结构不一致，融合时要对齐。
4. 现象：工单执行视图右侧有"报工 | 用料 | 成本"三个页签，"成本"和 B 线的成本分析可能重复。证据：S10、按钮清单"成本依据 报工 用料 成本"。问题：见文末冲突表。
5. 已达标：顶部写"历史工艺版本未确认 · 当前参考：通用工艺路线 · 2 个任务 · 2 条报工"；报工表注明"逐笔报工，不叠加工单良品"；节点"出料"写"已记录执行任务 316530530 · 已报良品 1,010.34 · 人工 0"。

### 3 目标信息层级
首屏三个问题：这张工单做到哪道工序、报了多少良品？用了哪些料（实际领退），和标准差多少？哪些地方是"未确认"的（历史版本、未映射的任务）？
- 导航与任务：侧栏"计划执行 › 生产工单"（六膳门工作区时，"生产计划"显示成"生产工单"）。
- 列表：紧凑表格，列：工单号、产品、良品（单位）、任务数、报工数、映射状态（"当前路线可对应 / 产品无路线 / 当前路线不含此工序"）、来源修订号；可以搜索、按状态筛选。替代 157 项下拉框。
- 当前对象（进入一张工单）：工单号 · 产品 · "历史工艺版本未确认"标签 · 来源快照。
- 业务内容：左边目录树（已记录工序、标准投入、待核用料）；中间是执行画布（按任务聚合，不画报工卡片）；右边节点详情"报工 | 用料 | 成本依据"。
- 详情与 AI："解读这张工单"（唯一入口）。
- 动线：产品 → 工单列表 → 工单执行画布 → 节点 → 逐笔报工 → 实际材料单 OUT… → "成本依据"（只显示这张工单的直接材料和人工；"去成本分析"跳到 B 线，带工单号）→ 返回工单列表时筛选保留。

### 5 AI 处理点
- 触发位置与文案："解读这张工单"（问号："只看这张工单的任务、报工、实际领退料；历史工艺版本未确认时，标准对照只算参考。"）。
- 当前对象：工单号＋来源快照修订号。
- 输入依据：工单、任务、报工（ID、审批状态、数量、单位、时间）、实际材料单、工资；当前路线和 BOM（标"当前参考"）。
- 代码确定的部分：良品只取工单级，不累加任务报工；0 工时、0 人工照实显示为"已记录 0"；任务映射分类；单位分组；直接成本只含已记录的材料和人工，币种待确认时标出；材料不平均分摊到工序。
- 模型生成的部分：解释差异的线索；指出"当前参考 ≠ 历史版本"；建议向谁补资料（黑湖管理员、车间）。
- 输出形态：结论 → 依据（报工 ID、材料单号可点击）→ 建议 → 可选动作"保存核对说明"（本地，预览后确认）→ 回读。
- 三种状态：回答完成；核对说明已保存；本页没有业务完成态（来源只读）。
- 异常态：来源快照比答案新时标"依据已过期，可重新解读"；工单没有任务时显示"来源未返回任务"。
- ⛔ 不回写黑湖；不补工资；不按当前路线伪造历史版本；不把任务良品加到工单良品上。

### 6 不该用 AI 的地方
任务映射分类、报工聚合、成本计算、单位分组、快照比对。

### 7 验收用例
1. 六膳门：计划执行 → 生产工单 → 搜索"S20260005" → 打开 → 节点"出料" → 报工 192013431 → 详情 → 返回 → 列表搜索词还在。
2. 同一张工单 → 用料 → OUT202610240004 → 成本依据显示良品 1157 KG、币种"待确认" → "去成本分析"→ B 线页面带上了这张工单 → 返回。
3. 映射状态筛选"产品无路线" → 显示 91 个任务所属的工单（按工单计数），不隐藏。
4. 阴性：任何工单页面上都没有"保存到黑湖"或审批按钮。
5. 阴性："出料"任务的人工显示"已记录 0"，不显示"缺失"，也不显示估算的工资。
6. 解读工单 → 保存核对说明 → 刷新 → 说明还在，来源记录的哈希没变。

### 8 依赖与数据缺口
依赖：六膳门黑湖快照（217/157/460/428/83）、本地工作流文件、成本下钻（B 线）。缺口：157 张工单都没有历史工艺版本；黑湖没有"计划"层，也没有"批次"对象；币种待确认；物料到工序没有分摊依据；"计划日期、负责人"这类字段在快照里有没有，未查明。

### 最需要 Steve 裁定的事
1. 版本号要不要统一成一个"生产版本"：现在用户同时看到"工序 v3 / 配方 v4"两套号（加上英文 ARCHIVED、ACTIVE）；六膳门融合方案建议对外只叫"生产版本"，内部保留工艺修订和 BOM 投影。这会影响计划锁定字段、领料单的"生成版本"和 B 线的成本依据。
