## 2 逐条

### 1. 订单履约齐套视图 · A 算，C 显示 · 高
- **黑湖怎么做**：「销售管理 → 履约助手」把每条销售明细按 BOM 逐层展开（层级编号 1、1.1…），每层给出需求数量、单位用量、计划缺料状态/数、库存缺料状态/数、已下达、已收货、已生产、已领料、库存齐套数、净需求数、齐套状态、已分配库存、可用库存；行内按制造模式给「安排生产」（自制）或「安排采购」（外购），还有「转采购需求」。证据：`P/BL-02-03.html`，列见 catalog `BL-02-03`；口径弹窗见 `P/D-PASSIVE-BL-02-03-calculation-netdemand.html`（「净需求数 = 父项计划缺料数 * 当前层级的单位用量；无父项产品，净需求数=需求数量」）、`…-planshortage.html`（「计划缺料数 = 需求数量 - 已下达数」）、`…-kitshortage.html`、`…-availableinventory.html`（「可用库存 = 库存数量 - 已分配库存」）。
- **我们现状**：缺料列表只在 A「生产分析」（D5），按缺料事件列出；销售订单（C7）只有订单级状态，没有「这张单的料齐不齐、卡在自制还是外购」。规格里检索不到「齐套」。
- **为什么值得借鉴**：跟单接到催货时，第一个问题是「能不能按期交、差什么」。按订单逐层看齐套，把销售、生产、采购三方的信息放进一张表，不用分头去问。行内按制造模式只给一个下一步，用户不用自己判断该找生产还是找采购。
- **不该照搬**：①按 D5 裁定，计算与列表留在 A，C 的订单详情只显示「齐套状态」标签和缺几项，跳到 A；②黑湖一行 40 多列，我们默认只给 8 列左右（产品、层级、需求、可用、缺料、齐套状态、下一步、来源），其余收进详情；③黑湖的缺料数允许手工改，而且「仅点击齐套计算时更新」，我们由代码实时算、不许手改（见第 3 节第 2 条）；④食品是配方加出成率，不是装配件，净需求要用出成率折算（A 维护出成标准，D3），不能照搬按单位用量直乘。

### 2. 补货建议公式 · C · 高
- **黑湖怎么做**：「采购管理 → 智能补货」逐物料列出最小、最大、安全库存，库存数量，采购在途量，在制数量，销售待发量，未清需求数，待领料数量，再算出建议补货量；「计算公式配置」弹窗写明补货依据（最小、安全或最大库存三选一）、加项（采购在途、在制）、减项（销售待发、待领料、未清需求），行内给「安排采购 / 安排生产」。证据：`P/BL-03-07.html`，公式弹窗 `P/D-PASSIVE-BL-03-07-formula.html`，列见 catalog `BL-03-07`。
- **我们现状**：C4「采购建议」实际只是一张带预算上限的建单表单，不算建议量（C-supply.md 第 4 节）；物料资料没有安全库存、最小库存、最大库存字段（规格未见）；请购审批（C2）会对照库存和在途，但只做单张核对。
- **为什么值得借鉴**：采购员要的是「哪些料该补、补多少」的清单，现在只能在库存查询和采购订单之间来回比对。把在途、在制、待发、待领逐项列开再给结果，建议数量有依据可查，不是黑箱。
- **不该照搬**：①公式由代码固定，界面只读展示，不开放用户改加减项（第 3 节第 2 条）；②食品原料有保质期，「补到最大库存」可能导致过期，建议只按安全库存补，并显示「到期前用不完」提示（依赖库龄，见第 8 条）；③任何一项缺数据（如味美没有在制数）就显示「未返回」，不按 0 参与计算（沿用 C 0.1 规则）；④C4 现有的预算受控表单保留，补货清单作为它的上游入口：选中几行后「生成采购草稿」，走 C4 预览。

### 3. 派生数量旁的只读「口径」弹层 · D 组件，A/B/C 使用 · 高
- **黑湖怎么做**：履约助手、采购需求、智能补货的工具栏都有「计算配置 / 计算公式」，弹窗统一写成「加项 (+)：… 减项 (-)：… ＝ 一行公式」，还附更新时机说明。证据：第 1、2 条的弹窗页，以及 `P/D-PASSIVE-BL-03-01-calculation-planshortage.html`。
- **我们现状**：D 规格的 P3 规定「代码定口径」，B 也写了「读数口径固定文案」（B-cost-analysis.md 0.2），但界面上没有一个统一的「这个数怎么算的」入口，各页靠问号说明，写法不一致。
- **为什么值得借鉴**：同一个「可用」「缺料」，各页口径不同正是用户最常问的问题。数字旁放一个统一格式的口径弹层，用户能自己核对；它和 AI 悬浮窗分工明确：口径弹层说公式，悬浮窗做解读。
- **不该照搬**：只读，不提供「确定」修改；公式文案和计算代码同源（同一份定义生成），防止两边对不上；不做成黑湖那种设置弹窗的样式，用组件库已有的 Popover，内容用「加项 / 减项 / 结果 / 数据时点」四行。

### 4. 销售明细分段进度 · C（补 N2）· 高
- **黑湖怎么做**：销售明细列表开头紧跟五个进度列：下达进度(%)、外购进度(%)、自制进度(%)、成品进度(%)、发货进度(%)，另有「进度详情配置」。证据：catalog `BL-02-02`，`P/BL-02-02.html`，`P/D-PASSIVE-BL-02-02-progressconfig.html`。
- **我们现状**：N2 把订单状态压成未完成 / 进行中 / 已完成三态，但「进行中」是一个大桶；订单详情里看不出卡在哪一段。
- **为什么值得借鉴**：三态解决了状态太多的问题，但「进行中」的订单才最需要跟进。分段进度直接回答「卡在生产还是卡在发货」，和三态正好互补：列表用三态，悬停或详情里看分段。
- **不该照搬**：①不做五列百分比，改成一条分段进度条（下达 → 生产/外购 → 入库 → 发货），悬停显示每段数量和单位；②味美没有外购和自制的区分时，这一段直接不显示，不显示 0%；③没有数据就显示「未返回」，不显示 0%（黑湖原型里未开始的行显示「- / - / - / 0% / 0%」，混用两种空值）。

### 5. 工单「工单进度」与「时间进度」并排，加工期状态 · A · 高
- **黑湖怎么做**：工单列表同时有工单进度(%)、时间进度(%)、工序进度(%)、工期状态、计划生产周期、实际生产周期、生产周期倍数，还有工单进度条。任务列表也有任务进度(%)和时间进度(%)。证据：catalog `BL-04-01`、`BL-04-02`。
- **我们现状**：A 生产计划列表只有状态；生产总览的大屏在味美工作区「尚未取到进度数据」（A-production-chain.md 第 397 节起）；六膳门有 460 个任务、428 条报工可以汇总，但没有和计划时间对照。
- **为什么值得借鉴**：「完成 40%」本身说明不了问题；完成 40%、时间已用 80%，才说明要出问题。两个进度并排，经理一眼就能挑出落后的工单，不用逐张点开。
- **不该照搬**：①只要「完成进度对时间进度」这一组，加一个「落后 / 正常 / 已超期」标签（代码判定），不要黑湖那一串周期列；②味美的计划只有日期、没有时刻，时间进度按天算；③计划日期缺失时显示「无计划时间，不能判断工期」，不出百分比。

### 6. 单据操作日志，带字段级变更前后值 · D · 高
- **黑湖怎么做**：「系统配置 → 操作日志」可以按模块、单据编号、操作类型、时间查询；详情列出「字段名 / 变更前 / 变更后」，并标明是人工编辑还是自定义事件触发。各列表右上都有「操作记录」入口，直接打开该单的日志。证据：`P/BL-12-04.html`、`P/D-SYS-log-detail.html`、`P/D-PASSIVE-BL-02-03-logs.html`，截图 `S/status-menu.png` 右侧「操作记录」。
- **我们现状**：首页「最近保存」5 条都显示「创建批次 / PLAN-LOCAL-…」，只差时间，分不清改了什么（D-home-analytics.md 第 157 行）；规格里检索不到操作日志或变更前值。
- **为什么值得借鉴**：多人改同一张计划、BOM、价格时，「谁在什么时候把什么从多少改成多少」是排查错误和划分责任的唯一依据；也能把「最近保存」从只有时间变成「改了交期 11-12 → 11-15」这样有内容的记录。
- **不该照搬**：①不另起系统配置菜单，放在每张单据详情的「记录」页签（C 已把时间线移进详情），首页「最近保存」跳到这里；②只列真正变了的字段，黑湖把未变字段也逐行列出（如「工单编号 DEMO-0001 → DEMO-0001」），噪音太多；③AI 生成的草稿被人确认时，日志里写明「来源：AI 草稿，人工确认」，延续「三种状态分开」的 AI 协议。

### 7. 不良品项字典，按工序、人员统计不良分布 · E（A 报工采集）· 高
- **黑湖怎么做**：基础数据有「不良品项」字典；工序上可以绑定不良品项列表和检验规范；报工时录不良品数和不良品项；报表有「不良品项分布 / 汇总 / 明细」，按工单、工序、生产人员列出报工数、良品数、不良品项数、不良品项比率、不良品率，「不良品项配置」能挑选要统计哪几项（原型里实际出现了「X光检验不良」「金检不良」）。证据：`P/BL-09-04.html`，catalog `BL-09-05`（工序的「不良品项列表」「检验规范」列），`P/BL-11-04.html`、`P/BL-11-05.html`，`P/D-PASSIVE-BL-11-06-defectconfig.html`。
- **我们现状**：质量管理只有「包装标签拍检」一项；A–D 规格里检索不到「不良」；报工只记数量。
- **为什么值得借鉴**：食品厂的金检、X 光、外观、重量不良是天天发生的事。有了按工序和不良项的分布，质量和生产主管能看出不良集中在哪一道工序、哪一类问题，而不是只知道总合格率；这也是 N7 分阶段检验之后最自然的数据出口。
- **不该照搬**：①不良品项字典归 E，报工时由 A 采集（选项来自字典），统计页在 E；②不做「按生产人员排名」的个人视图，只到工序和班组（与 B5「不放个人名单」一致）；③没有报工不良数据的工作区显示「未采集不良项」，不显示 0%（D13 已指出「0.0% 合格率」的问题）。

### 8. 库龄与呆滞库存分档 · C · 高
- **黑湖怎么做**：自定义页面「呆滞库存查询」按物料列出库存、最后出入库时间、库龄天数和分档标签（如「正常（≤30天）」），点开能看「产品出入库记录」。证据：`P/BL-16-01.html`、`P/D-EMBED-stock-basic.html`（v14 只复刻了内嵌界面，查询逻辑没复制）。
- **我们现状**：库存查询（C18）区分在库、可用、预留、在途，但没有库龄；规格里检索不到「呆滞」「临期」「效期」，保质期只出现 4 次（批次属性）。

- **不该照搬**：不做通用事件设计器；只把已有的预警和定时规则统一展示为「规则 / 最近触发 / 近 3 天次数 / 日志」，放在异常预警页内。

### 25. 动作级权限清单 · D · 低
- **黑湖怎么做**：WEB 端权限按菜单列出每个动作（工单：创建、导出、导入、编辑、查看、打印、调优先级、复制、开始、结束、撤回、取消、操作日志、删除、极速下单……），另有字段权限。证据：`P/D-SYS-web-permission.html`、`P/D-SYS-web-production-actions.html`。
- **我们现状**：C、D 规格多处要求「无权限按钮不可见」，但没有一张动作清单，各页自己判断。
- **为什么值得借鉴**：把每页的动作列成一张清单，是验收「无权限账号看不到按钮」的依据，也方便统一按钮命名。
- **不该照搬**：原型不做权限配置界面（不改账号权限，W9）；只在「原型与来源」里给一张只读的「页面动作 × 角色」对照表。

### 26. 报工时段规则 · A · 低
- **黑湖怎么做**：「报工 → 时段规则」：规则可以拖拽排序，按顺序从上到下匹配，命中后使用该规则；规则包含适用范围和时段详情，用于算休息、加班、有效工时。证据：`P/D-PASSIVE-BL-04-04-timerules.html`。
- **我们现状**：A 报工只记数量和时间。
- **为什么值得借鉴**：有效工时是第 15、16 条的分母；午休和夜班的规则写清楚，工时才可信。
- **不该照搬**：本轮不做配置界面，只把班次时段写进工作区配置，由代码算有效工时；等第 15、16 条落地后再看是否需要。

## 3 黑湖做得不好、我们应避免的

1. **默认列和筛选字段太多。**按 catalog 的 columnSchema 统计（默认勾选 / 可选总数）：销售明细 35/63（`BL-02-02`），工单 31/56（`BL-04-01`），任务 46/81（`BL-04-02`），履约助手 26/47（`BL-02-03`）；任务页筛选区有 24 个字段，占掉大半屏（截图 `S/status-menu.png`）。我们坚持 W6 默认 8–9 列、筛选区只放 3–5 个常用项，其余进「更多筛选」。
2. **核心数量的口径能被用户改，而且会过期。**履约助手的计算配置允许改加减项；页面自己写着「公式变更不会更新已生成的缺料数量」「手动编辑过的缺料数量不支持公式变更或计算更新」「缺料数量更新可能会存在 5-10分钟 的延迟」（`P/D-PASSIVE-BL-02-03-calculation-planshortage.html`）。同一个「缺料数」在不同行可能是不同公式、不同时点、或被人手改过。我们的口径只读，由代码实时算，并显示数据时点。
3. **合计不分单位。**进销存汇总等列表在 KG、包、个混排时，表尾仍只出一个「合计」（`P/D-PASSIVE-BL-07-09-countfilter.html`）。我们按单位分组合计，或者不出合计（N6 已要求不同单位分行）。
4. **同一类数据重复做菜单。**「收发明细」在销售、采购、委外各有一个，库存还有「库存收发明细」；库存有库存余额、库存余额明细、多维库存明细、进销存汇总、多维进销存报表五个相近的视图（catalog `BL-07-05`～`BL-07-10`）。我们一类数据只放一个主页面，其他地方用页签或筛选进入。
5. **配置入口挤在业务页头。**几乎每个列表的标题栏都有「数据分析模板 / 打印模板 / 移动端卡片 / 自定义事件」，工具栏有「字段配置 / 排序 / 行高 / 操作记录」（截图 `S/relative-date.png`）。业务用户每天都要看到这些管理员才用的入口。我们把这类入口收进「⋯」或管理员设置，页头只放主操作。
6. **侧栏让配置和业务平级。**一级菜单里，「自定义配置」（25 项）、「系统配置」、「插件市场」、「自定义页面」和业务模块并列（catalog `BL-10-*`、`BL-12-*`）。我们沿用 D9 和 D10：脚手架和配置收进账号菜单，侧栏只放业务任务组。
7. **自定义内嵌页面和主系统长得不一样。**呆滞库存、产品追溯、工单与任务看板都是内嵌的自定义页面（「仅外层框架；内嵌功能未复刻」），交互和样式与主系统不一致。我们把这些能力并入原有页面（见第 8、20 条），不另开内嵌页面。
8. **空值写法混乱。**同一行里未开始的进度有的显示「-」，有的显示「0%」（`P/D-PASSIVE-BL-02-02-progressconfig.html`）；未生成的单据显示「未生成」，没有数据的列显示「-」。我们统一用：「未返回」（没取到）、「未填写」（字段空）、「无记录」（真的没有）；不用 0 或 0% 代替缺失。
9. **菜单名和字段名不统一。**有「委外对账单New」这种带英文角标的菜单名；自定义字段（计算初成数量、单片重量、原材价格、领料重量）混进系统列，看不出哪些是标准字段。我们菜单名只用中文业务名，自定义字段在列设置里单独分组。
10. **各模块状态名不统一。**工单和任务的状态是「未开始 / 执行中 / 已结束 / 已取消」（截图 `S/status-menu.png`），销售明细里却写「进行中」（`P/D-PASSIVE-BL-02-02-progressconfig.html`），同一个意思有两种说法。我们按 N2 由代码映射，各列表共用一套三态加「已取消」。
11. **以列表为中心，缺少「下一步」引导。**黑湖大部分页面只有表格和工具栏，用户得自己判断下一步做什么；履约助手的行内「安排生产 / 安排采购」是少数例外。我们借鉴的是这个例外（第 1、2 条），每个异常行只给一个明确的下一步，而不是照搬整套「表格 + 配置」的页面结构。
