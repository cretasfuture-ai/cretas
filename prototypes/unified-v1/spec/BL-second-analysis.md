## 1 一页结论

**我们的真优势（4 条）**
1. **对「数据不全」诚实**：每个数标来源（黑湖 / Cretas 补充）、标时点，缺了写「未返回」「无法计算」，不用 0 冒充。六膳门真实数据一半以上是空的（第 3 节），黑湖界面照常给出 0% 不良率、0 元材料成本，我们会把它们分开（截图/08、10）。
2. **一页里能看到「为什么」**：工单列表一行就是完成进度对时间进度、工期、领 / 产 / 入闭环（截图/02），成本页并排「黑湖值 / Cretas 计算 / 采用值」并列出不能算的原因（截图/10）。黑湖要跨五六个菜单自己拼。
3. **食品概念有位置**：味美工作区有批次、过期日期、「即将过期」计数、标准出成率按「计划量 ÷ 出成率」倒推投料（截图/16）；Cretas 正式系统还有 HACCP/CCP、按客户和日期倒查批次、库存冻结、过敏原标签草稿等能力（仓库源码可查）。v14 复刻的黑湖里检索不到批次、保质期、温度、过敏原、CCP、召回这些词。
4. **AI 有边界**：悬浮窗先列出「依据」（代码算的事实），再给解读，只读不改单（截图/18）。黑湖的「数据分析模板」只是在列表上挂报表，不解释数字。

**黑湖的真优势（4 条）**
1. **单据是活的**：开单、审批、出入库、报工全在黑湖里真实发生，六膳门一个月产生 776 张出入库单、641 条报工、218 张工单。我们六膳门侧几乎全是只读，味美侧样本极少（1 张计划、0 张销售单，截图/15）。
2. **车间端有现成的报工终端和打卡**：任务、报工、报工工作台、打卡统计、移动端卡片一应俱全（catalog `BL-04-*`、`BL-11-09`）。我们的车间端还停在原型。
3. **配置能力强**：25 类对象可加自定义字段、编号规则、自定义事件、自定义报表与看板。六膳门就是靠这个补出了「出成率」「单片重量」「领料重量」「计算初成数量」等食品字段，并建了一张叫「出成率」的自定义报表（`P/BL-14-01`）。
4. **委外、价目、应收应付、开票这些「进销存 + 财务」外围齐全**，字段很深（委外明细 88 列）。

**最值得做的 5 个优化（按收益排序）**
1. **出成率 / 副产品做成一等公民**：六膳门 33 道工序的出成率全是 1.00，只好造一道叫「计算初成」的假工序和一堆自定义字段；不良只出现在「砍排修油」（推断：修下来的肥油和边角被记成了不良）。把「投入 → 主产品 + 副产品 + 损耗」做进报工，是分切肉厂最痛、黑湖最弱的点。
2. **批次贯穿出入库行**：黑湖 1,353 条出入库明细没有一个批次、生产日期或保质期字段，追溯与先到期先出无从谈起。我们的追溯、库龄、召回全靠这一个字段，必须在入库那一刻就收。
3. **「模块是否还在用」要写在数字旁边**：六膳门应收只录了 5 张（全在 10 月）、收款只到 10-25、待开票 213 万是合同额的 4.9 倍，我们的经营分析页照常把这些当头条显示（截图/11）。要给每类来源标「最近一次录入日期」，过期就降级为「模块疑似停用」。
4. **订单 → 工单的真实关联**：333 条销售明细里关联工单、关联采购的字段 0 条有值，工单只能靠单号前缀「S2026xxxx-001-001」猜。齐套、履约、按订单看成本都卡在这里。让关联在下单 / 建工单时由系统带出，而不是事后补。
5. **报工从「事后补一笔」改成「过程中一扫一报」**：574 / 601 个任务只报了一次，40% 的报工开始时间等于结束时间，46% 的任务工时为 0。有效工时、人工成本、效率（BL-borrow 15、16、26）全建在这上面。

**要点**
- 黑湖的问题不是缺环节，而是**每一环都允许不填关联就往下走**：工单可以不挂订单、领料可以不挂工单、出入库可以不带批次、报工可以起止时间相同。链条在系统里存在，在数据里断了。深化 BL-borrow 第 3 节第 11 条（「缺少下一步引导」）：缺的不只是引导，是**必填的关联**。
- 我们的问题是**只能看不能办**。六膳门侧所有「下一步」都只能写「在黑湖办理」。这是 DECISIONS W4 的既定边界，不是缺陷，但要清楚：只读产品无法修复上面这些数据断点，只能把断点照出来。

**要点**
- 黑湖是通用离散制造 MES，食品概念基本靠「自定义字段 + 假工序 + 假供应商 + 假客户」拼出来。六膳门的四种变通（「计算初成」工序、「客户自带原料专用」供应商、「品控留样 / 研发领用」客户、修油记成不良）每一种都在提示我们该把什么做成正式功能。
- 我们的结构领先在**正式系统**和**味美工作区**；六膳门工作区是只读黑湖，所以凡是黑湖没有的字段，我们在六膳门这边也一样空。来源原则（黑湖为准、Cretas 补充）在这里有一个盲点：**黑湖没有这个字段时，「补充」入口也没处可放**——例如批次，补也只能补到 Cretas 自己的单据上。

**要点**
- 深化 BL-borrow 第 3 条（口径弹层）：口径弹层解决「这个数怎么算」，还缺「这个数有多可信」。建议同一个弹层多两行：**覆盖**（有几张单参与、几张缺）和**新鲜度**（这类单据最近一次录入是哪天）。
- AI 悬浮窗的「依据」区目前列的都是计数（可算 84 / 215、未完工 37…）；可以把「最近录入日期」「与上月比的数量级」加进去，模型才有材料说出「应收模块 10 月底后没人录了，这个逾期数不可信」。这一句代码就能算，不需要模型猜。

### 2.6 实施与落地成本

| 项 | 黑湖 | 我们 | 判断 |
|---|---|---|---|
| 落地方式 | 通用模块 + 25 类自定义配置 + 自定义事件 / 页面 / 报表 + 插件 | 食品概念内置；工厂差异走「对话建厂」和按厂开关（机制归系统、策略按厂配） | 我们的方向省人，但还没在真厂上跑过 |
| 谁在维护 | 六膳门一个月的操作日志 992 条，25% 是改自定义字段；建了 1 张自定义报表、1 块看板（推断：有一位懂配置的人在维护） | 现在是我们自己（原型五批、十几个会话） | 黑湖的配置成本落在工厂；我们的落在我们 |
| 配置没做的后果 | 33 道工序出成率未配、安全库存未配、检验规范未配、价目表 46 条里 10 条单价 0、供应商价目 0 条，对应的智能补货、出成、检验、价格功能全部空转 | 同样：标准出成率「未填」，味美保质期「未录」 | 一样的病：功能依赖的主数据没人填 |
| 上手门槛 | 每页 20+ 筛选、30+ 默认列 | 3–5 个筛选、8–14 列，岗位视图 | 我们更好 |
| 切换成本 | 已在用一个月，单据在里面 | 六膳门只读接入，零切换成本；但要接管业务就得做录入端 | 短期「黑湖录、Cretas 看」最现实 |

**要点**
- 黑湖「功能多但用不起来」的直接原因是**主数据依赖**：补货要安全库存、出成要工序出成率、检验要规范和检验项、价格偏离要价目表。六膳门这些主数据要么 0 条、要么全是默认值。我们的功能同样依赖这些主数据，所以真正的落地成本不在页面，在**谁来填、什么时候填**。
- 建议把「主数据完整度」做成一个对工厂可见的清单（哪些功能因为缺哪类主数据而停着），而不是在每个功能页各写一句「无法计算」。这比再做一个功能更能推动工厂把数据补上。

### 3.3 这对我们意味着什么

1. **六膳门真正在用的是「工单 + 报工 + 出入库」这一条生产记账链**，销售只用到开单，财务、质量、协同、设备、价目基本没用。我们给六膳门做的经营分析、质量检验、协同任务、价目对照，读到的都是这些空转模块，页面再好看，老板也拿不到真信息。下一步的投入应该集中在生产记账链上：出成、副产品、批次、报工质量。
2. **黑湖的功能多，用不起来的原因是主数据和关联没人填**，不是界面不好。我们如果只是换一个更清楚的界面，同样的空转会在我们这边重演（味美库龄、补货建议已经是这样）。差异化必须落在「系统帮你填」：报工时按称重自动带出投入、产出、副产品；入库时按来源单自动带批次；下单时自动生成工单关联。
3. **工厂的变通就是需求清单**：假工序「计算初成」= 要出成率；假供应商「客户自带原料专用」= 要代加工；假客户「品控留样」= 要内部领用 / 留样单；修油记不良 = 要副产品。这四项黑湖都没有正式功能，Cretas 正式系统有其中两项（联产、代加工），值得优先接到原型里给六膳门看。
4. **只读接黑湖有天花板**：数据断在黑湖里，我们只能照出来。如果要真正改善，至少要在一两个点上让六膳门在 Cretas 里录入（最有价值的是报工称重和入库批次）。这是产品方向问题，见第 4 节第三组。

## 5 不确定与没看到的

1. **黑湖成本模块**：v14 跳过成本，只能从六膳门真实的 `project_cost`（212 张）反推黑湖成本口径，没看到黑湖成本页本身怎么展示、能否手调。
2. **内嵌页面未复刻**：呆滞库存、产品追溯、工单与任务看板、插件只有外壳。黑湖的产品追溯到底按什么追（推断：按单据关联，因为没有批次字段），没法从复刻里确认。
3. **「v14 检索不到」≠「黑湖没有」**：v14 复刻的是六膳门这个租户当前开通、当前配置下的界面。黑湖产品本身可能有批次管理、保质期等模块但没开通（推断，未核实）。第 2.4 节的「没有」都应理解为「六膳门租户里没有」。
4. **操作日志只有 8 个日期**：992 条日志覆盖的日期不连续，可能是采集查询窗口限制，「谁在维护配置」的推断依据偏弱。
5. **单据审批「即建即批」**：642 / 776 的判断只看了时间戳相等，可能是黑湖对某些单据类型不需要审批时自动写入审批时间，不一定是人在走过场（推断）。
6. **修油记成不良**：只凭「不良全在砍排修油」推断，没有不良品项明细（黑湖未返回），需要问六膳门车间确认。
7. **待开票 213 万**：只做了和合同额的比较；黑湖「待开票金额」的口径（是否含已发未开、是否重复累计）没有文档可查。
8. **统一原型没有逐页点完**：六膳门看了 14 页、味美看了 6 页；味美销售订单、采购、成本页和六膳门委外、客户价目、领退料页没有实看，相关判断依据规格与回执（impl-A、impl-C）。AI 悬浮窗只打开看了「依据」区，没有发送提问，严格 / 解释模式的回答质量这次未实测。
9. **Cretas 正式系统能力**：CCP、联产、召回、过敏原、代加工等只按仓库源码文件名和历史记录确认存在，没有在本次实际跑过；它们目前不在统一原型里。
10. **六膳门数据只有一个月**：10-14 前的历史不在采集范围，月度节奏（例如月底集中开票、集中收款）看不出来，「应收模块停用」的判断需要再过一个月复核。
