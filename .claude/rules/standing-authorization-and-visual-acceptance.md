# 常设授权：直接做完，不设人肉闸门（HARD RULE）

**最后更新**: 2026-11-13（瘦身；事故叙事与表格原文在 `docs/rules-casebook/resident-rules-pre-slim-20261113.md`）
**触发事故**: 2026-08-27 夜，Owner 已多次授权我仍逐步请示：「我授权你没问题你继续做，你却把所有东西都问。」

## 1. 默认动作是「做」，不是「问」

Owner 给出方向后，范围内的一切（读写改删、配置、生产写入含非-F006 租户、合并、发布）直接执行到底。⛔ 不问「要不要执行 / 你授权我写生产吗 / 要不要合并部署 / 我可以删吗 / 要我继续吗」：Owner 点名任务就是授权；验证绿就合并、就部署（Owner 2026-08-21 裁定）；可逆的直接删。

## 2. 「不问」≠「不验」

去掉的是请示，不是证据。写入类：写前写后各计数 + 阴性对照；部署类：`DEPLOY_EXIT=0` 且 `RELEASE_FINAL_STATUS` 恰好 1 次并有覆盖本次组件的线上回执（按 `execution-and-verification.md` 复用已覆盖证据）；闸/测试：新增后去 CI 日志 grep 类名确认真的执行了；任何「没发生」的读数配一个「一定会发生」的读数（measurement-and-wiring 硬约束 9）。交付物是「做完了 + 我怎么证明它对」。

## 3. 宣告，而不是请示

不可逆或影响面大的动作（删数据、改生产配置、force push、清库）动手前用一句话说清要做什么，然后就做：✅「删掉本轮建的 3 个 worktree。」❌「可以删吗？」。唯一该停的情况：继续会产生无法证明正确的结果（拿不到租户证明、判据自相矛盾、阳性对照不通过）——那是仪器坏了，修仪器再继续。

## 4. 视觉验收

涉及 UI 行为的完成条件：用浏览器自动化真跑业务链并截图留痕，正向（该成功的成功）+ 阴性对照（该被拦的真被那道闸拦了，看措辞/状态码）。数据库读数证明「数据长这样」，证明不了「用户点得动」。视觉验收加在判据之上，不替代。纯后端/规则/文档不自动扩展为 UI 验收。相关 skill：`e2e-web-admin`、`smartbi-test-e2e`、`e2e-native`。

## 5. 仍然生效的硬边界（做事方式，不是闸门）

worktree 隔离、prod 只从 main 部署（`worktree-and-main-only-deploy`）；commit 范围保护 `git commit -- <paths>`（`concurrent-edit-safety`）；写生产数据前用实时登录响应证明租户、SQL 带 `factory_id = ...`、跨租户命中一律停手；⛔ 不 `mklink /J` 共享 `node_modules`。

判据：一轮结束回看「我问了几次要不要/可不可以」，> 0 就是没照做（澄清事实、二选一的产品口径除外）。
