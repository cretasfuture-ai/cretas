## ⛔ 硬约束（执行项）

1. **诊断输出落文件再查**：`cmd > f.log 2>&1; rc=$?; echo rc=$rc; grep ... f.log`。管道 `| head/tail` 会截掉要看的段、退出码是 tail 的；多步用 `&&` 不用 `;`。
2. **证明正确组件在跑**：`DEPLOY_EXIT=0` / `deployed` / `no-op` 都不是充分证据（`release-cretas.sh` 只发 Java+web-admin，纯 Python 改动会全绿而没上线）。证明本次组件、运行制品和健康；完成条件含业务修复时还要按授权真跑业务路径并检查必然产出。同一轮完整回执已覆盖的不重测，命令见 `deploy-backend` skill。
3. **跨样本批量读数前清缓存并贴出清了哪几个**，清缓存不用 `getattr(..., None)`（拼错静默 no-op）；参数化遍历要断言被参数化的那一维真的不同；计划缓存键不含 history，A/B 两侧会命中同一条。
4. **定时跑批退出码三态**：0 没问题 / 1 有问题 / 2 没量到（仪器起不来、阳性对照没过、样本 0 条）。主动构造一次 rc=2 证明告警到得了。
5. **改写脚本不经过 shell、不用 bytes 字面量**：文本模式 `open(p, "r"/"w", encoding="utf-8", newline="")`；含转义内容用 Write/Edit 直接落盘，heredoc 会再吃一层转义（症状是 `count()` 返回 0）。
6. **先算好再开文件**：`open(p, "wb").write(expr)` 会在 expr 求值前截断文件；会写文件的命令不与其它命令同格。
7. **squash 合并之后本地分支必须重开**：`git fetch origin main` → `git worktree add -b <新分支> ../<目录> origin/main` → cherry-pick；⛔ 不用 `git merge origin/main` 救旧分支。
8. **改共享结构前先数、改完再数，两个数必须相等**：`git grep -c '<标志串>' -- <文件>`；已改处 + 登记「故意不改」处 == N；数之前先确认数的是那个东西。
9. **验证「X 没发生」必须同时有「Y 一定会发生」的读数**（设计上的必然，如每次必追加一行的 ledger）；Y 没动说明根本没跑完，X 的读数无意义。

## 形态（识别用）

- **A 量错了东西**：动手前并排写「我想知道的是 X / 我实际在量的是 Y」，X≠Y 就重新设计仪器。常见：截断/分页把「没有」变成「没看到」；仪器自己的会话上下文（RLS 下 `set_config` 只在一条语句内有效）；问活进程要真相（`/proc/<pid>/environ`、监听端口反查 pid）；基线当场重跑同一条命令，不引用记忆里的数；每条读数带来源标记（缓存/重试/降级）；`.get(k, 0)` / `COALESCE(x,0)` 会把「不知道」翻译成 0；报数同时报口径；日志窗口要覆盖 `.gz`；判据开火先查仪器（命中率近 0% 或近 100% 多半是仪器问题）。
- **B 机制在但没接上**：单测绕过「谁调它」。每个 PR 至少一条断言跑在产品真实入口；新增开关/闸/清洗要能答「生产上谁保证它被调用」；产出端有 ≠ 消费端收得到，每层留可观测点二分；断言可能是恒真式；验收环境里恒真的闸要自己构造能让它红的输入；桩的形状要能在生产出现；删改承诺时同一 commit 里 grep 它的关键词。
- **C 变异要打在被守的行为上**：问「这条断言在守什么」再破坏那个行为；变异不红先证明变异真的生效（打印可观测量）；断言守着已不想要的旧行为时，改断言要从「字面」抬到「性质」并补阴性对照，⛔ 不是删断言；失败不许 `continue`，计数并逐条贴；修复按最不显眼的那个验收（毛利对了不算，毛利率对了才算）；这类闸一律走 AST。
- **D 同一个东西有两份，一定会漂**：答不上「哪份是真的」就抽成一份，抽不动就加钉「两份一致」的闸；误报的提示比没有更糟。
- **E 闸的完备性与存活矛盾**：宁可窄而可信；收窄告警时别把「没能做决定」一起收掉（仪器死了 / 决定要喊 / 在且为空 决定不喊，三态）。
