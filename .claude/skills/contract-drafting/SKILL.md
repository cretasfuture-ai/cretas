# 白垩纪对外合同起草

## Overview

对外合同不是写完就发的文字，是一串可核验的决定。核心原则：**拍板记录是唯一商务依据；发送稿里没有一个字是关于文件本身的；每处改动可被脚本核验。**

**REQUIRED READING（动手前）**：本目录 `standards.md`（流程、条款原则、文字标准、坑）。条款写法查 `clauses.md`。

## When to Use

- 新客户合同 / 保密协议 / 合作方案 / 报价 / 排他或股权文件从零起草
- 改价、改条款、拆独立协议、换主体
- 把 md 转成发送用 Word/PDF
- 发出前审文字：AI 味、英文直译、缩写、占位标记、内部痕迹
- 不用于：内部备忘、给律师的问题清单（那些不受对外文字标准约束）

## 流程（不跳步）

1. **商务先拍板**：口头条件 → 决策备忘 → 创始人逐条拍板并编号 → 才起草。价格从成本账推、折让有名义。
2. **核对方主体**：信用代码、股东穿透、签约主体≠持股主体、风险页。
3. **起草**：结构按科技部示范文本；条款写法从 `clauses.md` 取；有独立对价的安排（排他、股权）拆成独立协议。
4. **对抗审计**：换模型多轮，每轮出拍板表；审完做「谈判姿态」修正。
5. **文字与排版**：按 `standards.md` 第三节；全部中文缩写、“”、无空格、全角编号、只有小标题加粗、零占位。
6. **审计**：`python tools/audit.py <文件…>` 命中为 0（合法用法逐条排除）；金额五处一致；平行合同 diff 落在对照表内。
7. **出包**：`tools/build_docx.py jobs.json` → `tools/to_pdf.ps1`；发 Word 不发 PDF；说明写消息正文，不写送审函、不写进合同。
8. **发出后**：`_sent-日期/` 快照；不再改价、改定义，等对方回修订稿那一轮。

## Common Mistakes

- **任务描述里的「人日 / T0 / SLA / P0」照抄进合同**——那是内部口语，落到发送稿一律翻成工日 / 首笔款到账日 / 服务等级 / 严重故障。
- 只被要求写部分条款时加一行「……（第一条至第四条略）」——那是给读者的说明，不是条款；直接从第五条开始写。
- 描述文件本身（供审阅稿、只签其一、待定）——那是消息正文的内容，不是合同。
- 缩写加英文括注「严重故障（Critical）」——直接写中文。
- 「不承担任何责任」——写可归责范围。
- 违约金写「不受责任限额限制」——应计入限额、故意除外、实际损失可另行主张。
- 把股权当排他对价、把折让写成股权对价——税务两头吃亏，还给融资定了锚。
- 对比表里加一行让某一版显得便宜——两版平等摆出。
- 发出后改价。
