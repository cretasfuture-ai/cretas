# 分发细节（仅在真正委派或跨会话时读取）

执行、验证和证据复用以 `.claude/rules/execution-and-verification.md` 为准；本文件只补分工与任务包，不重复写设计、模型资格表或验收流程。

## 执行方式

| 情况 | 做法 |
|---|---|
| 单任务、已有上下文、步骤强依赖，或数个很小的相关修改 | 当前执行者 DIRECT 完成 |
| 独立的较长切片，或需隔离大量日志/搜索输出 | 在 scope 和命令资源不重叠时委派 |
| 权限/安全、迁移、生产、金额/库存一致性或跨模块契约 | 保留独立终审，由协调者核对并收尾 |
| 跨天、多轮实现、需保留环境和调查结果 | 使用持久独立会话及交接登记 |

Claude 内可按实际需要使用 `executor`（实现）、`probe`（运行取证）、`recon`（窄范围只读调查）；代理配置是运行时默认，能力以当前实际工具为准。Codex/其他工具按各自规则执行，不继承本技能的角色；交接只传与任务有关的共享约束。用户当前模型与 effort 不构成资格或切换门禁。

## 简短任务包

```markdown
任务 ID / Owner / Base SHA：
worktree 绝对路径 / 分支 / 当前 HEAD：
目标与完成条件：
允许修改 / 禁止范围 / 依赖与共享资源：
设计、必要规则与入口：<可访问的准确路径；补充接收方拿不到的关键约束>
验收命令 / 已有证据与受测版本：
停止条件与交付范围：<commit/PR；不自行合并、部署或迁移>
```

回执只补实际修改文件、验收命令/结果与证据、commit/PR、阻塞及下一动作；不重写任务包和上游设计。合并/生产、租户、数据、JPA 与权限边界不能因精简省略。
