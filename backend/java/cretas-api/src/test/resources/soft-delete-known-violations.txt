# 软删注解覆盖率棘轮 —— 已登记的 offender 清单（只许变短）
#
# 守闸: SoftDeleteAnnotationCoverageRatchetContractTest
# 建闸: 2026-09-06, ARCH-PRODUCTION-PLAN-HARD-DELETE-PATH-20260906
#
# 这里每一行是一个实体: 它带类级 @Where(clause = "deleted_at IS NULL"),
# 但**没有**类级 @SQLDelete。
#
# 为什么这是个问题:
#   BaseEntity(@MappedSuperclass) 上写着 @SQLDelete, 而 @MappedSuperclass 上的
#   @SQLDelete 与 @Where 一样**被 Hibernate 静默忽略**(见 BaseEntity 的 R68 注释)。
#   R68-FIX-A 当年把 @Where 批量补进了每个子类, @SQLDelete **没有跟着批量补**。
#   ⇒ 这些实体「查询时像软删(@Where 滤掉 deleted_at 非空的行), 删除时是物理 DELETE」。
#   两种实现的 findById 读数完全一样, 所以这个缺陷类一直没人发现 ——
#   它只在**引用完整性**(孤儿行)和**发号器/幂等键占用语义**上显形。
#
# ⛔ 不要往这个文件里加行。加行 = 允许新增同型缺陷。
#    闸的失败信息里会直接告诉你修法(补 @SQLDelete 或 @PreRemove 抛异常)。
#
# ✅ 修好一个就从这里删一行。删得只剩注释时, 把 detectorCanStillFireOnAKnownOffender
#    这条阳性对照一起处理掉(它假设清单非空)。
#
# ⚠️ 数字大 ≠ 有 329 个活缺陷: 闸只看注解, 不看有没有人真的调 delete()。
#    也不是每一条都该补 @SQLDelete —— 日志 / 血缘 / 闭包类实体本来就该**禁止**删除,
#    正解是 @PreRemove 抛异常(见 BatchLineageEdge), 那种实体减不下这份清单, 别硬凑。
#
# 格式: 一行一个 FQCN; '#' 开头是注释; 空行忽略; 重复行会让闸红。
#       与 known-failing-tests.txt 同形。
