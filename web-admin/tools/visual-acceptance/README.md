# 全路由视觉验收工具

对着一个跑着的环境，用真账号登录，遍历 **Vue Router 里的每一条路由**，逐屏截图 +
记录 console 错误 + 记录 4xx/5xx。2026-08-28 用它跑 F006 的 287 条路由，抓到 2 个
从上线起就没工作过的缺陷。

```bash
# 前端指向目标环境 (web-admin/.env.local)
#   VITE_BACKEND_URL=http://<host>:10010
#   VITE_PYTHON_URL=http://<host>:8083
npx vite --port 5173 --host 127.0.0.1

OUT_DIR=/tmp/acceptance E2E_USER=f006_admin node tools/visual-acceptance/visual-sweep.cjs
node tools/visual-acceptance/instrument-positive-control.cjs      # 仪器自检
```

---

## ⚠️ 先读这一段：这个工具的第一版交出过一份**假绿**的验收

第一版报 **「287 屏 / 280 干净 / 0 错误」**，而且已经跑过阳性对照。读数看起来无懈可击。

真相：**289 张截图只有 96 个不同图像，最大一组 22 张逐字节相同** ——
截到的是「白垩纪 AI Agent / 正在加载应用…」**启动闪屏**。

成因：用 `page.goto()` 逐条访问 ⇒ **整页刷新**，每次都要重新引导整个 SPA
（登录态恢复 / 权限 / 模块配置，实测约 8 秒），而它只等 2.2 秒。

于是每一项判据都"正确地"指向干净：

| 判据 | 页面没渲染时的值 | 被读成 |
|---|---|---|
| `location.pathname` | 已经是目标路由（URL 先变） | 没被跳走 ✅ |
| console errors | 0（什么都没执行） | 没报错 ✅ |
| API 4xx/5xx | 0（还没发请求） | 接口正常 ✅ |

▎**「没渲染」和「渲染了且没问题」在每一项判据上长得一模一样。**

**阳性对照为什么没救回来**：它证明的是**监听器**活着（强制一个 404 能被记录），
不是**页面**渲染了。⇒ 阳性对照要对准你担心的那个失效，不是对准仪器的某个零件。

## 现在这一版怎么防它

1. **SPA 内部导航**（`router.push`）代替 `page.goto` —— 应用只引导一次
2. **等闪屏消失**再截图，而不是固定 sleep
3. **三态**：`UNMEASURED`（还在闪屏）**不算 clean**。把"没量到"折进"没问题"正是第一版的错
4. **仪器自检**跟着读数一起打印：
   - `distinct rendered-text fingerprints : N / M` —— 显著小于 1 就可疑
   - `routes that made ZERO api calls` ——
   这两个数是唯一抓到第一版的东西，而它们当初只是顺手加的

▎**截图数不是覆盖数。报「N 屏通过」之前先报「N 屏里有几张是不一样的」。**

## 另外两个踩过的坑

- **分类器顺序**：403 页面正文只有 34 个字符，会被"文本太短 = 还在闪屏"吞掉。
  必须**先判落地页面，再猜是不是闪屏** —— 曾把 62 条正确渲染的 403 记成"没量到"。
- **代理验证要用能区分的探针**：用 `/api/mobile/health` 验证 vite 代理指对了没有，
  会失败 —— 本机可能另有一个后端，两者对该端点的回答一模一样。
  用**登录**（一个 401 一个 200）才分得开。

## 已知不覆盖

- 参数化路由（`/sales/orders/:id`）不访问，但**逐条列进 json**，不是静默丢弃
- 只跑 web-admin，不含 RN App
