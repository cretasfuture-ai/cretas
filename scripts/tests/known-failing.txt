# ⛔ 名单里的用例**照常执行**, 不是 skip —— skip 会让「已经修好了」永远发现不了。
#    五条判定(见 run-script-tests.sh):

#      · rc=77 但日志里没有 `SKIPPED:<理由>` 行 ⇒ 红; 77 且同时在本名单里 ⇒ 红

#
# ⚠️ 加一条进来之前问一句: 这是**存量**, 还是我这次改红的? 后者不许进名单。
#
# ── FLAKY 是第四态, ⚠️ 不是「豁免」的委婉说法 ────────────────────────────
# 一条**时红时绿**的用例放进 known-failing 会让闸在它偶然变绿的那一次报
# 「FIXED 请删掉」而红; 从名单里拿出来又会在它红的那一次报 NEW_FAILURE ——
# **两边都会让闸随机变红**, 而随机红的闸活不过一周(形态 E)。
# ⇒ 单列一态: 照常执行、rc 照常打印、但**不参与红绿判定**, 只计数。
#
# ⛔ 它必须**自带出口**, 否则就是永久豁免 —— known-failing 的出口是 FIXED 探测器,
#    而 FLAKY 没有那个(时红时绿的东西, 任何单次读数都证明不了它已经稳定)。
#    所以有两道闸, 缺一条就红:
#      ① **双向 run id**: 一次 rc=0 的 + 一次 rc≠0 的, **两个必须不同**。
#         只贴一个 = 「我看它失败过」= 确定性失败的证据, 不是 flaky 的证据。
#      ② **14 天过期**: 超期就红, 强制重新分类。时间会替你做判断 ——
#         它要么早修好了(移出去), 要么其实是确定性失败(移进 known-failing),
#         要么真还在抖(重取两侧 run id, 日期更新到今天)。
#
