## 金标怎么来的

1. 出题：Claude Opus 5.5 按（题型 × 角色）分 56 格出题，并按 Steve 8 条口径和意图目录给出整套标准答案。答案包括对话动作、结果类型、意图、完整生效参数及来源、必须写明的默认、先问的选项、恢复的是第几轮。第一轮出完后，不含 ambiguous 的先问题只有 43 道，于是第二轮只补真两可的先问题，共 8 格。
2. 盲标：Claude Sonnet 5.5 只看用户原话和出题时设想的系统回复，看不到答案，独立再标一遍。每次 4 段多轮或 12 道单轮。
3. 判定：结果类型相同、意图相同（或在任一方明确列出的替代意图里）、且意图的读写属性与题意相符，算确定题；否则标 `ambiguous`，单列计分。还有两类不一致只降级、不整题作废：参数值不一致的键记入 `uncertain_param_keys`，计分时这些键算未量到；对话动作不一致的记 `act_uncertain`，这一维算未量到。
   - 读数：799 轮里 ambiguous 65 轮（A2 12、B2 53）；含 ambiguous 轮的会话 11 段。
4. 抽查：Steve 抽查 30 题。抽查结果回来后，改动的题登记在下面的「金标修订记录」，并重算 MANIFEST。

## 真人说法槽位（待 Steve 从合作工厂拿）

现在 799 轮全部 `source=synthetic`，是 Claude 改写的口语，只用作占位。每一轮有一个槽位号 `real_slot`（`RS-<题号>-<轮次>`）。`real_slots.csv` 列出每个槽位的角色、题型、对话动作、计分类和口径规则，不含原句。

接入格式：每条真人说法一行 JSONL，放到 `Documents\Cretas意图独立验收-v2-20261112\real-intake\`。这个目录在 sealed 之外，只放原始说法，不放答案。

```json
{"intake_id": "RI-0001", "factory_alias": "合作厂A", "role": "WAREHOUSE", "situation": "刚收完货，想看还有哪些没入库",
 "text": "今天到的那几车还有没进库的吧", "audio": null, "collected_at": "2026-11-20", "consent": "书面授权编号或说明",
 "desensitized": true}
```

- 录音：先走 `transcribing-audio` skill 转写，热词里放物料名和人名，再填 `text`，`audio` 写原文件路径。
- 脱敏：人名、电话、客户名换成虚构名，并在 `desensitized` 里注明。

替换流程（由一个独立会话执行，执行者不参与训练或调参）：

1. 按角色、情境给每条真人说法挑一个题型和对话动作都匹配的槽位。多轮槽位要连同上文一起看能不能接上；接不上就新开一段，用真人说法作首句，后续轮次仍用 synthetic。
2. 用同样的出题加盲标流程，给替换后的句子重标金标。不一致的标 ambiguous。
3. 替换后的轮次改为 `source=real`，记下 `intake_id`；被换下的 synthetic 句保留在 `_build/replaced.jsonl`。
4. 重新去重，重算指纹和 MANIFEST，版本号升到 2.x，在下面的「版本记录」登记，并同步更新仓库里的指纹文件。
5. 计分时 `real` 与 `synthetic` 分开报。真人说法达到 100 轮之前，`real` 一栏只作参考。

## 使用规则

1. **只在里程碑验收时运行**：Luna 主路径一次、阿里云退路一次。开发、调参、训练期间不得用它做回归。
2. ⛔ **其他线不得读 `sealed\`**（含 `_build\`）和抽查稿。训练线、开发线只用 `holdout_v2_fingerprints.jsonl` 过滤自己的样本。
3. 运行后只报分项汇总：按计分类、对话动作、角色、题型、口径规则、`source`，各项附 Wilson 95% 区间；另报整段会话成功率。不得把逐题内容（原文、期望、模型输出）贴进训练数据、开发讨论或 PR 描述。
4. 计分沿用 PR 1629（`STRICT_SCORING.md`）的口径：
   - 结果三态：通过、失败、未量到。未量到单列，分母仍是全部题。
   - 读和写分开报；意图准确率报 exact 与 with-alternates 两种。
   - ambiguous 与 `generic_followup_dup` 单列；含 ambiguous 轮的会话记为未量到，另报去掉它们后的辅助读数。
   - v2 字段多于 v1（`outcome`、`score_kind`、`disclosed_defaults`、`resumes_turn` 等），需要一个 v2 读取器，验收前另行补上，不在本 PR 范围。
5. 被打开的题要登记并剔除：为排错打开过的题，记下题号（`V2A-xxx#轮` 或 `V2B-xxxx`），不再计入后续成绩，下一版删掉。
6. 角色：每段会话都带角色，验收时用对应角色的账号跑，不再只用厂长。
7. 数据漂移：评测前后各取一次只读快照，沿用 `read_oracle.py` 的做法。

## 已知限制

- 意图集中在每个角色的日常业务（109 个），不是 266 个意图全覆盖。
- 出题用 Claude，盲标也用 Claude（不同型号），两者的错误并不独立。没有真人说法之前，「独立」指的是出题会话独立，题目分布仍可能偏向模型的说法。这也是要尽快接入真人说法的原因。
- 「出确认卡」以后，确认卡上的对象和数量对不对，取决于参数核对。`uncertain_param_keys` 里的键没有核对。
- 去重以字符相似度为准。换了词但意思相同的改写拦不住。
- 断流的 39 次生成请求按 0 记账；如果服务端按部分输出计费，实际花费会略高于 8.94 美元。
