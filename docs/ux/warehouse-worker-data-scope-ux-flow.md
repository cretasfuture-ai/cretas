# 仓库工人「发货 / 库存」在数据范围受限时的 UX Flow（2026-11-13）

背景：F006 真机，账号 f006_warehouse_worker。岗位 `warehouse_worker` 在 F006 没有工厂级数据范围配置（`factory_role_data_scopes` 0 行），
按全局默认落到「仅本人」(SELF)。结果：「发货」两条只读队列被路由闸以「当前数据范围不支持此快捷查询或批量操作，请使用主列表」拦下，
页面整页报错；「库存」列表按 SELF 只剩本人入库的批次（0 批），全厂统计被拦，底栏显示「统计暂不可用，可下拉重试」——下拉永远不会好。

口径（Steve）：谁能做按权限、拦不拦由工厂配置。工厂总监在网页后台「角色权限 → 数据范围」可以把本岗位改成「全工厂」。
本次 ⛔ 不放宽默认数据范围，只让页面按配置给出「能看的那部分 + 为什么只看到这些 + 去哪里改」。

## UX Flow Analysis

### 用户画像
仓库工人（warehouse_worker）— 低技术素养，只认「单子」「批次」「发货」，不理解「数据范围」— 在仓库现场用手机看今天要发什么货、库里有什么货。

### 用户旅程
| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|------|---------|---------|---------|
| 1 | 底栏「发货」 | 点开 | 列出自己数据范围内的待确认 / 历史发货单，不弹错误 |
| 2 | 列表上方一条蓝色说明：只列出你（或可查看同事）创建的销售单、客户对应的发货单；全厂发货请工厂总监在网页后台「角色权限 → 数据范围」调整 | 读一眼 | 明白「为什么是 0 单」以及「找谁」，不再反复点重试 |
| 3 | 底栏「库存」 | 点开 | 看到自己数据范围内的批次；顶部同类说明 |
| 4 | 底部合计条 | 看 | 写「全工厂合计不在你的数据范围内」，不再提示「下拉重试」 |
| 5 | 发货 → 查看手工发货历史 → 扫码出库 | 点 | 与仓管主管同一入口（本次不改） |

### 摩擦点清单
| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|-----------|---------|---------|
| F1 | 发货页整页红色错误「当前数据范围不支持此快捷查询…请使用主列表」，工人不知道「主列表」在哪，重试永远失败 | HIGH | 内联 UX 规则·错误恢复（发生了什么+怎么解决）；fool-proof Rule 5 |
| F2 | 库存底栏「统计暂不可用，可下拉重试」给了一个必然无效的下一步 | HIGH | fool-proof Rule 5；4 位一体 d |
| F3 | 列表 0 条与「真的没有货」长得一样，用户以为系统坏了或库是空的 | MED | fool-proof Rule 2（上下文）/ Rule 5（空状态要有 next action） |
| F4 | 后端拒绝没有语义码，前端只能靠中文原文猜 | MED | 4 位一体 a/d |

### 每个摩擦点的设计回应
- F1 → 后端：两条队列接入行级范围（按来源单据归属在查询里过滤），不再 403；前端不再出现这条错误。
- F2 → 后端统一给这类拒绝加 `errorCode=DATA_SCOPE_UNSUPPORTED` + `actionHint`；库存合计条遇到它改写为「全工厂合计不在你的数据范围内」，不提示重试。
- F3 → 发货：后端在受限范围的成功响应里带 `actionHint`，前端显示为列表上方蓝色说明；库存：全厂统计被这个码拒绝时，列表上方显示同类说明。说明里写明找谁（工厂总监）、在哪改（网页后台「角色权限 → 数据范围」）。手机端不提供改配置按钮（工人没有这个权限，按钮只会制造新的死路）。
- F4 → 见 F2，前端只按 `errorCode` 分支，不匹配中文。

触摸目标 / 输入：本次只新增只读说明条（`Surface` + 图标 + 文字），无新增可点元素。

# 仓库工人「收货（入库管理）」在数据范围受限时的 UX Flow（2026-11-13 续）

背景：#1657 上线后真机复验，f006_warehouse_worker 一进「收货」页就弹窗「入库任务部分加载失败：当前数据范围不支持此快捷查询或批量操作，请使用主列表」，
列表区「入库任务加载失败，请点击重试」。失败的是 4 条 `purchase/orders/by-status`（FINANCE_APPROVED / PARTIAL_RECEIVED / COMPLETED / CLOSED），
被路由闸以 403 + `DATA_SCOPE_UNSUPPORTED` 拒绝。同屏的「无订单入库」任务（`warehouse/receiving/tasks`）早已接入行级范围，不受影响。
口径同上：⛔ 不放宽数据范围，只按配置返回能看的那部分，并说明为什么、找谁改。

## UX Flow Analysis

### 用户画像
仓库工人（warehouse_worker）— 低技术素养，只认「采购单」「收货」「扫码」，不理解「数据范围」— 在仓库门口用手机看今天有哪些采购单要收货、收了多少。

### 用户旅程
| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|------|---------|---------|---------|
| 1 | 底栏「收货」 | 点开 | 不弹错误窗；顶部三个大按钮「待收货任务 / 扫码入库 / 生产成品入库」照常可点 |
| 2 | 按钮下方一条蓝色说明：只列出你（或可查看同事）创建的采购单；全厂收货请工厂总监在网页后台「角色权限 → 数据范围」调整 | 读一眼 | 明白列表为什么少/为空、找谁，不去点重试 |
| 3 | 采购单列表（自己范围内的单）或「当前筛选下没有入库任务」 | 点单子 / 点「扫码入库」 | 正常进收货；扫码路径不受影响 |
| 4 | （异常）某个状态仍被范围闸拒绝（例如旧后端） | 看 | 同一位置显示原因 + 找谁调整，不出现「重试」按钮，不弹红色错误窗 |
| 5 | （异常）网络断开等真正的加载失败 | 点「重试」 | 维持原有重试行为 |

### 摩擦点清单
| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|-----------|---------|---------|
| F1 | 一进页面弹红色错误窗「部分加载失败…请使用主列表」，工人不知道主列表在哪 | HIGH | 内联 UX 规则·错误恢复；fool-proof Rule 5 |
| F2 | 列表区「加载失败，请点击重试」+ 重试按钮：范围拒绝重试永远不会好，是死路 | HIGH | fool-proof Rule 5；4 位一体 d |
| F3 | 受限范围下列表为空与「真的没有采购单」长得一样 | MED | fool-proof Rule 2 / Rule 5 |
| F4 | 错误窗挡住顶部「扫码入库」等主入口，工人以为整页不能用 | MED | 内联 UX 规则·信息密度（主操作唯一且可达） |

### 每个摩擦点的设计回应
- F1 → 后端：`purchase/orders/by-status` 接入行级范围（按采购单 `created_by` 在查询里过滤），受限范围不再 403；前端对 `DATA_SCOPE_UNSUPPORTED` 不再调用 `handleError` 弹窗。
- F2 → 前端：被范围拒绝的状态视为「不在你的范围内」，不记入待重试来源，不显示「重试」；说明条展示后端 `actionHint`（原因 + 找工厂总监 + 网页后台位置）。真正的网络/服务错误仍走原有重试。
- F3 → 后端在受限范围的成功响应里带 `actionHint`，前端在按钮下方显示蓝色说明条（`wh-inbound-scope-notice`）。手机端不放改配置按钮（工人无此权限，按钮会制造新死路）。
- F4 → 三个入口按钮位置与行为不变；说明条放在按钮之下、搜索框之上，不遮挡入口。

触摸目标 / 输入：只新增只读说明条（`Surface` + 图标 + 文字），无新增可点元素。
