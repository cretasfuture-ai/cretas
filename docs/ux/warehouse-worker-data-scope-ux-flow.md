# 仓库工人「发货 / 库存」在数据范围受限时的 UX Flow（2026-11-13）

背景：F006 真机，账号 f006_warehouse_worker。岗位 `warehouse_worker` 在 F006 没有工厂级数据范围配置（`factory_role_data_scopes` 0 行），
按全局默认落到「仅本人」(SELF)。结果：「发货」两条只读队列被路由闸以「当前数据范围不支持此快捷查询或批量操作，请使用主列表」拦下，
页面整页报错；「库存」列表按 SELF 只剩本人入库的批次（0 批），全厂统计被拦，底栏显示「统计暂不可用，可下拉重试」——下拉永远不会好。

口径（Steve）：谁能做按权限、拦不拦由工厂配置。工厂总监在网页后台「角色权限 → 数据范围」可以把本岗位改成「全工厂」。
本次 ⛔ 不放宽默认数据范围，只让页面按配置给出「能看的那部分 + 为什么只看到这些 + 去哪里改」。

## UX Flow Analysis

### 用户画像
仓库工人（warehouse_worker）— 低技术素养，只认「单子」「批次」「发货」，不理解「数据范围」— 在仓库现场用手机看今天要发什么货、库里有什么货。

### 用户旅程
| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|------|---------|---------|---------|
| 1 | 底栏「发货」 | 点开 | 列出自己数据范围内的待确认 / 历史发货单，不弹错误 |
| 2 | 列表上方一条蓝色说明：只列出你（或可查看同事）创建的销售单、客户对应的发货单；全厂发货请工厂总监在网页后台「角色权限 → 数据范围」调整 | 读一眼 | 明白「为什么是 0 单」以及「找谁」，不再反复点重试 |
| 3 | 底栏「库存」 | 点开 | 看到自己数据范围内的批次；顶部同类说明 |
| 4 | 底部合计条 | 看 | 写「全工厂合计不在你的数据范围内」，不再提示「下拉重试」 |
| 5 | 发货 → 查看手工发货历史 → 扫码出库 | 点 | 与仓管主管同一入口（本次不改） |

### 摩擦点清单
| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|-----------|---------|---------|
| F1 | 发货页整页红色错误「当前数据范围不支持此快捷查询…请使用主列表」，工人不知道「主列表」在哪，重试永远失败 | HIGH | 内联 UX 规则·错误恢复（发生了什么+怎么解决）；fool-proof Rule 5 |
| F2 | 库存底栏「统计暂不可用，可下拉重试」给了一个必然无效的下一步 | HIGH | fool-proof Rule 5；4 位一体 d |
| F3 | 列表 0 条与「真的没有货」长得一样，用户以为系统坏了或库是空的 | MED | fool-proof Rule 2（上下文）/ Rule 5（空状态要有 next action） |
| F4 | 后端拒绝没有语义码，前端只能靠中文原文猜 | MED | 4 位一体 a/d |

### 每个摩擦点的设计回应
- F1 → 后端：两条队列接入行级范围（按来源单据归属在查询里过滤），不再 403；前端不再出现这条错误。
- F2 → 后端统一给这类拒绝加 `errorCode=DATA_SCOPE_UNSUPPORTED` + `actionHint`；库存合计条遇到它改写为「全工厂合计不在你的数据范围内」，不提示重试。
- F3 → 发货：后端在受限范围的成功响应里带 `actionHint`，前端显示为列表上方蓝色说明；库存：全厂统计被这个码拒绝时，列表上方显示同类说明。说明里写明找谁（工厂总监）、在哪改（网页后台「角色权限 → 数据范围」）。手机端不提供改配置按钮（工人没有这个权限，按钮只会制造新的死路）。
- F4 → 见 F2，前端只按 `errorCode` 分支，不匹配中文。

触摸目标 / 输入：本次只新增只读说明条（`Surface` + 图标 + 文字），无新增可点元素。
