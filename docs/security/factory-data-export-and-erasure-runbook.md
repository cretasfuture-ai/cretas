## §2 表的分类：导出 / 删除 / 保留

规则是**按类别**定的，⛔ 不是逐表手写名单：手写名单一定会漏掉以后新增的表。默认类别是「业务数据」，所以新加的带 `factory_id` 的表**自动**随工厂导出和删除。只有下面显式登记的表例外，登记的唯一来源是代码 `FactoryDataCatalog`。

| 类别 | 包含 | 导出 | 删除 | 理由 |
|---|---|---|---|---|
| 业务数据（默认） | 所有带租户列的表，以及它们顺外键找到的子表 | ✅ | ✅ | 承诺的主体 |
| 工厂主记录 | `factories` 中 `id = 编号` 的那一行 | ✅ | ✅ 最后删 | 其他表都引用它 |
| 凭证类列 | 任何表里名字含 `password` / `secret` / `token` / `api_key` / `credential` / `private_key` / `salt` 的列 | ⛔ 值替换成 `[已移除]` | ✅ 随行删 | 导出包会离开平台，凭证一旦泄露就能登录或调用接口 |
| 删除回执 | `factory_data_requests`（本功能自己的台账） | ⛔ | ⛔ 保留 | 证明「删过了、删了多少」；只存编号、计数和时间，不存业务内容 |
| 审计 / 留痕 | `platform_data_access_log`、`operation_logs`、`tool_execution_audit_events`、SmartBI `smart_bi_llm_egress_audit` | ✅ | 按 Q3 | 《网络安全法》第 21 条：网络日志留存不少于 6 个月 |
| 训练样本 | 主库 `ai_training_samples` 等；SmartBI `smart_bi_distillation_samples`、`training_consent` | ✅ | 按 Q4 | 已授权样本的去留要 Steve 拍板 |
| 库内副本 | `public` 里的 `backup_*`、`repair_backup_*`、`bak_*`，以及其他 schema | ⛔（不是业务数据） | 按 Q6 | 一次性修数据时留下的副本 |
| 迁移台账 | `migration_*`、`flyway_schema_history` | ⛔ | ⛔ | 只记录表名和计数，不含业务内容 |
| 平台共享 | 不带租户列、也不被该厂数据引用的表（行业知识库、意图样例、权限定义……） | ⛔ | ⛔ | 不属于任何一个工厂 |

## §3 谁能发起、怎么核对租户

（Q1 拍板后补齐。下面是不论 Q1 怎么定都成立的部分。）

1. **申请留底**：由工厂总监（`factory_super_admin`）书面提出，微信或邮件均可，内容包括工厂名称、工厂编号、申请类型（导出 / 删除）、联系人。截图存进回执。
2. **核对申请人**：在 prod 只读查询申请人账号确实是该厂的 `factory_super_admin`，且状态为启用：
   ```sql
   SELECT id, username, role_code, factory_id, is_active FROM users
    WHERE factory_id = '<编号>' AND role_code = 'factory_super_admin';
   ```
   再用电话或当面向工厂确认一次，⛔ 不能只凭一条微信。
3. **核对租户**：用平台账号调用 `GET /api/platform/factory-data/{factoryId}/preview`，回执里的 `factory.name` 必须与申请里写的工厂名称**逐字一致**。不一致就停手。
4. ⛔ **团队演示租户 F006、真实客户 LIUSHANMEN 不在可删除范围内**：删除接口对这两个编号直接拒绝（代码里写死），除非 Steve 专门书面指示，并且同时修改代码。

## §4 删除范围怎么算（外键闭包）

这是 2026-08-07 `V20261029_68`（清理 60 个测试租户）踩出来的经验：**扫描面必须是外键闭包，⛔ 不能只看带 `factory_id` 的表**。

1. **种子**：所有带租户列的表中，租户列等于该编号的行，加上 `factories` 里的那一行。
2. **扩散**：顺着单列外键，把「引用了种子行」的子行加进来，反复做直到不再增加（不动点）。目前最深 2 层：`line_schedules → worker_assignments`。
3. **跨租户命中 = 停手**：如果扩散到的行带有租户列、且值是**别的**工厂，或者是空值，说明有别的租户的数据引用了本厂的数据。删除会连带破坏对方，预演会把这些行逐条列出来，执行接口直接拒绝。
4. **置空类外键**（`ON DELETE SET NULL`，例如 `factories.parent_id`）不扩散：子行不属于本厂，只是引用会被清空。如果子行属于别的工厂，同样算跨租户命中。
5. **多列外键**：库里有 87 条，都带 `factory_id`，子行已经由种子覆盖。若出现子表不带租户列的多列外键，预演会标为「无法判定」并拒绝执行。

### 删除顺序

不手写拓扑顺序（维护一份手写顺序更容易漏）。在**同一个事务**里多轮删除：撞上外键约束的表留到下一轮再删，直到全部删完；最后删 `factories` 那一行。超过上限轮数仍有残留，就整体回滚，并列出残留的表。SmartBI 库同理，单独一个事务；附件最后删。

## §5 导出

1. 完成 §3 的核对。
2. 调用 `POST /api/platform/factory-data/{factoryId}/export`，得到 ZIP 文件（格式按 Q5）：
   - `manifest.json`：工厂编号、名称、导出时间、操作人，每张表的行数和文件 SHA256，附件清单；
   - `cretas/<表名>.csv`、`smartbi/<表名>.csv`；
   - `attachments/`：按 OSS 对象键存放的原文件（OSS 不可用时只给 URL 清单，manifest 里注明）。
3. **核对**：manifest 里每张表的行数与预演接口给出的行数逐表相等；解压后抽一张大表，用 Excel 打开一次，确认中文不乱码。
4. **交付**：通过加密压缩或当面拷贝交给申请人，⛔ 不发公开网盘链接。服务器上的临时文件在交付后删除。
5. 每次导出在 `factory_data_requests` 写一行（类型 EXPORT、行数合计、包的 SHA256），平台访问记录里也会留一条。

## §6 彻底删除

> ⛔ 真正删除的接口在 Q1–Q6 拍板之前不上线。

1. **申请与核对**：完成 §3。删除前**必须**先完成一次 §5 导出并交给工厂。这是工厂履行《食品安全法》记录保存义务（进货查验 / 出厂检验记录保存至保质期满后 6 个月，没有明确保质期的至少 2 年）的前提，平台不替工厂保管。回执里写明「已交付导出包 SHA256=…」。
2. **冷静期**（按 Q2）：登记删除申请，工厂当即停用、禁止登录；冷静期内可以撤销。
3. **预演**：`GET /api/platform/factory-data/{factoryId}/preview`，得到每个库每张表将删除的行数、跨租户命中、保留项。**跨租户命中不为 0 就停手**，先把那些行查清楚。
4. **给 Steve 看计数**：把预演回执原样发给 Steve，等他回复「可以删」。
5. **执行**：`POST /api/platform/factory-data/{factoryId}/erase`，请求体必须带：
   - `confirmFactoryId`：再输一遍工厂编号，必须与路径一致；
   - `previewId`：第 3 步预演的编号。执行时重新算一遍，若与预演计数不一致（期间有人写入），拒绝执行，回到第 3 步。
6. **阴性对照**（接口在事务内自动做，不通过就整体回滚）：
   - 本厂：每张表按同一口径重新计数，必须全部为 0；
   - 其他工厂：执行前后按工厂分组的行数逐厂相等，一行都不能少。
7. **文件**：按 `<编号>/` 前缀删除 OSS 对象，删后再列一次前缀，结果必须为空。
8. **回执**：§9。

| 保留项 | 内容 | 期限 | 依据 |
|---|---|---|---|
| 删除回执 `factory_data_requests` | 工厂编号、名称、申请人、操作人、每张表删除的行数、时间 | 长期 | 证明承诺已兑现 |
| 审计 / 留痕 | 按 Q3 | 按 Q3 | 《网络安全法》第 21 条 |
| 每日备份 | 整库 | 本机 7 天，异地 30 天 | 按保留期自然过期（§8） |

## §8 备份里的数据

1. **每日备份**（`backup-db.sh`，每天 3:00）：本机保留 7 天，异地 OSS 保留 30 天。删除生效后，这些备份里仍然有该厂数据，**最长 30 天后随备份过期自然消失**。回执写明最后一份含有该厂数据的备份会在哪一天过期。⛔ 不为删一个工厂去改写整库备份文件。
   - 若在过期前需要用备份恢复整库，恢复完必须立即对该厂重做一次删除（回执里登记过的工厂都要重做）。
   - ⚠️ 2026-10-24 起异地上传因阿里云账号停用而失败（`uploaded=0 failed=2`），异地桶里的旧备份也删不掉。这件事由数据安全主线跟进；恢复之前，异地那份「30 天过期」无法执行。
2. **没有过期机制的副本**（§1 最后一行）：按 Q6 处理。⚠️ 在 Q6 落地之前，「备份按保留期自然过期」这句话**对它们不成立**，不能写进给客户的回执。

## §10 禁止事项

- ⛔ 不对 F006（团队演示租户）、LIUSHANMEN（真实客户）或任何还在使用的真实工厂做删除演练。演练只在专门新建的一次性测试工厂上做：先造数据，预演计数，删除，再计数确认为 0，同时确认其他工厂行数不变。
- ⛔ 不在 psql 里手写 `DELETE` 代替执行接口；接口里的跨租户检查和阴性对照是唯一保证删对地方的东西。
- ⛔ 不在预演回执给 Steve 看过之前执行删除。
- ⛔ 导出包不发公开链接、不留在服务器上。
