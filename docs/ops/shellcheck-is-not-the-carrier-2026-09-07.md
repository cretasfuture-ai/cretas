## 一、原始观察仍然成立：**豁免在，检查器不在**

```
.github/ 下跑 shellcheck 的 workflow:  **0 个**
scripts/ 下的 `# shellcheck disable=`: **11 处 / 7 个文件**
```

有人一路写 `disable=` 去绕过一个**从来没运行过**的东西。
⇒ 与今晚那批同族，但形态是新的：不是「闸瞎了」，是**闸从来不存在，而现场看起来像它存在** ——
`disable=` 指令是「它存在过」的最强证据，而那个证据是假的。

### 那 11 处逐条判过了：**全部承重，⛔ 没有一条是假豁免**

⚠️ **判法很关键**：把 `# shellcheck disable=` 行**剥掉再跑**。
⛔ 不能看原样的命中数 —— shellcheck 会 honor 指令，那个数是**抑制之后**的，**天然为 0**。
（这是「一个恒 0 的读数」在另一个位置的实例。）

```
剥掉指令后:  SC1090×6  SC1091×5  SC2207×1  SC2087×1
阳性对照:    同一跑里还报了 SC2164  ⇒ 这一跑确实在工作(⛔ 否则 0 可能又是「没量到」)
```

全是「动态 `source` 跟不进去」「heredoc 故意展开本地变量」这类真豁免。
📌 **且没有一条是 SC2312** ⇒ 接它**不会继承任何既有豁免**。

## 二、🔴 但 shellcheck **不是**硬约束 1 的载体 —— 这是本票的结论

我们一度打算接 SC2312（`check-extra-masked-returns`），依据是它的**描述**：

> `Consider invoking this command separately to avoid masking its return value`

⇒ 措辞与硬约束 1 完全吻合。**⚠️ 而我们从没拿真实事故去喂它。**

### 实测：把本仓四次真实事故的形状**原样**喂给 `shellcheck -o all`

```
① applied=$(psql -tAc "…")            set -e 下当场中止, 三态检查走不到
② found=$(grep … | sed …) || echo     退出码恒 0, || 是死代码
③ rc=$(cmd | head -1)                 用 | head 之后读退出码
④ last=$(cmd | tail -1)               同上

报告: SC2249 / SC2250 / SC2292  ——  **全是风格建议**
⇒ **命中 0/4。SC2312 一次都没开火。**
```

### 那 786 条是**另一个族群**

```
SC2312 全仓命中: **786 条 / 134 文件**
其中 38% 直接落在 `echo "$(...)"` / `printf` / `log` 行上   ← 按行文本数的, 是**下界**
实例: print_success "Node.js 版本: $(node --version)"
      echo "… ($(wc -l < "$F") lines)"
```

⇒ 打个版本号、打个行数，**基本无害**。

🔴 **接了它会得到**：`786 条债务 + 一条真事故都拦不住 + 从此认为硬约束 1 有闸了`。
⚠️ 而 786 这个大数字会让它**看起来覆盖得很彻底** ——
▎**「一道只覆盖一半的闸给出全覆盖的安心」的极限情形：覆盖是 0。**

### 📌 由此立的规矩

> **给一条规矩选载体时，先拿这条规矩真栽过的实例去测那个载体 —— 测完再采用，⛔ 不是采用后再验。**

这就是「阳性对照」用在**选工具**上。
▎**判据的描述与判据的行为，是两件要分别验证的事。**

## 三、⇒ 硬约束 1 的实际覆盖：**② 部分有，① 没有**

硬约束 1 原文是两件事：

| | 内容 | 载体 |
|---|---|---|
| ① | 管道会**截断**你要看的那一段 | 🔴 **没有，且大概率造不出来** |
| ② | `cmd \| tail` 的**退出码**是 tail 的 | ✅ 部分：`test-pipeline-tail-swallows-rc.sh` |

**② 的载体**（自写，⛔ 不是 shellcheck）：盯 `x=$( … | head|tail|sed|awk|grep -c … )`，
**只拦新增行**（存量 219 处只报数不断言），验收判据**就是上面那四个形状**：

```
READING: PIPE_RC_ACCEPTANCE caught=[6 7 8] expect=[6 7 8] blind=[5:形态①] coverage=3/4
```

⚠️ **形态 ① 抓不到**（`x=$(cmd)` 不带管道，与正常命令替换文本上同形）—— 已在闸的文件头明写。

**① 没有载体**：`| head` 在绝大多数场合是正当的，机械区分「诊断用途」与「浏览用途」做不到。
⇒ 唯一可执行的纪律：

> **凡是要据以下结论的输出，⛔ 一律不截断。**
> ⛔ 不是「小心使用 head」，是**在做判断的那一刻不准有 head**。

📌 这条能被执行，是因为它**不要求现场判断「这次算不算诊断用途」**。
▎**一条不需要现场判断的纪律，才是能被执行的纪律。**

⚠️ 2026-09-07 一晚，① 栽了 5 次（organizer ×2 · Line B ×1 · Line C ×2）。

### ⛔ 所以：**不许把「接了 ② 的闸」读成「硬约束 1 已有闸」**

闸自己会打这条读数：

```
READING: PIPE_RC_HARD_CONSTRAINT_1_COVERAGE=partial ⇒ ⛔ 不许读成「硬约束 1 已有闸」
```

## 四、📌 顺带一条反直觉的读数：`fetch-depth: 0` 只贵 **2 秒**

为了让 ② 那道闸能比 `merge-base...HEAD`，`ops-script-tests.yml` 的 checkout 加了 `fetch-depth: 0`。
⚠️ 这里比的是**改变了的那一步**，⛔ 不是 job 总时长：

```
                        checkout    Run scripts/tests/*.sh    job 总
shallow (main)              23s            140s              170s
fetch-depth: 0 (#743)       25s            146s              176s
                           ────
                           **+2s**         ↑ 这 6s 是**新闸自己的运行时间**, 与 depth 无关
```

⇒ **1.7 GB 的仓在 ubuntu-latest 冷 clone，全历史只多 2 秒。**
📌 下次有人凭「仓库很大所以全历史很贵」拒绝，**直接引这条读数**。
⚠️ ⛔ 别拿自建 runner 那次外推（那边工作区常驻，几乎免费）—— 两个场景不可比，只是结论同向。
