# 工厂操作日志与故障定位

## 库存变更

系统操作日志中，模块选择「库存变更」，可按记录类型、记录 ID、操作人、时间筛选。记录包含审计字段的变更前值、变更后值、逐字段差异；界面保留服务器返回的时间小数精度。

覆盖主业务数据库经 Hibernate 写入的原料批次、成品批次、调拨单及明细、领料单及明细。自有原料与客户供料使用同一审计入口，保留归属和货主客户 ID，不改变库存归属规则和仓储流程。

- 批次：入库、使用/发货、预留、可用、账面实物数量、单位、仓库、状态、归属、来源单据。
- 调拨：源/目标工厂和仓库、状态、处理时间、明细数量、实收数量、源/目标批次、包装换算字段。
- 领料：计划、仓库、状态、处理人/时间、关联调拨单；明细的需求、领用、发料、消耗、损耗、退料数量。

数量以库存基本单位及数据库保存精度为准：原料批次数量最多 6 位小数，成品批次数量最多 4 位小数，不显示数据库无法保存的额外精度。账面实物数量＝入库量−已用/已发量；可用数量再减预留量，均是系统账面值，不替代实际盘点。

审计记录使用业务事务的同一连接写入 `operation_logs`。业务回滚会同时撤销审计；关键库存审计写入失败时，业务事务也必须回滚。`inventory_audit_failed` 表示需要处理审计存储故障，不能通过关闭审计继续写库存。一次业务操作可能产生多条批次、单据记录，以摘要中的 `correlation` 关联请求日志。

审计工厂取自实体/所属单据，操作者取自认证后的请求属性。跨工厂调拨分别归属双方，同工厂只记一次；其他工厂不能通过现有日志查询接口访问这些记录。无请求的后台操作标记 `origin=system`，不能确认身份的请求标记 `unattributed_request`，不伪造用户。

超出已有日志 ID 列 100 字符限制的库存 ID，在列表使用 `sha256:` 索引，完整 ID 保存在快照 `recordId`；查询时仍可直接输入完整 ID，由接口转换索引。一般 UUID 不受影响。日志只保存明确列出的业务字段，不保存价格、密码、表单全文或实体关联对象；快照不是完整实体备份。

## 页面故障

Web 管理端为共享 API 请求生成 `X-Correlation-ID`。客户端错误接收入口为 `POST /api/mobile/{factoryId}/client-errors`，仅接受认证后匹配的工厂身份。事件写入应用 `client_error` 日志，标明来自浏览器的报告，不能作为已发生业务变更的证据。

捕获范围为 Vue 异常、浏览器未处理异常/Promise 拒绝及共享请求客户端失败。只上报允许的技术字段：故障类别、路径、方法、状态码、受限错误码、请求关联 ID、脚本文件名与行列位置。诊断正文不包含异常原文、完整堆栈、URL 查询参数、表单、原请求正文或认证信息；接收接口本身仍使用正常登录认证。

接收正文上限 8 KB；后端按工厂/用户限流，浏览器去重并限制频率，上报超时后不重试、不创建离线积压队列。日志接收故障不阻塞原页面操作。客户端断网、关页、限流或未登录时，部分事件无法到达服务器，因此客户端错误记录不承诺零丢失。

## 已知边界与核验

- 普通业务请求审计仍使用既有异步队列，失败/队列满时留应用错误日志；只有本批六类库存事实采用同事务持久化。
- 原生 SQL、批量 JPQL、外部数据库写入不触发 Hibernate 实体事件；不能把这些路径宣称为已覆盖。
- 不录制全部点击或未提交表单；本批不包含手机 App、独立 calibration Axios 或 Python 直连 fetch 的完整请求上报。
- 无法补回上线前缺失的日志；毫秒格式也不表示所有设备时钟已达到毫秒同步。
- 启动应出现 `inventory_audit_ready`。Java 门禁 `InventoryAuditTransactionContractTest` 使用真实主持久化配置验证提交、回滚、存储失败、归属、明细与软删；同一测试在 PR 的 PostgreSQL job 显式执行。客户端使用 `ClientError*Test` 和 `clientErrorReporter.spec.ts` 验证。

生产验收以发布回执和后续真实操作的只读回查为准；不能通过伪造生产库存变动验证日志。
