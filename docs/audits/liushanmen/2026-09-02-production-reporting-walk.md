## 缺陷 31 —— 开工前不做料齐检查，缺料要走到那一道才知道

**长相**：owner 顺利报完 ①原料拆箱 ②出料/缓化 ③破碎 ④绞肉，
在 **⑤搅拌** 填完 92kg、点「正式报工」时才被拦：

```
生产库投料不足，本行只能保存草稿
  冰水（调料）  缺 3.54292 kg   需 3.54292 kg，可用 0 kg
  去哪补：联系仓管补料
```

**为什么这是缺陷**：BOM 在**建计划那一刻就固定**了
（`production_plans.selected_bom_recipe_id` 非空、`selected_bom_version` 已钉死）。
按计划量把 BOM 全展开算一次短缺，是**开工前**就能做的纯计算。
现在的做法是**每道工序各自撞一次墙**。

🔴 **代价不是「多点一次」，是排队踩雷**。同一张 BOM 上还埋着第二个：

| 拦在哪 | 缺什么 | 需要量 | 全厂在手 |
|---|---|---|---|
| ⑤ 搅拌 | 冰水（辅料 `RMT_1786268298741`） | 38.51 g/kg × 92kg = **3.54292 kg** | **0** |
| ⑩ 装箱 | L1纸箱（包材 `RMT_1782891392801`） | 0.0694 个/kg × ~89kg ≈ **6.2 个** | **0** |

⇒ 不查库的话，owner 会**做完 9 道工序之后**在最后一道被拦。

**⑩ 一定会拦，已核到源码**（`ProcessSheetServiceImpl.buildAutomaticBomRequirements` :512-560）：

```java
if (producesFinishedGoods) {
  for (BomRecipeItem item : bomRecipeItemRepository.findByRecipeIdOrderBySortOrderAsc(...)) {
      if (!"PACKAGING".equalsIgnoreCase(item.getMaterialCategory())
              || Boolean.TRUE.equals(item.getIsOptional())) { continue; }
      ...requirements.add(...);
  }
}
```

遍历 BOM 里**全部** PACKAGING 项，**不看** `workflow_material_node_id` 绑定
（L1纸箱那一行该字段是 NULL，照样要），唯一豁免是 `is_optional=true` ——
而它是 `f`。

**建议修法**：建计划 / 开工前跑一次全 BOM 展开，一次性列出全部短缺清单。
⛔ 不是把现在的提示做得更好看 —— 提示已经很好（见下），问题是**时机**。

**✅ 值得保留的**：这条错误提示本身**质量很高** —— 缺什么、缺多少、
「需 X 可用 Y」、去哪补，四样都给了，还有「查看系统原始信息」折叠层。
⛔ 改这条时不要把这些信息弄丢。

## 缺陷 32 —— 混批投入的展开面板渲染在「产出明细 / 确认提交」**下面**

**长相**（④绞肉那一屏，展开「破碎来源(混批)」之后，自上而下的真实顺序）：

```
①  投入行「破碎来源(混批) ∨ 1批·92.0kg」   投入(kg) 92.00
③  产出明细 — 1 项
④  确认提交   [保存草稿] [正式报工]
①  投入来源 — 1 项            ← 🔴 展开出来的内容在这里
      美式/破碎料 | 投入数量 92.00 | 来源批次 CLK-W-20260902-90557 | 余92kg
```

**判据是机械的，不是审美**：**编号 ① 的内容被渲染在编号 ④ 之后。**
用户点的是第一步的展开箭头，内容出现在提交按钮下方，
中间隔着整个产出明细区 —— 视觉上与触发点完全断开。

**它造成的实际卡点**：owner 在投入行填了 92，
「正式报工」**不可点，且界面一个字都不说为什么**。
真正缺的是那个跑到页面最底下的分配面板里再填一次 92。
折叠态还显示 `1批 · 0.0kg` —— 一个已经填了总量的行显示 0.0kg，
把「没分配到批次」看成了显示瑕疵。

⚠️ 这两点叠加 = **按钮静默不可点 + 折叠态给出误导读数**。
最初我判断 `0.0kg` 大概是显示问题，**是错的**：它就是真的 0。

**owner 要的形态**：展开内容**紧跟在「破碎来源(混批)」那一行下方**，
一行一张卡片直接填投入数量；或者干脆像「原料拆箱」那样点一下就选批次。

## 待观察 —— 副产/不良品在报工里没有独立表达

⑤搅拌 那屏「∨副产」展开后只有两个框：**副产数量(kg)** + **副产回收单价**。

- ❌ 没有类型区分（副产 / 不良品 / 损耗 分不开）
- ❌ 副产品本身不能选，只有一个数量 + 单价

⚠️ 而 owner 定的模型里「副产」与「不良品」是**并列两类**
（⑥肉饼成型出边角料 = 副产；⑧金检挑出的 = 不良品，要走 rework-out）。
现在只能都记成副产。

📌 **还没定性** —— 出成率会不会因副产变化，等 ⑥ 实填之后才知道。
⛔ 别在这条上派活，先等读数。
