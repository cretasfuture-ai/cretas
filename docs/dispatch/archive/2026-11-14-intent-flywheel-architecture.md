# 意图飞轮与本地决策模型方案（INTENT-DISTILL-20261111 · 2026-11-14）

Owner：Steve 定方向；organizer（意图蒸馏批次）拆线执行。本文是后续开线的依据，状态以 2026-11-14 为准。

## 1. 目标

1. 线上每一轮 AI 对话都被回收：用户原话、上下文、决策模型的输出、执行结果、用户之后的反应。
2. 用这些数据把线上决策模型（Luna，openai/gpt-6-luna Decisions 接口）的能力蒸馏到本地模型，再用用户反应做强化学习，最终本地模型做主决策，效果不低于 Luna，成本更低，更懂各工厂的习惯。
3. 意图目录会持续扩充和拆细（现 235 个工厂意图不够），由飞轮发现缺口、AI 自动补，人做批量复核。

流量少不是阻塞：先把基建和闭环搭好，有流量就自动转起来。

## 2. 决策架构（分层）

| 层 | 做什么 | 谁来做 |
|---|---|---|
| 0 | 整句一字不差命中短语表 | 查表（已有，`ai_intent_phrase_registry` + 两入口短语快捷通道） |
| 1 | 理解这句话：业务域（生产/仓储/质检/销售/采购/财务/人事…）、动作类型（查/建/改/删）、抽实体（客户、产品、数量、日期） | 决策模型输出；实体到本厂主数据精确匹配，⛔ 不靠语义猜 |
| 2 | 在该业务域的候选意图里定具体意图，以及 直接办 / 先展示再确认 / 先问 | 决策模型（同一模型多输出一个维度，或分两步，按读数定） |
| 3 | 参数：同名实体全部列出让人选（规则 8），能默认的写明默认 | 规则 + 主数据 |
| 4 | 把关：权限、写操作确认卡 + 一次性令牌 | 规则（已有） |

- 候选意图按业务域从意图目录确定性取出，意图涨到上千个也不用语义相似度筛候选（语义召回只能做兜底，不做决定）。
- 生成回复调哪个模型与本方案无关；关键是第 1、2 层的输出和用户反应进飞轮。
- 逐步替换成本地模型的是第 1、2 层。

## 3. 飞轮记录（基建）

每轮一条记录（新表 `ai_intent_flywheel_turns`，Java 单点写，Python 把决策轨迹带回）：

- 工厂、用户、会话、入口（普通 / 流式）、原话、上下文摘要
- 决策来源与跳数（短语表 / Luna / 阿里云 / qwen / 本地 / 规则 / 按钮）、业务域、意图、动作、置信度、候选
- 最终状态（成功 / 澄清 / 写确认 / 拒绝 …）、耗时、意图目录版本
- 用户反应（回填到上一条）：追问后直接答 / 改说法 / 放弃；默认展示后接受 / 改条件；写确认确认 / 跳过；选项选第几项。判不了记 UNKNOWN，⛔ 不把不知道写成 0
- 写失败不影响用户请求，但有计数可观测

保密（按工厂开关，⛔ 不整厂排除）：

| 内容 | 保密厂默认 | 备注 |
|---|---|---|
| 客户名（含「老张家」这类称呼） | 脱成「客户A」 | 同会话同客户编号一致 |
| 产品名、数量/重量 | 不脱 | 工厂可单独打开 |
| 价格数字、配方、工艺参数 | 脱 | |
| 普通说法（特价、加急、老样子） | 不脱 | 是说法不是秘密 |

识别靠本厂主数据精确匹配；保密厂原文只加密存（密钥走环境变量，没配密钥就不存原文），训练导出只出脱敏版。例：「给老张家下五十斤卤鸭腿，按特价走」→「给客户A下五十斤卤鸭腿，按特价走」。

导出：按时间/工厂导出蒸馏用 JSONL（输入 → 决策 → 反应）。

## 4. 三个闭环

### 4.1 说法闭环
新说法对到已有意图上：高频、确定的进短语表；其余进训练数据。现有短语表 377 条（批准 277、待审 90、驳回 10，10-02 后无新增）要接到飞轮上恢复流动。

### 4.2 意图闭环（Steve 11-14 定：全自动 + 批量复核）
1. 飞轮出「意图缺口」清单：没匹配上或掉进闲聊的话、低置信、同一对意图反复澄清、用户常选非第一候选、追问后改说法或放弃；相近说法聚类。
2. AI 判定：缺口确实存在、有把握、符合规则 ⇒ **直接自动加，查询和写操作都一样**；完全没把握或不符合规则的才逐条转人工（管理员 / 开发 / 产品）。
3. 每 2-3 天或每周，用 Claude Code / Codex 对这一批自动加的意图做批量复核。
4. 加完观察 1-2 周（接受率、改说法和放弃率、与相近意图是否抢、执行报错）；有问题算新缺口，再交 AI 判断修改或转人工。

不需要人的保护：
- 自动加的意图只挂在现有 Tool/Skill 上；需要新写代码的能力不在此范围，走开发 PR。
- 权限随底层能力，不借新意图放宽；写操作运行时仍逐笔出确认卡。
- 放量 影子 → 单厂 → 全量，指标变差自动回滚。
- 意图目录有版本，旧记录重新对应到新意图可回退；每次自动加留痕。

### 4.3 决策模型闭环
三层 + 训练方法：
1. 短语表（已有）。
2. 本地模型微调（主力）：先蒸馏（Luna 决策当老师答案），再强化学习（用户反应当奖励）。只用飞轮里的历史记录离线训练，不拿真实用户做试验。
3. 相似案例检索：两次训练之间的新说法，从过去判对的记录里找相近几条给本地模型参考（向量索引），只做参考不做决定。

奖励设计（要平衡，否则学成什么都问）：

| 结果 | 奖励 |
|---|---|
| 直接办，用户接受 | 最高 |
| 先展示，用户接受 | 高 |
| 先问，一次答完 | 中（追问本身有成本） |
| 用户改条件 | 小扣分 |
| 判错直接办 / 用户放弃 | 大扣分 |

切换步骤（每一步靠读数）：
1. 影子对比：本地模型与 Luna 同判一句，只记录不影响用户，比一致率和用户反应。
2. 分流：某一类达标（门槛 98%）的先交本地模型，低置信和未达标的仍走 Luna；写操作照旧确认。
3. 以本地为主，Luna 抽查和兜底；线上退步一键切回。

### 4.4 自动优化器（Steve 11-14：先有基础准确率，之后靠闭环自动提升）
飞轮只攒数据不会自己变好，要有一个定时调模型来优化的步骤：
1. 定时（先每天一次）从飞轮取最近的记录，算各项读数：意图判错、该问没问、不该问却问、用户改说法 / 放弃、写确认跳过，按工厂、业务域、意图分组。
2. 调强模型（Claude / OpenAI / Codex）分析主要错误类型，产出可执行的改动：补短语、加或拆意图（按 4.2）、调先问门槛、改决策提示词、生成训练样本、触发一轮本地模型微调或强化学习。
3. 每个改动先在冻结验收集（史浩禾校准集 + 验收集 v2 + 飞轮里用户反应明确的记录）上跑改前改后对照，再影子跑；比现状好才自动上线，变差自动放弃或回滚。
4. 每次优化留记录（改了什么、依据哪些读数、上线前后读数），纳入 4.2 的批量复核。
5. 花费有上限（按月预算），超了只出报告不自动改。

## 5. 金标与校准
