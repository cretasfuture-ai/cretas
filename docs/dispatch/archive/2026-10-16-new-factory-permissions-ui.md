# New-factory employee, organization and data-scope acceptance

Task `NEW-FACTORY-PERMISSIONS-20261016`, Owner root, base `f7d03883ca09fe8e72a8d1b64cfada5ef6f57415`. This is an increment in the main Cretas repository, using the existing isolated nonproduction environment and synthetic factory. No production access, deployment, factory initialization or existing-factory configuration writes.

## Delivered behavior

- The employee editor preserves main's free-text department and complete role catalogue, reads back the raw department/manager, preserves omitted organization fields and supports explicit clearing. Manager validation is same-factory, active, undeleted, acyclic and bounded to ten levels. A factory advisory lock is acquired before loading the edited user; validation includes the existing descendant subtree.
- The role page persists factory-local ALL, SELF, SELF_AND_BELOW and DEPT_AND_BELOW policies with optimistic versions. Only the current factory administrator can write them. CUSTOM and locked administrator scopes are rejected. Existing role defaults remain when no factory override exists. Missing/broken policy storage denies access rather than broadening it.
- Function permissions remain separate. The local role/module matrix can configure a new factory even when global L1 is empty, using the server's real factory roles. It excludes platform/unknown roles and discards stale cross-factory responses. No global permission defaults were initialized or written.
- JWT authentication produces explicit platform/factory actor namespaces. Equal numeric IDs never let a platform account borrow a factory user's policy or function permissions. Factory tokens with a platform-looking role still undergo factory/user checks.
- Scoped business lists and record/parent checks cover the connected customer, sales/purchase, material-batch and return paths. Unadapted shortcuts, bulk operations and aggregates reject restricted accounts. Linked receiving/shipping follows the source order; standalone delivery follows its customer. Internal business calls retain their existing authorization paths.
- Real UI found that customer-detail sales and return queries bypassed the scoped lists. Both now apply factory, customer and creator-chain predicates before database pagination/count; sales returns additionally require SALES_RETURN. Real JPA tests exercise the new derived queries.
- Quote, invoice and payment customer shortcuts do not yet support equivalent creator/source-order filtering. They now reject restricted scopes before the handler; their tabs display a local access restriction instead of an empty-success result or repeated global notices. ALL behavior is preserved. The quote shortcut also requires sales read permission. Customer child tabs mount only after the parent customer was successfully loaded.

## Limits

This is a real Web UI acceptance of new-factory account/organization/configuration and representative customer data-scope enforcement, supported by targeted backend tests for the connected business paths. It does not certify every business module or native-device UI. DEPT_AND_BELOW currently means the same department; a department hierarchy is not implemented. CUSTOM is unsupported. Restricted quote/invoice/payment customer shortcuts and other unadapted aggregate/bulk paths remain explicitly unavailable; their full scoped business implementations are not claimed. Existing main's unrelated feature-default initialization endpoint was not used and is not accepted by this slice. No production deployment or migration was performed.
