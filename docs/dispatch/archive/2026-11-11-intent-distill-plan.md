## 分阶段

### P0 评测可信（先做，零模型花费）
- 评测脚本 `tests/semantic-read` 单独进仓。
- 计分拆成五项：目标、对话动作、澄清判定、参数、真实结果。
- 每个版本跑 3 次，报均值和最小最大值；单次成绩不再作为结论。
- 用已有三轮 trace 重算分项成绩；列出有歧义的标准答案交 Steve 审。
- 开发集从 24 段扩到 100 段以上；另建独立验收集（见待拍板 1）。

### P1 把 PR 1476 拆成小 PR 上线
1. 普通入口与 SSE 用同一份上下文进入识别（Web 多轮续句因此变好）。
2. 参数来源优先级（本轮明确值 > 已确认值 > 默认值）与分页绑定。
3. 统一澄清候选与候选预算修复（特殊选项不挤掉业务候选）。
原 PR 1476 拆完后关闭。

### P2 压调用与澄清判定
- 请求目的、候选粗选、参数理解三次 mini 调用合成一次结构化输出。
- 「是否需要澄清」单独用 Luna Predicate 判定并校准阈值，单独计分。
- Luna Choice 只在需要时调用。

### P3 蒸馏数据
- 样本形态：当前句 + 结构化任务状态摘要（上轮目标、已确认参数、待答字段）。
- 标签：对话动作（新任务、改参数、翻页、取消、需澄清）+ 266 类目标 + Luna Choice 概率分布（软标签）。
- 两位老师独立标注（Luna；Terra 或 Claude）。一致的进训练集，不一致的进人工审核队列。
- 按语义族切分；35 / 796 / 1637 / 已打开的多轮对话及其近邻全部排除。
- 代码缺陷造成的失败（上下文丢失、参数合并）不进训练集。

### P4 学生模型
- 输入加上下文；输出加对话动作头和需澄清头；损失用软标签 KL + 硬标签交叉熵。
- 在独立校准集上定阈值，按「覆盖率 × 覆盖内准确率」验收，不看单一准确率。
- 不替换线上模型，权重先留本地。

### P5 本地直出接线（红线）
- 只在只读 Tool 的意图之间直出。
- 写意图的概率质量超过校准下限就升级。
- 对话动作为「需澄清」或置信不足就升级。
- 按工厂开关，默认关；先影子运行（本地只记录不生效，和老师逐条对比）。
- 独立终审后才合并。

### P6 影子运行、飞轮与发布
- F006 影子运行达标后打开开关。
- 本地与老师的分歧样本进审核队列，审过再进训练集。
- 合并与发布由 organizer 统一做。
