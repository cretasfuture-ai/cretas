# 新建销售订单明确选择包装规格

Task `NEW-FACTORY-BASICS-20261017` 的共享业务修复，独立于平台建厂交付提示；Base `74685b5c2b0c5fcbdd9745a6265e453ae2085c58`。仅使用现有 Windows 原生隔离环境和模拟新厂，不访问或部署生产。

## 问题与修复

基础资料 UI 为同一成品保存两种箱规（1箱=10个、1箱=60个）后，新建销售订单页只有单位选择。销售产品轻量列表不含完整箱规，该页未读取正式包装规格；即使取得多条规格，旧逻辑也只会采用默认规格，操作员无法明确选择第二条。

本修复在添加产品时读取其同工厂正式包装规格；读取失败明确提示且不添加产品。存在多条同单位有效规格时，页面展示名称、换算数和基本单位供明确选择；未选择、失效或单位不匹配均拒绝保存。更换单位清除旧选择。提交保留实际所选规格 ID，单规格和基本单位行为保持兼容。未改后端、价格计算、库存、权限、Entity/Repository 或迁移。

## 真实 UI 及独立读回

- SKU 编辑保存并刷新：原味面包仍为160g/个，两条正式包装规格换算分别10和60。
- 新建销售订单真实选择“箱”，列表同时展示“默认箱规 · 1箱=10个”和“箱规2 · 1箱=60个”。切换基本单位再切回箱后选择被清除；未选箱规点击保存得到明确中文提示，销售订单 POST 为0。
- 明确选第二条并保存：创建1张 DRAFT，1箱，成品仓。正式订单行包装快照为箱规2、factor=60、baseUnit=个，所选 ID 对应正式60个规格。不是只验证HTTP成功或规格文字。
- 浏览器对包装读取注入503：产品行数0且显示“包装规格加载失败，未添加产品，请重试”；撤销注入后同一真实入口恢复添加。该503为阴性测试，不是产品或服务器故障。
- 独立数据库断言：原5张订单、库存批次、8张生产计划、BOM和Workflow不变；仅多1张测试草稿。其他工厂相关15表指纹一致。没有确认订单、审批、预留、发货或扣库存。
