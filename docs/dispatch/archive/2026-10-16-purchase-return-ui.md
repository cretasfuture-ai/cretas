## 发现及修复

采购异常的包装数量曾直接交给按库存基本单位扣减的通用退货服务，且退货金额使用未税包装价。本次只在采购异常生成退货的边界换算：同厂源采购单唯一物料行的不可变包装快照 → 基本单位数量；源未税价格 × 计价换算因子 ÷ 包装因子 × 含税系数 → 基本单位含税价。

缺少/歧义来源、不可确定的基本单位或换算、库存两位小数无法精确表达的数量，均在创建前拒绝。历史行没有基本单位快照时，只接受同厂物料主数据，禁止按 `kg/g` 等字面猜测。备用单位换算明确传入实际数量。

采购退货页面现在持续展示服务端 `completionHint`，明确“已退库、应付冲减待审批”，避免把完成出货误认为余额已冲减。未修改通用退货 FEFO、应付审批、权限、Entity/Repository、迁移或生产配置。

| 财务审批 | 包材单通过实际页面财审；面粉单通过已授权工厂总监实际会话接口财审，非UI步骤。两单FINANCE_APPROVED时库存及应付仍不变 |

| 重复完成 | 已完成单再次请求完成返回409；库存、库存审计、应付流水、余额与退货状态完全不变 |
| 来源单据 | 两条异常RESOLVED/RETURN_OVER并关联退货；源采购单及原收货明细保持退货前事实，未倒写或清除 |

工厂总监在现有后端规则中拥有全部模块权限，其实际会话财审返回200属于授权操作，不能作为“无财务权限403”证据。本次没有新增或声称完成受限财务角色的完整权限矩阵。

应付冲减属于余额调整，不代表源采购发票已付款或实际银行退款。原采购入账流水保留，不伪造付款/结清。
