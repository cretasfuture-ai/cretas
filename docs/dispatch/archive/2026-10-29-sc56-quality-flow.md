# SC56 质检状态修复边界

## UX Flow Analysis

### 用户画像

F006 现场质检员，使用原生手机 App 选择批次并填写实测值；依赖明确的
待检、合格和不合格提示决定下一步，不能将系统任务当成检验结论。

### 用户旅程

| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|---|---|---|---|
| 1 | 待检批次的品名、批次号、数量 | 选择目标批次 | 进入该批动态标准，分页数量真实 |
| 2 | 必检项、单位、标准版本、允许范围 | 填写实测值 | 缺项明确提示并保留草稿，不生成结论 |
| 3 | 当前批次与实测值 | 提交一次 | 完成对应任务，保存真实检验员和标准快照 |
| 4 | 已保存的检验详情 | 返回记录 | 真实合格/不合格结论可回读，待检不伪造等级 |
| 5 | 合格、失败或待处理状态 | 正常复检或处理异常 | 保留已判定历史，失败继续隔离而非静默放行 |

### 摩擦点清单

| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|---|---|---|
| F1 | 空必检项可能被误认已检 | HIGH | fool-proof Rule 1 / 错误恢复 |
| F2 | PENDING 显示 D、不合格和 0% | HIGH | fool-proof Rule 2 / 信息密度 |
| F3 | 已检批次继续进入待检、分页数量不实 | HIGH | fool-proof Rule 4 / 批次选择 |
| F4 | 记录合格/失败与生产、库存状态不一致 | HIGH | 业务一致性与事务门禁 |
| F5 | 网络或提交失败后无下一步或丢草稿 | MED | fool-proof Rule 5 / 错误恢复 |

### 每个摩擦点的设计回应

- F1 → 保留现有必检校验；真机留空已实际拦截，不添加自动填值。
- F2 → 待检明确显示待检验；未知显示未知，均不生成等级、通过率或失败结论。
- F3 → 按数据库中有效待检任务分页；终态与重复任务不能挤占第一页或虚增总数。
- F4 → 正常完成任务与批次传播、失败告警和隔离处于同一事务，已判定历史不可覆盖。
- F5 → 保留现有草稿与重试入口；原生断网已观察明确错误，恢复网络后可显式重试。

本切片为真实状态修复，沿用既有大按钮、间距、标准表单和安全区；不扩展
报工/入库/拍检等无关页面，不为减少点击而跳过批次与标准确认。真实设备
再次验收须覆盖记录页、待检消失、结果回读和失败隔离，不能仅以样式或编译通过。
Rule 3 保持现有动态标准类型与约束选择，不新增自由文本判定结论；实测值
仍由检验员填写，结果由标准计算。已判定历史不可被提交按钮覆盖。
