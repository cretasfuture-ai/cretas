# 工厂独立视觉训练 SOP v1

本 SOP 复用现有 VisionLab 的采集、数据集、候选训练、评测、导出一致性和发布门禁。通用的是流程和证据契约，每个工厂、工位、产品与包装范围都需单独建立数据与验收。六膳门权重、类别、托盘几何与阈值不作为其他工厂的默认值。

## 日常质量管理入口与接入契约

Web 长期入口是 `质量管理 → 视觉质检训练`，路径 `/quality/vision-training`。工厂管理员和质量负责人从当前登录工厂进入，不通过 URL 参数选厂，也不依赖平台建厂开关。对话建厂负责平台初始化；训练任务、执行记录和独立验收是本厂日常功能，平台建厂页不挂载此组件。

工厂日常页面分为三步：选择“包装是否缺件/包装文字是否正确”等检查内容 → 填写生产线或检查位置、产品、包装 → 核对真实服务端预览并明确保存。系统产生本次设置引用，工厂人员不必手填版本号；引用不表示照片、人工标准或独立试用资料已准备完成。新增任务不自动猜选执行方案，即使本厂只登记了一项也须明确关联。已有项目保留原始规格和执行记录。

保存后先进入四步照片准备：准备照片 → 逐张审核 → 确认合格要求 → 提交训练。后台阶段和执行记录折叠到“查看后台处理进度与执行记录”，原始编号、版本、执行设置、回执和英文原因折叠到“系统记录（维护人员）”。缺资料、登记输入或适用执行设置时仍阻塞，准备清单不等于完成回执。页面简化不改变各厂独立训练、独立验收及单独启用要求。

### 照片准备与冻结提交

工厂人员从本机选择 JPEG/PNG，分别准备学习照片和另批拍摄的独立试用照片，填写拍摄批次。每张不超过 5 MiB，最多 200 张，每项目原图与标准化图片合计不超过 512 MiB；原图保留，页面使用经方向校正的衍生 PNG。原图/像素/相似指纹及拍摄批次检查覆盖同厂其他项目，禁止学习和试用之间混用。每类至少两张合格/不合格例子只代表资料完整性，实际数据量、训练划分和效果门禁仍按本厂配置。

逐张框选检查对象、选择合格/不合格/无法判断并明确保存。人工身份、审核时间和来源由服务端生成，无法判断的照片不进入训练；OCR 另需正确文字。保存后进入下一张，未保存时禁止换图；字段序列化顺序不应影响已保存判断。质量负责人填写合格/不合格说明和漏检/误报上限后明确确认。照片或审核变化会使标准确认失效，需再次确认。

标注编辑复用原 VisionLab 托盘标注器的交互核心：缩放、命中选择、移框、四角调整、重拉框、单框删除和撤销。日常 Vue 编辑器与原本机托盘工具共用 `boxEditorCore.js`，不维护两份几何实现。工具为中文，类别来自当前工厂任务；切换下一种类别不自动改写已有框。缩放不改变保存坐标，重拉完成前保留旧框，换图/冻结后不沿用旧编辑历史；只读照片仍可放大查看。快捷键仅作用于当前编辑区域，不截获标准或文字输入框。

本机旧工具的固定共享资源从当前仓库读取，只在 loopback 提供明确的 JS 路由。继续使用完整仓库 checkout 运行原 `tray_annotator_local.py`；不再依赖复制出去的单个脚本。六膳门标签缺失确认、托盘边缘/完整性、四点工作区等专用流程保持各自审核规则，不作为其他工厂的默认配置。外部旧标签脚本是否可用需单独核对，不能把启动器存在当作完整功能可用。

浏览器通过同一 Java 工厂权限代理访问 `/drafts/{project_id}/preparation`，使用 `revision` 拒绝过期覆盖。提交先持久化冻结照片、人工审核和标准的不可变快照，再向现有队列派发；网络中断后仅刷新状态，不自动重复提交。相同冻结快照重复提交复用原任务。提交后禁止修改，可查看照片和标准。尚未登记精确的本厂快照/模板/SOP/输入/worker 时，明确显示“等待本厂执行设置接通，尚未开始训练”。通用检测/OCR 不会套用六膳门 adapter。

维护人员使用现有命名 worker 的可信下载入口逐张接收原图和衍生图：`prepare_sop_photos.py --registration <外部注册文件> --source-project-id <源项目> --expected-snapshot-sha256 <冻结哈希> --project-root <新外部下载目录>`。服务端必须明确授予该 worker 源项目读取范围；工厂范围执行授权不包含整厂照片读取权。传输要求内部认证、独立 worker 凭据和预期快照哈希；只允许固定可信服务地址，拒绝重定向和非本机明文 HTTP。大批照片不拼成一个 base64 JSON，完整下载后才写完成标记。

当前专用桥接用 `prepare_sop_photos.py --bundle <下载目录> --project-root <新本厂执行目录> --execution-project-id <执行项目> --factory-id <工厂>` 生成原 VisionLab `queue/manifest.json`、人工标注和独立试用 manifest。只导入经人工审核且可训练的学习照片，沿用拍摄批次分组划分；试用照片单独保存，无法判断的试用照片仅留审计，不进入有效验收清单。该桥接仅支持已登记的托盘标签专用任务；通用检测/OCR 可完成照片工作流，但适配器仍须按工厂接通。

配方额外登记 `preparation_project_id`、`preparation_sha256` 及冻结数据/标准/试用版本，并明确授权派生执行项目。先提交已有 `dataset` 阶段，由原 `build_dataset` 整理并返回实际数据集回执。维护人员把产生的 `datasets/<dataset_id>/manifest.json` 作为下一阶段 `train` 输入，登记文件 SHA-256 和数据集回执的来源 SHA-256；页面核对一致后，用户再明确“提交本厂模型学习”。训练阶段仍检查独立试用隔离、基础模型及其哈希和全部原有门禁。此流程不自动启动常驻 worker，不自动训练、验收或启用模型。

准备资料保存于现有外部状态目录的独立 `preparation.sqlite3`，启动校验建表、读写与回滚。原图数据量、保留周期、备份和清理需由正式环境的运维策略配置，当前本地验收不代表该生产策略已完成。

浏览器调用 Java `/api/mobile/{factoryId}/vision-training`，复用同一套 SOP 组件、服务、持久化和 runner。Java 从真实 JWT 及当前数据库成员核对工厂和 `factory_super_admin`/`quality_manager` 角色，再通过内部认证转发至 Python `/api/vision-training`。生产 Python 挂载要求内部认证、明确的 `FACTORY_USER` 和相同两角色，拒绝直接 JWT 绕过 Java 成员检查。JSON 中的 factory_id 仅声明请求范围，不构成身份；平台身份不能冒充工厂身份。

1. `GET /templates`：取当前工厂可用模板及 TaskSpec JSON Schema，据此生成表单或对话补问。
2. `POST /preview`，提交 `{spec, template_id?}`：校验、预览阶段与适用范围，不保存。
3. 用户明确保存训练任务时，`POST /drafts`，提交 `{preview}`：服务端重建模板并验证预览，按内容幂等创建草稿。
4. `GET /drafts/{project_id}` 与 `/drafts/{project_id}/plan`：读回持久化草稿、待办、阻塞与阶段证据。

TaskSpec 必填：factory_id、workstation_id、task_family、product_scope、packaging_scope、data_version、recipe_version、human_standard_version、independent_acceptance_version；OCR 另需 ocr_rules_version。工厂、工位、产品/包装或标准变化时建立新规格，不悄悄复用旧验收。

有限模板：`packaging-detection`（有无/缺件检测）、`packaging-ocr`（独立 OCR 规则），以及显式服务端工厂白名单内的六膳门专用模板。模板描述流程，不能证明某个模型已经具有该检测能力。未登记任务族直接拒绝；通用模板没有默认训练 runner 或模型。

## 阶段和证据

| 阶段 | 复用入口/证据 | 通过条件 |
|---|---|---|
| 定义任务 | 训练草稿、人工验收标准、适用范围 | 明确可见缺陷、采集条件和独立验收版本 |
| 采集 | 既有 collect 阶段 | 原图保留；工厂/工位、时间与来源可审计 |
| 数据集 | 既有 build_dataset、人工审核与去重机制 | 人工审核数据；训练集排除保护集；冻结版本与 SHA-256 |
| 候选训练 | 既有 train_candidate | 候选训练回执；不等于验收或启用 |
| 评测 | 既有 evaluate_candidate、verify_export_parity、evaluate_gate | 按本厂任务的标准完成保护集、独立正常集、一致性、延迟及回归门禁 |
| 独立验收 | 本厂独立数据和评测回执 | 工厂/项目/任务、数据/配方/人工标准版本一致，独立验收通过 |
| 启用 | 既有 deploy_candidate 受控发布 | 单独发布与线上读回；保留可回退模型 |

任何阶段失败、无 runner、无回执、跨厂证据或未经人工审核的数据都不能变成成功。回执必须携带工厂、项目、任务族、版本和真实哈希；训练成功不推导独立验收通过，验收通过不推导已启用。

## 日常任务和本地执行接线

已有平台固定代理保留兼容，仍受平台建厂自己的开关与 `PLATFORM_ADMIN` 身份/目标工厂校验约束，不作为日常训练入口。平台身份不会借用同数字 ID 的工厂用户身份。日常照片流程复用预览、保存、已存项目、阶段计划、执行记录及本地训练引擎；封闭 v2 能力目录不新增虚构的视觉能力项。

执行前由维护人员明确关联已登记的本厂设置，或先补齐资料与标准；按顺序提交采集、数据集、候选训练、评测，再更新进度读回本厂执行记录。选择已登记配方时使用服务端绑定的数据、方案、人工标准和独立验收版本；修改版本须新建项目并重新登记输入。浏览器不传可执行命令、文件路径、模型 URL 或可信输入哈希。

后台将执行任务保存于代码树之外的 SQLite 队列。命名 Windows worker 仅能领取自身工厂/项目范围内的任务，通过租约和心跳持有执行权，使用既有 `collect`、`build_dataset`、`train_candidate`、`evaluate_candidate`，回传完整身份和产物回执。重复提交相同身份返回同一任务；过期或身份冲突不能自动重训。成功训练、独立验收和启用仍分别判断；HTTP 队列不接收独立验收或启用执行请求。

六膳门 adapter 是 `liushanmen-visionlab-v1`，只对明确登记的工厂与该专用任务开放。通用检测/OCR 模板没有已验证的通用 runner，未登记时可定义和保存任务，执行保持阻塞；不能将已有六膳门权重、类别、托盘几何或指标换个工厂名直接复用。

服务器通过绝对路径 `VISION_TRAINING_REGISTRY_FILE` 读取代码树之外的操作员配置，格式包含 `recipes`、`worker_bindings`、`specialized_factory_allowlist`。默认三者皆空，不启用任何工厂。每项配方须绑定工厂、任务族、模板/SOP/版本、配置 SHA-256 和当前阶段输入 SHA-256；新产物经本地核对后再登记下一阶段输入。worker 记录只含 `worker_id`、`token_env`、`factory_ids`、可选 `project_ids`；令牌由命名环境变量提供，不能写入配置或仓库。每个 worker 使用独立令牌，与服务间内部凭据分开。

本机执行入口为 `scripts/windows/vision-sop-worker.ps1 -Registration <本机外部注册文件> -Once`，只消费一个已排队任务；空队列不启动计算。注册文件限定本机项目根目录、配置/输入文件与其哈希、服务地址白名单、worker 名称及环境变量名。运行前须提供 worker 专属凭据及内部服务凭据，凭据不通过命令行输出。执行和提交失败返回非零结果；回执 hash 表示完整性，不能当作 GPU 实际运行或模型效果的独立证明。

本地计算遵守上海 Windows/RTX 3060 规则，不向 Mac 派工；日常原入口 `scripts/windows/liushanmen-vision-lab.ps1` 保留。队列不会启动客户训练、改变现有自动任务或切换生产模型。原图、人工 JSON、固定划分、保护集、正常集、ONNX 一致性、延迟和回退门禁继续使用已有实现。

草稿使用代码目录之外的绝对持久目录：Linux 默认 `/var/lib/cretas/vision-training`，Windows 默认用户目录 `.cretas-state/vision-training`，可由 `VISION_TRAINING_DRAFT_DIR` 指定。相对路径、代码树内路径拒绝；启动验证创建、写入、读回和原子替换。多 worker 按相同预览只能原子创建同一份草稿。

草稿与队列在应用导入时不创建目录或打开数据库，启动时再检查持久卷。队列终态回执是阶段读回的持久来源，避免“队列完成、草稿未更新”造成永久不一致。重新启动后仍须读回同一工厂项目、阶段和产物。

当前接线的单测、HTTP/数据库读回、实际日常入口验收和各厂真实模型训练/效果验收分别记录；不得用模拟 adapter 或合成样本的编排测试代签真实模型效果。2026-10-15 本机隔离体验已在平台建厂开关关闭时，验证工厂/质量负责人登录、预览保存刷新、本厂既有采集回执和跨厂/平台拒绝；未执行客户训练或模型启用。改动保留独立分支，未合并、未部署，用户体验验收另行记录。
