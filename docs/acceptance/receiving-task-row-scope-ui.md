# 收货任务入口行级权限验收

Task `RECEIVING-SCOPE-20261018`；Base `c847f54b049676480e6a58d21d909d1aa280892a`。承接[生产与财务行级过滤](production-finance-row-scope-ui.md)保留的收货任务拒绝边界。仅修复共享导航角标和规范收货任务列表，不改变收货、库存、审批或财务业务规则。

## 权限边界

`GET /warehouse/receiving/tasks` 在原模块权限之后，按来源单创建人筛选：采购入库使用采购订单；销售订单客供料使用来源销售订单；无订单来料使用入库申请。工厂、软删除及未知来源均保守处理，不回退仓储操作人。采购状态分页在数据库内先绑定创建人范围，再截取原有500条窗口；精确ID/单号也绑定同一范围，隐藏与不存在均为空列表，避免泄露存在性。

只对规范控制器中明确声明支持范围的GET放行；客户来料写操作不随列表开放，采购收货原有来源单权限检查保留。生产经理仓储只读，任务行显示“只读”；不扩大角色或模块权限。ALL及无HTTP的内部调用保持原有契约。

## 已有环境与场景

复用原隔离新厂、Windows浏览器、Java、Web和原生PostgreSQL。旧采购单已全部收齐，空列表不能作授权阳性；本批用显式测试SQL加入三类来源、各含本人/下属/范围外的临时样本，不宣称这些样本通过UI创建或审批。任务物料使用“个”，不执行收货。
