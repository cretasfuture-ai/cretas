# 六膳门黑湖生产问数验收

所有答案等上线后按实测填。对账以 `LIUSHANMEN`、`blacklake` 的 `fact_external_production_daily` 为准。用黑湖报工日期划分期间，原样匹配产品编码。数量与不良率按单位分别计算。成品口径只取「成品入库」工序。跨工序对比各自的产出，同一批物料可经过多道工序。

| 问题 | 标准答案算法 | 上线实测 |
| --- | --- | --- |
| 11 月每天成品入库的良品量是多少？ | 筛选 11 月和「成品入库」，按报工日期与单位汇总 `SUM(good_qty)`。无报工的日期留空。 | |
| 11 月成品入库良品量最多的产品是哪几个？ | 按单位、产品编码汇总「成品入库」的 `SUM(good_qty)`，在各单位内降序排列，同量按编码排序。 | |
| 11 月产品 C P2026100002 的每日成品入库量怎样？ | 按完整编码筛选「成品入库」，逐日逐单位汇总 `SUM(good_qty)`。 | |
| 11 月各工序分别报了多少良品？ | 逐工序、逐单位汇总 `SUM(good_qty)`，展示分项。 | |
| 11 月各工序的不良数量是多少？ | 逐工序、逐单位汇总 `SUM(defect_qty)`。 | |
| 11 月各工序的不良率分别是多少？ | 逐工序、逐单位计算 `100 × SUM(defect_qty) / (SUM(good_qty) + SUM(defect_qty))`。分母为零或负时留空。 | |
| 11 月每天成品入库的不良率怎样变化？ | 筛选「成品入库」，按日期、单位先分别汇总良品与不良数量，再以汇总数量计算不良率。没有有效分母的日点留空。 | |
| 11 月产品 C P2026100002 在出料工序比成品入库多报了多少良品？ | 按完整编码筛选，分别汇总两道工序的良品量。只对两道工序均有记录的相同单位做 `出料良品量 − 成品入库良品量`。 | |
| 11 月按盒计量的成品入库里，哪天不良数量最多？ | 筛选单位「盒」和「成品入库」，按日算 `SUM(defect_qty)`，求最大值，列出并列日期。 | |
| 11 月按 KG 计量的产品 C P2026100002 成品入库累计不良率是多少？ | 按编码、单位、月份和工序过滤后，用汇总的不良数量除以汇总的良品加不良数量。分母大于零才出数。 | |
| 11 月出成率是多少？ | 出成率需要投入量。标准回复为「黑湖数据不含投入量，无法计算」。 | |
| 11 月成品入库单位成本是多少？ | 单位成本需要制造成本及匹配单位的产量。快照无成本和投入量，标准回复为「黑湖数据不含投入量，无法计算」，同时说明缺少成本数据。 | |

## 上线后对账

1. 以 Cretas 应用数据库的现有只读连接验证 `external_source_snapshots` 对 ETL 可读。仅对 `factory_id = 'LIUSHANMEN'`、`external_system = 'blacklake'`、`dataset = 'report_output'` 读取最新 `id`、`collected_at`、`row_count` 和报工日范围。
2. 记录 SmartBI 事实表中六膳门黑湖的总行数、覆盖窗口行数和快照状态。迁移上线后，在 Python 服务目录用既有服务环境运行 `python -m smartbi.gold.external_production_etl --factory-id LIUSHANMEN`。再查同一谓词，按事实唯一键消重对账并抽查四种单位。同一快照复跑后比对事实行数、数量和快照 ID。核对每日 03:30 的 `cretas-gold-etl-refresh.timer` 经 `python -m scripts.gold_etl_daily_refresh` 在采集后覆盖六膳门。作业日志应有本厂 `external_snapshots_synced=1`、`errors=[]`，以及全局 `failures=0`。
3. 登录六膳门，打开「生产管理 → 生产分析查询 → 生产数据分析」，选择有黑湖报工的日期。截图留存默认趋势、单位/工序/产品切换后的数量与不良率、成品入库排行、采集时间和无法计算说明。另核对成本分析页的相同口径，与 F006 现有生产/成本读数做对照。
4. 从「工厂问数 → 业务数据」逐题实测，记录回答、引用来源、日期/单位边界及对账结果。外部事实已通过工厂问数的业务来源接入。普通上传报表问数仍使用原上传数据源。多步比较、自然语言期间识别和各问题的模型选图以实测为准。

快照 payload 未携带采集时的查询窗口。ETL 用该份非空快照中最早至最晚的报工日确定覆盖范围，窗口外保留历史事实。空快照只更新采集状态。采集超过 36 小时显示「数据未更新」。
