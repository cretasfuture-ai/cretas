## 现状实测（⛔ 不是从截图推断的）

| # | 现象 | 实测出的成因 | 判据来源 |

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像

**仓管员（warehouse_worker / warehouse_manager）** — 年纪偏大、文化素质参差（客户张权原话：「你不能太依赖他们，最好的方法就是你告诉他这个东西你要收多少就行了」）。典型场景：货车到厂，掏出手机，找到这一单，点确认、拍照、收完；以及有发货任务时按单发货。**他不查库存、不看统计、不做分析** —— 那些是办公室在 web 上做的事。

### 用户旅程（收敛后）

| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|---|---|---|---|
| 1 | 打开 App，**直接落在「入库」** | 无 | ⛔ 不需要先看一屏统计再点进去 |
| 2 | 待收货单列表，每张卡带 **供应商 + 货品名 + 预计数量** | 找到到货的那一单 | 一眼认出是哪一车货（防呆 Rule 2） |
| 3 | 点「确认入库」 | 填实收数量 + 拍照 | 数量框预置上限与已收数（防呆 Rule 1） |
| 4 | 收满后该单**从列表消失** | 无 | 不会对着已结单的单子再扫一次（上一轮已修） |
| 5 | 有发货任务时切到「发货」 | 按单确认发货 | 缺货时给「去调拨」出路（上一轮已修，⚠️ 本次不能砍断） |

### 摩擦点清单

| # | 摩擦点 | 严重程度 | 来源规则 |
|---|---|---|---|
| F1 | 底部 5 个 tab，其中 2 个（首页/库存）是他从不用的；库存栈下挂 **18 个屏** | HIGH | 内联 UX 规则「每屏只暴露当前步骤需要的信息」 |
| F2 | 首页的任务列表与「入库/发货」两个 tab **内容重复** —— 同一件事两个入口，他不知道该点哪个 | HIGH | 内联 UX 规则「主操作按钮唯一」 |
| F3 | 首页抬头堆着「今日入库 30 单 / 待发货 1 单」等他不需要决策的聚合数 | MED | 内联 UX 规则「信息密度」 |
| F4 | 卡片上货品恒显示「未知材料」 —— 他**无法确认这是哪一车货** | HIGH | 防呆 Rule 2（上下文必带身份信息） |
| F5 | 隐藏首页会砍断上一轮刚接好的「库存不足 → 去调拨」跨栈跳转 | HIGH | 防呆 Rule 5（Dead-end 改导航） |
| F6 | 入库列表顶部 4 个筛选 Chip（全部/待入库/质检中/…）—— 他只关心「还有哪几单要收」 | MED | 内联 UX 规则「信息密度」 |

### 每个摩擦点的设计回应

- **F1** → 底部导航 5 → **3**（入库 / 发货 / 我的）。⛔ **隐藏不是删除**：两个 Stack 与其下 24 个屏全部保留在代码里，只是不再从底部导航进入。用一个具名常量 `SIMPLIFIED_WAREHOUSE_NAV` 控制，**改一行即恢复**（owner 说「先隐藏起来看看效果」）。
- **F2** → 落地页改为「入库」。首页这一层直接不出现，重复入口自然消失。
- **F3** → 随 F2 一并消失。⛔ 不单独去改首页的抬头文案 —— 改一个不再出现的屏是白工。
- **F4** → `materialTypeName` → `materialName`。并**把那个后端从不发的字段从 TS 类型里删掉**，否则下一个人还会读它；配一条闸钉住「RN 读的字段名必须在后端实体里存在」。
- **F5** → 把 `TransferList` / `TransferDetail` 从首页栈**迁到发货栈**，并改掉 `WHDeliveryConfirmScreen` 里那处跨栈跳转。⚠️ 这是本次唯一的「两个各自正确的改动会叠加出缺陷」的点。
- **F6** → 保留 Chip 但**默认选中「待入库」**而不是「全部」—— 他打开就该看见要干的活。⛔ 不删筛选（质检中/已入库偶尔要回查），只改默认值。

### ⛔ 保留 "我的" 的理由（不是凑数）

它是**登出 / 切账号的唯一出口**。砍掉等于把用户锁死在一个账号里 —— 防呆 Rule 5 的原教旨违反。

## 采购弹窗延迟的修法

**结构判据**：这个文件已经有过两次 prod 事故（2026-08-04「点了没反应」），成因都是**在显示弹窗之前等网络**。
▎「永远打不开」和「2 秒才打开」是同一个结构缺陷的两个刻度。

| 路径 | 现在 | 改成 |
|---|---|---|
| 新建 | `await` 3 个请求 → 开弹窗 | **先开弹窗** → 后台刷新下拉，select 挂 `loading` |
| 编辑 | `await` 3 个下拉 + 单据 + 供货关系 + 规格 → 开弹窗 | 三个下拉**不阻塞**；只等单据 + 草稿判定（⛔ 这个判定必须在开弹窗前 —— 非草稿根本不该开） |

⚠️ **保留 2026-04-28 那条修复的意图**（每次打开强制刷新，防止 dropdown 用旧 cache）——
改的是「阻塞地刷新」而不是「不刷新」。

**硬约束 8**：`await Promise.all([loadSuppliers(), loadMaterials(), loadSalesOrders()])` 改前 **2** 处，两处都改，⛔ 不留一处。
