### 1.1 同步线的真实形状（动手前核实）

- 它**不是**服务器 cron（47 与 139 的 crontab 里都没有），是 Codex 云端自动化：账号 `Cretasfuture`，每天约 09:10 CST 开 `codex/sop-sync-YYYYMMDD` 分支发 PR，08-24 起共 9 次。云端日志本仓看不到。
- 每次同步改**五样东西**（以 #427 为样板）：
  1. 语料 `f006_production_sop.md`（RAG 源，`source=f006-production-full-chain-sop.md`）
  2. 静态页 `docs/manual/F006-production-full-chain-manual-test-sop.html`（挂 `/lsmsop/`）
  3. `web-admin/public/aiassist.html` 工厂 tab 新增一条编号快捷问（当前到 58）
  4. `backend/python/food_kb/api/manual_chat.py` 新增一个关键词护栏 + 固定答案常量（命中即不走 RAG）
  5. `tests/test_food_kb_manual_chat_sop_contract.py` 新增一条 `test_YYYYMMDD_*` 钉住以上四处
- 灌库**不在**部署脚本里：`python -m food_kb.services.manual_ingester --source f006-production-full-chain-sop.md` 在 47 上单独跑（原子重建，台账记「正式块 N / .NEW=0」）。

## 2. 目标与非目标

**目标**
1. 语料、静态页、快捷问、护栏四处与 origin/main **当前**工厂行为一致，覆盖 09-01 09:16 之后的全部碰代码 PR。
2. 有一套**可重复跑**的回归探针（问句 + 判据），跑到全对为止，之后每次同步都能复用。
3. 同步线再漏跑时**当天可见**。
4. 把这次的口径写成客户可读的 SOP 句子，不带内部 UUID / 缺陷编号 / PR 号（PR 号只留在 spec 与测试注释里）。

**非目标**
- 不改 RAG 检索、缓存、prompt 结构。
- 不重写 08-26～08-31 已同步过的章节；那六天只抽查，答错才改。
- 不接管 Codex 云端自动化本身（改不了，只加仓库侧监测）。
- 不碰餐饮 tab 与餐饮语料（契约测试要求两线隔离）。

## 5. 执行方式

1. worktree `codex/claude-aiassist-sop-resync`（off origin/main，已建）。
2. 主线先做 4.6 的探针脚本与问句集（先有尺子），用当前线上跑一遍得到基线读数。
3. 按 4.1 的章分 6 组派子代理并行起草：每组只拿本组 PR 正文 + 台账/走查件摘录 + 该章现有语料文本，产出「替换/新增段落 + 每段引用的 PR 号」，不直接改文件。
4. 主线合稿：逐段核对代码（尤其三条答反的），改语料与静态页，写快捷问、护栏、契约测试。
5. 本地 `pytest tests/test_food_kb_manual_chat_sop_contract.py`（现 150 条）+ HTML/JS parse + `git diff --check`。
6. PR → CI → merge（碰 backend/python 与 web-admin，走 PR 通道）。
7. 部署：`release-cretas.sh` 发 web-admin（aiassist.html）；`deploy-smartbi-python.sh --env prod`；47 上跑 ingester 重建 `f006-production-full-chain-sop.md`；`/lsmsop/` 静态页按现有 rsync 到 139。
8. 部署判据：47 进程启动时间晚于制品；ingester 日志「正式块 N / .NEW=0」；线上探针 4.6 跑到 0 未过；仍有未过的回到第 4 步，不减问句。
9. 台账登记 `SOP-RAG-RESYNC-20260902`。
