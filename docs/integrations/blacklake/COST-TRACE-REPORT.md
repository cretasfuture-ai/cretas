# 六膳门：SmartBI 成本差异追溯与来源补查

本切片基于 `56a39807cdc339481c954ca6c06f828d14967550`，沿用独立测试工厂 `BLACKLAKE_POC_TEST`。黑湖正式源仅查询，现有测试库原1,879条归档保持不变。原成本时点是北京时间2026-11-03 17:21:49，补查结果明确另列时间，不把新数据混入原成本快照。

## 已接上的 Cretas 能力

调用现有 `smartbi.services.factory_charts` 的 `Series`、`series_candidate`、`facts_for` 和 `render_answer`，生成8个产品成本视图，3个产品具备多工单差异比较。未新建另一套图表指标引擎，未将材料+人工伪装成完整制造成本，也未调用外部LLM处理真实生产明细。

同一产品代码必须在产品定义中唯一对应稳定ID，领退料的ID/代码也须一致。仅在同产品、同成品单位、通过原成本字段校验的工单子集内比较。缺少产品身份映射时不生成跨工单比较，身份冲突直接拒绝分析。

- 单位直接成本的子集汇总使用“已识别直接成本合计 / 成品量合计”，不取工单单位成本的算术平均。
- 对比该子集观测到的最高、最低工单，分解为材料单位成本差额和人工单位成本差额。最低只是相对比较基准，不是标准或最佳成本，不构成时间趋势。
- 同物料、同单位且正净耗用/正净额时，可进一步按“净额/净耗用折算价”分解价格项与耗用量项；净额零/负、新增/减少或不具备两侧值的物料不强行拆分。
- 逐物料差额 + 人工差额与单位直接成本差额对账，容差1e-8。当前3组真实比较最大残差约1e-26。
- 这些是可追溯的代数差异，不证明采购涨价、损耗或人员效率的业务原因；仍需回查源单。币种未由接口返回，完整制造成本/毛利仍缺失。

## 真正补查了什么

1. **225条工单用料归属查询核实**：109张工单分别按ID、编号进行218次查询，109组配对结果相同且与原归档一致；随机不存在工单的请求由源端明确拒绝，业务码1014、消息“工单不存在”。负对照与本报告的租户/来源/运行ID/归档指纹/请求摘要/时间绑定，不能拿旧的无关1014当证据。原响应用料没有projectId，保持原文，只记录查询归属证明。
2. **两条缺关联领退料追到源单后仍无指针**：复查明细的业务关联ID/类型/编号、来源明细ID/信息，以及订单级来源ID/编号。类型码单独保留，不把类型当关联ID。备注与自定义字段中也没有任何已知工单编号。不能按物料名、日期或数量猜测分摊；明细源单编号在受保护的测试页面中提供给工厂核对。
3. **74行零估值重新确认**：本次按原订单ID+明细ID对照当前响应，74行金额和成本单价仍为0；单价缺失/变化均0行。另检查实际成本单价、产品主数据和历史入库。31种涉及物料中，2种存在当前移动平均价，按产品ID+代码+单位精确匹配；它们不是当时的领料成本，不能回填。
4. **没有找到可回填的历史价证据**：筛选已审批、同物料同单位、不晚于领料业务时间的正数单价记录。当前归档内无合格参考行。不能把当前主数据价、税额金额或更晚入库价当成历史实际成本。
5. 本次源查询已返回336张出入库单，比原归档多4张。新增单据作为补查线索单独保存，没有改写原332张库存单及其成本口径。

原来的 **16/109张工单可展示单位可识别直接成本** 没有被放宽。225条用料查询归属证明是参考资料核实，不等于补齐真实领料成本；BOM单位用量、损耗及包装换算基准仍待核，不计算未经证明的标准用量差异。

## 页面和运行边界

入口仍为 http://127.0.0.1:5178/blacklake-smartbi.html ：“原料 → 成品成本”新增同产品选择、成本对比图、价量/人工差额及对账；“关联与估值补查”展示225条查询证据、2条源单、74条零值、2种当前价格线索和待核对清单。工单抽屉显示经查询核实的用料参考，并明确单位用量基准未核。

补查证据是仓库外CurrentUser DPAPI文件，按当前证据schema、complete状态、有效负对照、tenant/source/run和完整原归档指纹校验。任一不匹配或不完整时，不提供已验证用料引用，页面明确警告。数据集通过PostgreSQL只读角色与原RLS读取，仍仅限该测试工厂授权管理员。

常规共享Web外壳旧权限接口404仍未通过，沿用上一切片的原始FAIL。本次未刷新共享Java、部署生产、启用持续同步或修改黑湖业务数据。

## 复现

在 `backend/python`、已配置同一安全来源绑定和测试环境的当前用户下：

```powershell
python -m blacklake.gap_inspect
python -m blacklake.gap_probe
python -m blacklake.gap_evidence
python -m blacklake.smartbi_acceptance
python -m blacklake.test_local
```

`gap_probe --control-only`只重查与同一归档匹配的已有活动报告之负对照，不重新把过期/不同归档的证据标成有效。任一项目失败、数量不足、双查询或归档不一致时返回非零。补查原文与价格线索不回写黑湖或原成本事实。
