# 人工资料补充与原生 MES 复用

此功能写入本机隔离补充库，不修改黑湖工单、报工、工资或 Cretas 生产账。公开测试链接展示汇总和待补项；填写、Excel 保存仅在本机管理入口或已鉴权的工厂管理员 API 开放。公开反向代理不能获得本机写权限。

## 使用路径

产品成本分析 → 产品 → 人工与工序成本 → 补充 / 导入资料。

- 逐项填写：选择工单和具体任务，每段填写实际参与人员代码、开始/结束、休息/停机分钟及核对依据。同一人跨工序使用同一代码。
- Excel：下载当前范围模板，工单号、任务 ID、工序三项严格对应。每行一个时段，相同任务可多行。先预检和预览，整批确认；有错误时整批不保存。拒绝公式单元格。
- 只存人员代码的工厂范围 HMAC，不向网页返回名单、个人工资或哈希。编辑时整条重填；每版保存审计依据、操作者、来源及原始来源签名。补充库不进 Git。
- 零人时须明确确认，不等于已证明实际名单；缺少名单时真实人均仍为空。原始零工资、零时长与补充结果分别展示。

## 计算与自动更新

有效人时 = Σ[(结束 − 开始 − 休息 − 停机)小时 × 本段实际人数]。

实际人均 = 所选工单已记录人工费 ÷ 实际参与人员去重数。每道人工作业均需有人员依据；代报人、计划人数、整天出勤不能替代。

先逐张工单计算：工序分摊额 = 本单人工费 × 本工序人时 ÷ 本单总人时；分币尾差落在最后一个有工时的工序，再汇总到产品。仅重新分配同一笔人工费，不把报工估算工资再加一遍，也不改变材料费或原账。

保存后读接口实时重算数字和缺口规则；页面自动拉取。补充版本纳入持续分析变化标识和周期报告指纹，本地模型沿用既有队列、全事实核验和重试。历史分析保留旧依据，新结果不会冒充旧版。任务相关源事实变化时原补充标为待复核，不继续使用过期值。

## Cretas 已有资料及实际缺口

| 资料 | 现有采集 / 管理入口 | 可以复用 | 仍需核实 |
|---|---|---|---|
| 逐工序报工 | `production/plans/list.vue`、`production/approval/list.vue`；`ProductionReport` | `factoryId`、`batchId`、`workProcessTaskId`、`processOrder`、`totalWorkers`、`totalWorkMinutes`、`laborSegments` | 审核状态；多段记录通常仅含时段和人数，不能还原全部逐人名单 |
| 实际批次人员 | `processing/batches/{batchId}/workers`；`BatchWorkSession` | `employeeId`、批次、签到/签出、作业分钟 | 批次名单还需关联每道工序和具体时段 |
| 考勤 | `timeclock/admin/history`；`TimeClockRecord` | 人员、上下班、工作分钟、休息分钟 | 考勤没有直接工单/任务 ID；不能直接将整天出勤摊到工单 |
| 原生人工与人效 | `production/labor-efficiency`；`labor-efficiency/batches/{batchId}/step-breakdown` | 实际工时/人数、已授权工资、计划比较 | 计划 `estimatedWorkers/estimatedMinutes` 不能当实际；工资受成本权限保护 |
| 人员分段结单 | `ProductionSettlementRequest.LaborSegment` | 请求可带 workerId/name、工种、分钟和人数 | 服务聚合链路未完整保留人员身份，不能声称已形成逐人时间账 |
| 电子工序表 | `ProcessSheetRowRequest` | 批次、工序、时段、人数、总人时 | 每段逐人 ID 及工序级停机扣除不完整 |

现有管理端采用 Element Plus 表单、弹窗、审核表格与逐段录入。本入口沿用这些组件及品牌颜色，并接在已被原生 `M67YieldCost.vue` 与黑湖产品分析共同复用的 `LaborCostAnalysisPanel` 上，不另建孤立人工成本总览。

当前六膳门隔离黑湖租户尚无已核实的原生业务工厂／批次／任务映射，因此**没有自动调用原生生产租户数据进行拼接**。不能按姓名、产品名或同一天自动关联。先将现有已审核记录按下载模板核对导入；后续自动复用需建立 `tenant + source_factory + external_project/task ↔ native_factory + batch + workProcessTask` 显式映射并核对同租户权限。此项不等于修改原生采集模型已经完成。

## 存储与验收边界

补充库位于安全配置同目录 `labor-supplements.sqlite3`，scope 含 tenant、来源工厂、baseline anchor。行以任务锁定，并验证真实工单父子关系；乐观 revision 防覆盖，整批事务，已填人员跨任务时间重叠拒绝。未填写、不匹配、未确认、工资不一致、源数据变化均保持缺失或待核，不填零。

使用合成资料验证录入→保存→重算→缺口解除及错误行回滚；真实六膳门仍缺实际班组依据，不能用合成名单回填以制造完成结果。本机保留测试日志、运行回执、补充库与历史资料；未部署到共享生产服务。
