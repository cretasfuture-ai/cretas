# SmartBI 本地模型分析规范

目标：将可复用的经营判断方法交给本地模型，并检查它是否有证据地使用这些方法。不是让模型编数字，也不是宣称小模型与 GPT 的综合能力已经相同。

## 每份分析必须回答

1. **统计依据**：引用哪些可验证数据？选择了哪些指标？数字、名称和工单由程序绑定，模型不能自由改写。
2. **怎么看**：这组数据说明什么，适合与谁比较？
3. **为什么重要**：可能影响什么业务决策？
4. **可能原因**：列为待验证假设，不写成已确认原因。
5. **下一步**：先找哪个角色、核对什么资料，如何区分几种解释？
6. **不能下的结论**：现有数据证明不了什么？
7. **继续追问**：给出本板块适用的后续问题，沿用同一份证据。

## 先问对问题，再比较金额

| 维度 | 统计口径 | 必须带上的解读 |
| --- | --- | --- |
| 数据覆盖 | 可核算工单数 ÷ 当前范围工单数 | 算得出来不代表实际成本记全；缺失和零值分开 |
| 原料 | 已审批领料减退料的成本，再除最终良品 | 核对主料、半成品和历史计价；当前均价不能填旧账 |
| 人工 | 任务累计工资 ÷ 最终良品；人工占材料加工资比例 | 人工占比高先排除漏料；零工资不代表效率好；不再加报工估算工资 |
| 成品 | 工单最终审批良品数量 | 工序和多次报工不能重复相加；确认包、盒、公斤的换算 |
| 产品成本 | 同产品材料加工资合计 ÷ 合格产量合计 | 大单小单按产量算，不能直接平均各单单价 |
| 同产品差额 | 高低工单单位材料差＋单位人工差 | 先核对同产品、规格、单位和阶段；低价对照漏薪时不把差额当浪费 |
| 生产 | 按明确归属日期统计状态、任务、报工 | 完工样本不能冒充全厂完成率；没有标准基准不能认定低效 |
| 库存 | 按业务日期的收发与明确时点的余额分开 | 没有历史期末余额不等于没有出入库流水；无记录不等于零库存 |
| 历史 | 引用相同口径、已完成的兼容报告 | 不累加重叠周期、不平均日报单价，未再命中不等于问题解决 |

## 已固化的误判检查

- **看起来便宜**：主原料或上游半成品价值是否没带进来？是否只是包装工单？
- **人工比例高**：是工资偏高，还是材料没记全把比例抬高？
- **同产品差价大**：低价单有没有零工资、缺材料或不同规格？
- **材料差额**：需要核对用量、材料组合、退料和历史估值，不能直接说采购涨价或生产损耗。
- **同编码不同名称**：可能属于不同工艺阶段，先核对身份，不强行合并。
- **样本很少**：仅作核对线索，不作稳定趋势、标准成本或绩效结论。
- **周期没齐**：按采集时点说明覆盖范围，不预测填满剩余日期。
- **缺库存历史**：区分期末余额、采集时点余额、期间出入库三个概念。
- **部分缺失**：只约束受影响工单，不扩大成全厂都不能计算。
- **数据未提供给模型**：只能说当前证据不足，不能捏造源端不存在某种数据。

## 模型与程序怎样分工

程序负责取数授权、精确算账、可比组筛选、指标准备、证据和名称映射。本地模型依据版本化的业务规范选择统计，生成白话解读、假设、责任角色与核对步骤。校验后才展示。

模型只接收匿名统计、必要比例和受控风险类型；原始工单、人员、工资明细、实际金额、产品名称、自由问题与认证材料不进入提示词。真实名称和金额在输出后从已授权证据绑定显示。

不合格输出进入修复或排队重试：引用错误、缺少板块、漏掉必要风险、捏造数字、错误单位或证据归属、把猜测写成原因、把已有流水说成缺失等，都不能作为当前有效解读展示。

一次生成最多修复一次；两次调用的 token 都记录。跨持久重试保留已知调用 ID 并去重。分析版本与输入事实进入缓存键，旧模板不能冒充新模板结果；旧报告保持原版本，用户重新查看日期时按需生成新版本。

## 能力如何继续提高

维护可人工核对的业务案例，记录“应发现什么、不能说什么、需要什么证据”。新增发现先变成通用指标或检查项，再扩充案例并回归。以覆盖、事实一致性、错误拒绝和实际业务反馈衡量质量，不能以报告写得长或语气肯定衡量。

当前这套规范提高的是指定制造经营任务的覆盖和稳定性，不能证明模型已经具备 GPT 的全部知识、推理和泛化能力。标准配方、批次对应、期初在制品和制造费用缺失时，换更大模型也不能把它们变成已知事实。

已进一步加入三组示范的二次追查与衍生指标，见 [轻量蒸馏案例](TEACHER-DISTILLATION.md)。它们随每次本地分析一起进入提示词，触发材料数量与估值拆分、投入单位转换、计量来源等追查方向。
