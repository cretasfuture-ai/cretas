# 日常报告逐项分析

自 `smartbi-period-report/2026-11-05.3` 起，新生成的周期、夜间和持续采集报告都经过相同流程：

1. 固定来源工厂、日期范围和数据指纹，保存确定性统计。
2. 生成七个主题的概览。概览提供的事实数量不算作逐项核对完成数量。
3. 用 `analysis_evidence.build(..., include_all=True)` 枚举本报告全部程序事实，每批最多八项，由本地模型分别解释、指定处理部门和核对动作。
4. 每项独立通过数字、事实绑定、处理部门、风险措辞及推断边界校验后保存；同批其他项失败不会丢弃通过项。失败项携带校验反馈和限定在当前事实内的未通过草稿，定向纠正一次；仍不通过则六十秒后自动续跑。草稿不作为事实。连接失败同样保留进度并重试，不消耗永久失败次数。
5. 全部事实通过且没有上游事实缺口才把报告置为完成。没有可归属工单的空周期明确标为不适用，不调用模型猜测生产原因。

队列每五秒检查一次，不依赖浏览器打开。每批释放队列租约；进程重启后从本机 JSON 检查点和 SQLite 队列续跑，不重新生成已核验概览。检查点绑定工厂、报告、数据指纹、事实摘要和有效队列租约。权限或来源绑定失败不能被模型重试绕过。

接口的 `ai.analysisFactCoverage` 返回 `mode / reviewed / total / remaining / phase / currentFacts / blocker / retryAt / attempts / updatedAt`。网页在周期状态、报告详情和自动更新记录展示同一份进度；具体核对项折叠显示。历史补充模式仍保留 `additionalReviewed`，不会把原来仅补核遗漏项的报告误标为新模式的逐项分析。

“全部”指本报告程序生成的分析事实，既有统计聚合口径保持不变；不表示原始业务单据完整、所有业务原因都已确认或材料到成品批次已经闭环。模型不能补造缺失的单位、价格、领退料或完工记录，这些缺口仍进入各主题的处理清单。

原始输入、各次模型返回、拒绝原因、通过项和实际 token 用量保存在本机；此流程只调用已配置的本地模型，不调用收费补课 API。现有已完成历史报告不批量重写，活动采集报告会升级一次，之后仍按数据变化合并排队。
