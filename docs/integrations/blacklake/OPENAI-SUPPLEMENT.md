## 模型与参数实测

同一批六题涵盖逐料成本差、正常对照、覆盖偏差、库存时点、矛盾断言和计数粒度。三个配置各调用一次，六题分类一致；这不是盲测准确率，也不能推断在真实业务上等效。

| gpt-6-astra | high | 823 | 4,476 | 0.232030 |

本次选择 Astra medium 的简洁表述为主要补充素材，以 Sol high 交叉核对。没有证据表明把这组题的 Astra 强度升为 high 会多发现问题。Astra high、Sol high 都把合成库存题的出入库单误称为工单，这段不能原样蒸馏。三份原始结果均保留。

调用采用 Responses、严格 JSON Schema、`store:false`、`max_output_tokens:6000`、`text.verbosity:medium`；不传 reasoning 模式下不支持的 temperature/top_p。不要求内部推理过程。实际输出含推理 token，预算按总输出计。长答或 usage 未知时保留原答并保留预算预占，禁止自动重发；答案可再交本地模型摘要，摘要不自动成为事实。

官方文档将 Astra 定位于最高能力，将 6.1 Sol 定位于接近 Astra、成本更低；仍应按实际任务选择。[模型与参数](https://developers.openai.com/api/docs/guides/latest-model)、[价格](https://developers.openai.com/api/docs/pricing)。

## 补课落实到什么

- 高成本先拆材料和人工，再核逐物料数量、账面单价、投入组合。共享物料编码的账面单价一致，不足以认定采购涨价；同码异名、规格和工艺阶段须单独核对。
- 强制纳入高差异样本和另一产品的稳定对照，不能只找异常；分组标识防止把一个产品的问题套到另一个产品。稳定仅是所见账面稳定，不证明成本完整。
- 按产品报告工单覆盖和同单位良品产量覆盖。未知数量保留缺失；按产量加权不能修复非随机缺失，也不能把子集推为全厂。
- 正文、影响与使用边界一致。先断言“严重低估”再说“无法反映”或“不能确认”仍然是错误。程序校验拒绝并给模型一次修复机会。
- 出入库单、任务、报工、工单、告警、物料行各有粒度；数量差不直接等于漏报次数。期后快照不能代替期末余额。

服务端继续计算数字并绑定可读证据；模型负责白话解读。新增共同物料账价核对是辅助线索，不是采购价审计。每板块仍有证据采样边界，遗漏明确标记，不能声称所有逐单记录均被模型核对。

## Decisions 与飞轮

八题共享上下文的 Decisions 实验在 0.5 阈值只有 4/8 与预期一致，四个误报；改成每次单独一题后为 7/8，但矛盾断言题给出 0.45，仍会在 0.5 阈值漏报。因此没有接成线上放行条件，不将概率当正确率。0.2—0.8 可作为后续灰区试验方向，本轮不宣称阈值已校准。[Decisions 定义](https://developers.openai.com/api/docs/guides/decisions)。

可选 `SMARTBI_ANALYST_FLYWHEEL_DB` 指向本机绝对 SQLite 路径，记录未通过校验的证据、原候选和固定错误码。默认未配置时关闭。候选不是训练真值；不自动改提示词，不自动训练，不自动调用云模型。按租户和来源快照家族隔离，确认训练/留出集不能共用家族，撤回样本不可再入选。`human:` 仅是离线操作人的显式标记，不是用户认证服务；只有经业务审核确认的样本可以导出。近重复检测仍需审核，不能把来源家族检查当完整去重。

预算复用前轮账本，累计上限 10 USD，本轮额外保守上限 1 USD；全部输入按更高缓存写入单价预估，不依赖缓存或免费奖励。调用未明时保留预占。最终金额与验收见本轮验收文件。

本轮 OpenAI 共 12 次调用，按标准价格估算 0.341305 USD；与前轮 Claude 合计估算 1.810355 USD。账本累计保守记账 1.838147 USD，无未结预占；实际账单与免费奖励未核实。

## 本机长期保存与迁移

固定目录 `D:\CretasSmartBILab\local-analyst-distillation`，访问限本机用户与 SYSTEM。保存原始教师答案、案例、真实回放输入输出、提示词源码、参数、用量账本、候选账本与校验清单；不保存账号密码、API Key、Token 或 DPAPI 凭据文件。活动 SQLite 使用 backup API，保留 WAL 中已提交内容。

模型是 `qwen3.8:27b`（27.3B、Q4_K_M）。Ollama 服务端版本 0.40.6；完整 OCI manifest 引用五个 blob，共 17,741,872,154 bytes（16.52 GiB），包含模型、投影器、模板和参数。不能仅保存单个 GGUF 或只抄一条 FROM。原 manifest 的 SHA-256 为 `aaee06c39dcf2437cde036998d960e1fc1494b8191be7cc9657d01e509097813`。

迁移时：

1. 在获准、能运行该模型的新主机安装兼容的 Ollama。先停止该主机自己的推理服务并备份已有同名模型，避免覆盖他人模型。
2. 将本机 `model-store/blobs` 中五个文件和 `model-store/manifests/registry.ollama.ai/library/qwen3.8/27b` 原样放入目标 Ollama 模型根目录对应位置。通过自定义模型目录使用时显式设置该主机的 OLLAMA_MODELS；勿盲目修改其他主机配置。
3. 校验全部 blob SHA-256 与 manifest digest，然后启动服务，核对 `/api/show` 的量化、模板和参数，并用保留案例回归。仅文件校验不能代表推理验收。
4. 重新提供目标主机访问授权后切换计算入口。测试适配器只接受 `BLACKLAKE_LOCAL_AI_SSH_HOST=canada-mini|aurora-mini`，不自动安装模型或借用算力。当前本机未配置 aurora-mini 别名，替代计算主机尚未验收。

Windows 负责保存和编排，不要求运行 27B。加拿大机器不可用时，已保存内容可迁往后续获准的计算主机；迁移推理效果仍须回归。备份完成以本机 `model-backup-acceptance.json` 的五文件校验结果为准；本轮未在 Windows 执行 27B，也未完成另一台机器上的恢复推理。
