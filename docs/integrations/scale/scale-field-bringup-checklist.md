# 电子秤现场联调清单

用途：现场拿到真秤后，按顺序验。每一项写「怎么做 / 预期 / 判据」。没做的项就是**没验**，不要写通过。
背景和已知缺口见 `scale-integration-current-state.md`。**先别连生产：只在测试厂（F006）用 `QA-` 前缀数据，不碰 LIUSHANMEN，不输入生产密码。**

## 0. 开始前先确认的事实（逐条记到「记录」栏）

| # | 要确认 | 怎么确认 |
|---|---|---|
| 0.1 | 秤 / 仪表品牌、型号、固件版本 | 铭牌拍照 |
| 0.2 | 对外接口：RS232 / RS485 / 以太网 / WiFi / 蓝牙 / USB | 看背板、手册；多口的选哪个 |
| 0.3 | 输出模式：连续输出 / 按键打印 / 询问应答（Modbus）/ 变化时输出 | 仪表参数菜单（手册里叫「通讯参数」「输出方式」） |
| 0.4 | 厂家协议文档 | 向厂家要；没有就走 §2 抓帧 |
| 0.5 | 网关放哪、谁写（现状文档 G1） | 先定，没有网关就没有后面的整链 |

## 1. 接线与串口参数

| 项 | 种子里的默认（**需现场核对，不是已验证值**） |
|---|---|
| 柯力 D2008 | RS232，9600 / 8 / N / 1，无流控，连续输出 |
| 耀华 XK3190 | RS232，9600 / 8 / N / 1，连续输出，帧以 `=` 开头 |
| 托利多 IND570 | RS232，9600 / 8 / **O**dd / 1（种子写奇校验），STX…ETX + XOR |
| 通用 Modbus RTU | 9600 / 8 / N / 1，从站 1，功能码 03，寄存器 0 起 2 个 |

接线：RS232 用 TX/RX/GND 三线，注意**秤的 TX 接电脑的 RX**（交叉）；RS485 注意 A/B 极性。
先用 USB 转串口 + 串口调试工具（SSCOM、PuTTY 等）直接看秤发什么，**确认有数据再接网关**。

## 2. 抓帧（所有后续判据的依据）

1. 秤空载、稳定时：抓 ≥ 20 帧，另存为十六进制原样文本（`.hex` / `.log`）。
2. 逐项抓：稳定、不稳定（用手压称盘晃动）、去皮前后、负重（去皮后移走货物 / 去皮后放轻物）、零点、**超量程**（放超过量程的重物，注意安全）、秤断电重启、拔线再插。
3. 抓到的帧和下面「预期」对：长度、起止标记、符号位、小数点、单位、稳定标志位置。**不一致就改协议配置，不要改帧去迎合配置**。
4. 把真实帧补进 `tools/scale-simulator/scale_sim.py` 的 `scenarios()`，重新 `dump-fixtures`，让模拟器和测试以后覆盖真实格式。

## 3. 预期读数（模拟器按种子样例生成，真秤要逐项对）

| 场景 | 柯力样例帧 | 预期解析 | 判据 |
|---|---|---|---|
| 稳定 | `+001240 kg S\r\n` | 124.0 kg，稳定 | 称盘放已知砝码，系统读数与秤显示一致到最小分度 |
| 不稳定 | `+001245 kg U\r\n` | 124.5 kg，不稳定 | 晃动称盘时 `stable=false`；**报工不得采用该读数** |
| 零点 | `+000000 kg S\r\n` | 0.0 kg | 空盘读数 0 是真实读数，不是「没读到」 |
| 去皮后负数 | `-000520 kg S\r\n` | −52.0 kg | 符号保留 |
| 克 | `+015000 g  S\r\n` | 1500.0 g → 系统换算 1.5 kg | 报工里是 1.5 kg |
| 超量程 | 未知（模拟器代表帧 `+OOOOOO kg U`） | 拒绝，错误码 `OVERRANGE` | **现场抓真实帧**；任何情况下不得读成数字 |

耀华样例 `=+00125.40 kg S\r\n` → 125.40 kg 稳定；Modbus 应答 `01 03 04 00 00 04 D2 78 AE` → 12.34 kg（`int32/100`，**若真秤是 FLOAT32，这条要改**）。

## 4. 整链验证（G1 网关就位后）

| 步 | 做法 | 预期 / 判据 |
|---|---|---|
| 4.1 | 网关连秤，发 MQTT 到 `cretas/F006/device/{deviceId}/data`，body `{"type":"WEIGHT","data":{"weight":..,"unit":"kg","stable":true/false}}` | broker 订阅能看到消息；`mqtt.enabled=true` 的测试后端日志出现「称重数据」 |
| 4.2 | 查 `iot_device_data` 与 `factory_equipment.last_weight_reading` | 有新记录、最近读数 = 秤显示（kg） |
| 4.3 | 在测试厂启动一个工位（`scaleDeviceId` 指这台秤），称盘放已知重物稳定后点手动计数 | 计数结果的 `productWeight` = 秤显示 |
| 4.4 | 称盘晃动时点手动计数 | 提示「没读到秤重量」，总重不增加，**不是 0** |
| 4.5 | 拔秤的线，等 1 分钟，再点计数 | **当前会仍用旧读数（缺口 G3）**：记录实际行为，别当通过；和 Steve 定过期规则后再改 |
| 4.6 | 插回线 | 网关自动重连，新读数继续进库（断线重连）；记录重连耗时 |
| 4.7 | 故意制造坏帧（拔线瞬间、干扰、改波特率） | 网关丢弃，库里没有 0 kg 记录；网关日志有拒绝计数 |

## 5. 联调完成的判据

- §0 全部有记录；§2 抓到的真实帧已补进模拟器 fixtures 并被测试覆盖。
- §3 每个场景系统读数与秤显示一致（或明确记录偏差原因）。
- §4.1–4.4、4.6、4.7 通过；4.5 记录实际行为并有结论。
- 种子协议配置按真实帧用迁移修正，`ScaleSeedConformanceTest` 对应断言删除。

## 6. 本地先用模拟器预演（不需要真秤）

```bash
python tools/scale-simulator/scale_sim.py serve --protocol KELI_D2008_ASCII --port 9100 --scenario weigh_cycle --drop-after 40
```

网关或串口调试工具连 `127.0.0.1:9100`，能看到「抖动 → 稳定 → 回零」循环，`--drop-after` 到点断线，用来预演重连。`--scenario corrupt_mix` 混入坏帧。
