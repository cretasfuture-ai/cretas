## 3. 判据：什么条件下才问（⛔ 这才是本卡的正文）

**三条同时成立才追加，任何一条不成立就闭嘴。**

| # | 判据 | 为什么是它 |
|---|---|---|
| 1 | `laggard.delta_revenue < 0` 且 `\|Δ\| / bench_revenue >= 阈值` | 差距要有实质规模。⛔ 阈值**现在不拍数**，等有真实分布再定（见 5.2） |
| 2 | `primary_cause == "客流"` | 差在**人少了**。客单价差是内部可解释的（折扣/菜品结构/渠道），⛔ 不该拿商场活动去搪塞 |
| 3 | 能解释「为什么人少了」的外部维度**全在** `missing_dimensions`：`physical_traffic` / `mall_activity` / `nearby_event` / `competitor` | **有数据就用数据答，⛔ 不反问。** 反问只在我们确实看不见时才诚实 |

▎判据 2 是防噪音的主力：它把「⑤ 会不会变成每次都追一句的废话」这个问题
▎**变成一个由数据回答的问题** —— 客单价型的差距一律不问。
▎📏 在 MOCK_REST 上它的效果是 **0/32 触发**（不是噪音），
▎但这同时意味着 **0 个可验收样本**（见第 4 节）。

判据 3 有个自我了结的性质：**一旦接入客流数据源，⑤ 自动退场**，
因为那时该走「用数据答」。⇒ ⑤ 是一步**临时**的诚实，不是永久设计。

## 4. 三个选项、代价、裁定

| | 做法 | 代价 |
|---|---|---|
| **A** | 按第 3 节三条判据，在接地闸**之后**确定性追加一段（同 `_append_investigation_directions` 的形状，2 个接线点） | 判据在今天的数据上**一次都不会触发** ⇒ 无法验收反目标那句「命中的那个店，老板去查会不会一无所获」 |
| **B** | 写进 prompt，让 LLM 自己决定问不问 | 不确定、不可测；📏 且本轮实测**叙述被接地闸整份驳回 17/32 (53.1%)，完整链只送达 3/32** ⇒ B 的送达率上限就是那 9.4%。等于把「会不会变成废话」和「会不会送到」一起交给模型 |
| **C** | 不上线，判据写进设计卡，等有能让它触发的租户再做 | 这一步继续缺着；老板暂时拿不到「线下变化」这条线索 |

### 裁定：**C**（维持，本轮独立复核后仍是 C）

**理由（按分量排序）**：

1. **反目标那句话我答不上来。** 「排在最前面的那个命中，老板去查会不会一无所获？」
   —— 📏 **没有命中样本**（0/32）。
   ⛔ 「不知道会不会误发」就上一条**会主动向老板提问**的提示，
   赌的是「这东西说的话能信」——本仓最贵的那笔本钱。
2. **唯一有数据的租户上，判据由构造为假。** MOCK_REST 主因恒为客单价、
   Δ 只有 1.5~2.0%、**客流效应还是正的** ⇒ 在它上面「不触发」**证明不了任何事**
   （形态 B⁴：闸在验收环境里是恒真式）。⛔ 不能拿它当验收通过。
3. 🔴 **而那个唯一的租户本身就是模拟的**（登记名「假 POS 数据接入验证」，
   prod 上餐饮租户总数 = 1）。⇒ 现在连「误伤率」这个问题都**问不出口**。
4. **⛔ 不为只有种子数据支持的形状建检测器** —— 那是在建幻觉。
   本条在 2.5 之后从「原则」变成了**当下的事实描述**。

### 🔴 裁定的补充条款（本轮新增，由 2.2 的读数逼出来）

**将来解冻时，载体只能选 A，⛔ 不能选 B。** 两条理由：

- B 的送达率被接地闸压到 9.4%（完整链 3/32），而一条**时有时无的反问**比没有更糟
  （老板问同一句话，这次被问了、下次没被问）。
- 更要紧的：⑤ 是一句**我们对自己看不见什么的声明**，它必须由判据说出口，
  ⛔ 不能由模型即兴决定 —— 「说不说」和「说得对不对」不能一起交出去。

⚠️ 但 A 也有一个**本轮才量出来的缺口**：接地闸毙掉叙述时，
现有的确定性追加（⑥⑦）**也一起消失** —— 因为它们和被驳回的叙述
**在同一个字符串里**，被外层整份替换（定位见 2.2）。

⇒ 解冻做 A 之前，必须先确认 ⑤ 挂在**拒答之后仍然会执行**的位置
（即：外层替换 `answer_text` 之后再追加，而不是在 `synthesize()` 内部），
否则 ⑤ 会继承同一个 53.1% 的接地闸静默率。**这一条是解冻的前置，不是可选项。**

▎🔑 反过来看，这也是 ⑤ 最该被放在拒答旁边的理由：
▎老板拿到那 129 字拒答时，**正是他最没有线索的时刻** ——
▎而 ⑤ 恰好是一条**不依赖叙述、只依赖三条结构判据**的线索。

## 5. 能让判据红的对照（⛔ 不是「测试通过」）

### 5.1 解冻后照这个验收，一条都不能省

先造一份三条判据**全部成立**的 FactBook（真实租户优先；⛔ 不用 MOCK_REST），
确认那段话出现。然后逐条打掉，**每一条都必须让它消失**：

| # | 变异 | 期望 | 它守的是 |
|---|---|---|---|
| M1 | `primary_cause` 客流 → 客单价 | 那段话**消失** | 判据 2：客单价型不许拿商场活动搪塞 |
| M2 | 把 `mall_activity` 从 `missing` 挪进 `available` | 那段话**消失** | 判据 3：有数据就用数据答 |
| M3 | 把 `delta_revenue` 缩到阈值以下 | 那段话**消失** | 判据 1：差距要有实质规模 |
| M4 | 三条全成立（不变异） | 那段话**出现** | 阳性对照：⛔ 否则前三条「消失」可能只是它从来没出现过 |

**M4 不能省** —— 没有它，M1~M3 全绿也可能是因为那段话**根本不会出现**
（本仓的恒真式前科）。

### 5.2 变异纪律（⛔ 每条都要，不是提醒）

- **变异不红时，先证明变异真的到达了被测代码**，再下「断言没用」的结论。
  做法：变异后先把代码**实际读到**的那个值打出来，确认它变了。
- ⛔ **红在 `NameError` / `NoneType` 上的变异不算数** —— 那是把代码弄坏，
  不是移除被守的行为。红的那一条必须是**判据本身**。
- ⛔ 阈值**不许现在拍**。等出现真实分布再定，
  否则 M3 验的是一个我们自己编出来的数。

### 6.2 草案

```
### 这家店少的是客人，不是客人花的钱

模拟·XX店比门店平均少了 N 万。拆开看，来的客人少了，
而每位客人花的钱和别家差不多 —— 所以差距出在**人少了**。

人为什么少了，这几条线索现在都还没接进来：门口经过多少人、
商场那边有没有搞活动、周边有没有演出或施工、对面有没有新开店。
**这些事只有你在现场才知道，我看不到。**

- 你现在能做的：想一下最近这家店周边有没有变化 ——
  商场活动、路面施工、对面新开的店、公交地铁改道。
  是这几件里的哪一件，直接告诉我，我按那个方向再算一遍。
```
