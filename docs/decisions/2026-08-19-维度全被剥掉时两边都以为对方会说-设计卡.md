# 设计卡 · 维度全被剥掉时，两边都以为对方会说

**日期**: 2026-08-19
**口径**: MOCK_REST / prod `smartbi_prod_db` / `_dimension_not_served`（2 轮逐轮一致）
⚠️ 评测题库口径，⛔ 不是真实流量。

---

## 一 · 老板看到的（prod 原文）

问：**「最近30天哪家店折扣给得最多」**

```
**折扣力度（2026-07-21 至 2026-08-19）：**
- 折扣占营收 4.5% / 折扣总额 ¥939,770
**构成：** …金额最高的前 3 种（美团团购套餐券、大众点评双人餐券…）
| 折扣类型 | 金额 | 占折扣 |
| 美团团购套餐券 | ¥198,149 | 21.1% |
```

▎他问「**哪家店**」，拿到「**哪种券**」，**一个字没提「按门店拆不出来」**。
▎与静默顶替同族：**换了个问题回答**，而他不知道。

## 二 · 🔴 这是**同日另一处改动引入的回归**

`RESTAURANT_OPS_DISCOUNT_SUMMARY` 的能力表是 `[]`（一个维度都不支持），
而 `_dimension_gap_advice` **本来就有**正好对应这一格的分支：

```python
if not supported:
    return f"你这句要按{extra}来看，而这次选中的算法不按维度拆，只能给一个整体结论。"
```

本地 A/B（同一个 spec，只切 `caller_judged`）：

| | `dropped` | `_dimension_gap_advice` | `_partial_grain_note` |
|---|---|---|---|
| 剥之前（今天之前的形状）| `()` | 「你这句要按门店来看…只能给一个整体结论。」 ✅ | — |
| 剥之后（今天）| `('store',)` | `''` | `''` 🔴 |
| 阴性：老板点了名的门店 | `()` | 同第一行 ✅ | — |

成因：`_drop_unanswerable_mislabeled_dimensions` **今天**把「门店那一格」接了进来
（为「哪家店缺货最严重」那一刀），而 `_partial_grain_note` 在
「能算的一层都不剩」时返回空串**让位给整份拒答**——
▎**剥维度这个动作把那条路的输入清空了**（advice 看的是剥完之后的 spec）。
▎**两边都以为对方会说。**

⚠️ **全量回归没抓到** —— 没有任何断言守着「`supported` 为空」这一格。
   ⇒ `test_dropping_every_grain_still_says_so.py` 补上它。

⚠️ 形态归类：这是形态 B 的一个**新变体** ——
   不是「产出端有了、消费端收不到」，是**上游把消费端的输入清空了**。

## 三 · 修法（⛔ 不造第二份措辞）

`_dimension_gap_advice` 的语义是「**你问的**那一层拆不出来」——
它的输入天然该是**老板问的**维度，⛔ 不是执行侧适配之后剩下的那些。
剥维度是适配，不该改变「老板问了什么」这个事实。

⇒ `_partial_grain_note` 在 `both` 为空时，把被剥掉的那层**加回去**再问
**同一个** advice。⛔ 不在这里另写一句：advice 那三支的措辞是拿 prod 实测
**打磨过两轮**的（两次都是因为它在编机制 / 硬编码建议词）。

对老板的含义不同，⛔ 不许混成一句。

## 六 · 同一轮量到、**本卡不做**的两条（登记）

   ⇒ 没踩到维度空白格），但老板问的是**毛利**，拿到的是**营收 / 单量**表。
