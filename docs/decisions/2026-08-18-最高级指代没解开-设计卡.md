## 二 · 「最差的那家店」到底被谁当成了没指定门店（实测，⛔ 不是读码）

姊妹缺陷（「有几家店是亏钱的」）的落点是**确定性抽取器**。
⛔ 这次不假设一样，探针钩了三层分别读。

### 读数（3 轮 × 8 句 = 24 次，S 组 = 含最高级指代）

| 层 | 读数 | 结论 |
|---|---|---|
| LLM 提名的门店 `store` / `stores` | **0/24 次给出店名** | ❌ 不是「LLM 把它当成了店名」 |
| 确定性抽取器 `extract_store_mentions` | **3/24**，只有「拖后腿的那家店」这一句 | ⚠️ 次要来源，见下 |
| LLM 的 `dimensions` | **24/24 都含 `store`** | 🔑 模型**判对了**：这是按门店拆的分析 |
| LLM 的 `store_scope` | 给 `'all'` 的 13 次**全部作答**；留空的 11 次**全部反问** | 🔴 飘的是这一格 |

▎**稳的是 `dimensions`，飘的是 `store_scope`。** 同一句话在三轮里两种归宿，
▎而两次的 `dimensions` 一模一样。

### 拦截方**有两个**，不是一个

把模型原始 JSON 的 `missing_fields` 也读出来之后（它到不了 `_build_spec`，
只在 `_semantic_spec_from_t3` 的入参里看得见）：

| 拦截方 | 长相 | 次数（A 组基线，24 次） |
|---|---|---|
| ① 模型自己报 `missing_fields` 含 `store_scope` | `planner_authority='llm'`，反问是模型**自撰**的自由文本（每轮措辞都不同） | 8 |
| ② 下游 `_apply_store_scope_guard` | 模型没报缺项、但 `store_scope` 为空 ⇒ 这道闸自己问一句固定文案 | 3 |

⚠️ 两个拦截方的**根子是同一个**：`store_scope` 这一格空着。
⇒ 判据必须挂在 `dimensions` 上（两条路都接得住），
⛔ 不能只挂在 `missing_fields` 上（那只接得住 ①）。

### 对照组（C 组：真的没指定门店，反问是**对的**）

```
生意下滑了怎么办 / 怎么提升营收   →  raw dimensions = ()   12/12 次
```

▎**模型自己就把这两类分开了**：真该问门店时它给的 `dimensions` 是空的。
▎prompt 里那条「多门店账号未指定门店范围应追问门店」的 few-shot 示例 4
▎（「这周营收怎么提高」）给的也正是 `"dimensions": []`。

## 三 · 三个选项

### 选项 1 · 往词表里补「最差 / 垫底 / 拖后腿」

`extract_store_mentions` 里已经有一张排名/极值黑名单
（`最高 最低 最好 最差 排名 排行 客单价 营收`）—— 正因为它有「最差」，
「最差的那家店」才没被当成店名；正因为它没有「拖后腿」，
「拖后腿的那家店」**被**当成了店名（实测 3/3 轮）。

- **代价**：下一个措辞又炸（垫底 / 掉队 / 拉胯 / 最弱 / 吊车尾）。
  那个函数自己的注释就写着这一类「应该换成封闭集合，单独登记、单独做」。
  而且它只治得了拦截方 ②，对 ①（8/24）一个字都不管。
- ⛔ **不采纳**。owner 已裁定不复活关键词路由；往词表加词是同一件事的小号版本。

### 选项 2 · 给 LLM 契约加一个「计算式指代」字段

例如 `"store_selector": {"rank": "worst", "metric": "revenue"}`，
代码收到后先按指标排序算出 laggard、再跟门店目录核对、填进 `store_slots`。
这是缺口 #19 记的那件事，也是架构上最完整的形状。

- **代价**：(a) 要改 prompt + 契约 + 校验 + 一条新的算 laggard 的路径；
  (b) 新字段的模型依从率**没有量过**，而本轮实测同一个模型在
  **已有**字段 `store_scope` 上就在翻面（11/24 ↔ 13/24）——
  新字段大概率同样不稳，那就等于把一个不稳的输入换成另一个不稳的输入；
  (c) 排序要用哪个指标、哪个窗口，在规划阶段还没定，是个鸡生蛋。
- ⏸ **本轮不做，挂账**（解冻条件见第七节）。

### 选项 3 · 用**稳的那一半**推出**飘的那一半** ✅ 采纳

```python
if (
    "store" in tuple(dimensions or ())      # 模型自己判定: 这是按门店拆的分析
    and not store_scope
    and not store_names                     # (冗余防线, 见下)
    and len(tuple(available_stores or ())) > 1        # 查: 目录里真有多家店
    and _resolver_serves_dimensions(code, ("store",)) # 核对: 能力表说它出得了
    and not is_continuation
):
    store_scope = "all"
    store_scope_defaulted = True            # ⛔ 披露, 不偷偷替他选口径
    missing_fields = tuple(f for f in missing_fields if f != "store_scope")
    clarification_options = _validated_llm_clarification_options(...)  # 按钮跟着缺项走
    if clarification_needed and not missing_fields:
        clarification_needed = False        # 模型自报的缺项没了 ⇒ 这句反问不再诚实
```

**为什么这是「查/算」而不是「猜」**：
判据取自**模型自己的语义输出**（`dimensions`），代码只做两件确定性的事 ——
**查**租户门店目录、**核对**能力表。⛔ 没有一个中文词进入判据。

**为什么按门店拆 ⇒ 范围就是全部门店**：
按门店拆的计划对**每一家**店都出数，排序本身就指出「最差的那家」。
一个 store-grain 的计划不可能同时缺「你指的是哪家店」——
那是模型输出的两半在打架。

**剩下的缺项自动交给既有机制**：`store_scope` 摘掉之后缺项收缩成
`('time_range',)`，既有的「只缺时间 → 补默认窗口并明示」那一格接住。
⛔ 没有新建第二条默认通道。

### 🔴 M2 的教训（值得单独记）

第一版 M2 打的是 `and not store_names`，变异后**一条都没红**。
差一步就写成「对照② 是恒真式」。真相是**变异没有改变行为**：

```
上游 `if store_names and not store_scope: store_scope = "single"`
⇒ 点名门店时 scope 已是 single ⇒ 我这里的 `not store_scope` 先短路
```

把靶子挪到 `not store_scope` 上（M2a）—— **仍然不红**，因为这回换成
`not store_names` 拦住了。**两条互为备份，单独去掉任何一条都不红。**
只有 M2b（两条同时去掉）才让对照② 变红。

▎**「变异不红」有三个成因，症状一模一样**：断言恒真 / 变异没生效 /
▎**判据里有两把锁**。第三种本轮第一次遇到，已在产品代码里显式登记
▎`not store_names` 当前不承重、为什么仍然留着。

## 七 · 没做的部分 + 解冻条件

| 没做 | 为什么 | 解冻条件 |
|---|---|---|
| **选项 2**（LLM 契约加 `store_selector`，真的算出 laggard 填进槽位） | 新字段依从率没量过；而实测同一模型在**已有**字段上就在翻面。且排序指标/窗口在规划阶段还没定 | 先量一次：给现有 prompt 加一个**只读不用**的字段，跑 ≥30 次数依从率。**≥90% 才谈落地**；<90% 说明换字段解决不了不稳定，该改的是别处 |
| **排名/极值词退役成封闭集合**（`extract_store_mentions` 里那张黑名单） | 本轮实测它只影响 3/24，且已被本块兜住（`store_scope` 一旦定成 `'all'`，`store_slots` 里那个假店名在执行时由既有的 `_mentions_backed_by_catalogue` 丢掉） | 出现「假店名进了 SQL 过滤条件」的实测证据时做。⛔ 在那之前不做 —— 那是一张永远补不完的表 |
| **B 组剩下的 2/24 反问** | 它们的 `missing_fields` 含 `metric`，而**指标没有无歧义的默认值**。补错等于给一个看着像答案的错答案 | ⛔ 不解冻。这两次反问是**对的** |
| **模型自撰反问的措辞审查** | 模型每轮自己写反问文本（「你想看哪个时间范围？以及具体是哪家垫底的门店？」），本轮没有量它的措辞合规性 | 另立一条线。与本卡正交 |
| **多租户验证** | 本轮只跑 MOCK_REST。⚠️ 按「MOCK_REST 只做冒烟」那条常设配置，这是**冒烟不是验收** | 在脏样本上重跑一次：`RES_3101_009`（38 店）与 `DEMO_REST`（27 店）。⚠️ 判据要挑**能让它红的**样本 —— 单店租户（若有）能让 M4 那条守卫真的开火 |
