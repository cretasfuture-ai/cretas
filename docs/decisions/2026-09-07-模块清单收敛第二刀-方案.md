## 1. 四刀，各一 PR，各降一次基线

### 刀 A：删 `web-admin/src/utils/permission.ts`（−6，零风险）

[RUN] 2026-09-07：`grep -rn "from '@/utils/permission'"` 在 `web-admin/src` 里 **0 个调用方**（文件自己的注释也写着「未见任何组件 import —— 疑似死代码」）。它内含第三份 role×module 矩阵（legacy `read_write` 值域）+ 平台管理员内联数组。
- 做法：删文件 + 闸里那份清单从 9 份降到 8 份 + 基线 27 → 21。
- 阴性对照：`vue-tsc -b` 与 vitest 全绿（0 调用方，本来就该绿）；闸的 INSTRUMENT ALIVE 地板照旧。
- ⚠️ 不删就是「留着一份没人读的真相」——正是形态 D 的温床。

### 刀 B：L1/L2 写白名单补 `operations`（−2，🔒 权限）

L1 有 5 行 `operations`（operations_coordinator rw、permission_admin rw 等），`PermissionServiceImpl.ALL_MODULES` 有它，只是两份写白名单没有 ⇒ step-2 页面上 `operations` 列今天**写不进去**（400 无效模块）。
- 做法：两份 `ALLOWED_MODULES` 各加 `"operations"`（它们逐字相同，闸钉着相等）；基线 21 → 19。
- 契约：写服务对 `viewer × operations = r` 能写（今天 400）；阴性照旧（餐饮格、`ai`）。

### 刀 C：web fallback 矩阵改为**从 L1 快照生成**（−3 −4，接口键与 store 数组一起收敛）

今天 `store/modules/permission.ts` 的 `PERMISSION_MATRIX`（26 角色 × 20 键手写）只在 DB 权限**竞态 / 离线 / 接口失败**窗口里生效，但它是 `ModuleName` 类型与 `getAccessibleModules` 内联数组的根：三份互相咬着，手改一处就漂。
- 做法（照 #654 的 RN 做法）：`frontend/CretasFoodTrace/src/utils/permissionMatrix.l1Snapshot.json` 已是 prod L1 的只读快照（488 行 / 30 角色 / 23 模块码，带 `exportedAt`），web 直接 `import` 它生成 fallback：
  - `PERMISSION_MATRIX` = 快照 `levels`（值域已是 rw/r/w/-，无需转换）；
  - `ModulePermissions` 接口保留为类型但键从快照模块码派生（`keyof typeof snapshot.levels[role]` 做不到跨角色并集 —— 改成 `Record<string, PermissionLevel>` + 一个从快照现算的 `MODULE_CODES` 常量给 `ModuleName` 用）；
  - `getAccessibleModules()` 的内联数组换成 `MODULE_CODES.filter(canAccess)`。
- 既有闸 `permission.fallback-matches-l1.spec.ts` 比的是「fallback vs 带标记的最高 Flyway 迁移」（只钉餐饮四部门 20 格）——生成之后它恒绿；改成比「fallback === 快照」即可（或删掉，因为来源已是同一份）。
- 餐饮：快照里餐饮角色/模块的格**原样带过来**（不动不删不补），与 owner 边界一致；`FACTORY_TYPE_MODULE_FILTER` 与四部门 `min(restaurant, 部门)` 逻辑不动。
- ⚠️ 风险点要先量：fallback 只在 DB 未加载窗口生效，但 `ModuleName` 类型收窄/放宽会影响编译期——`vue-tsc -b` 是判据；`cashier` 等只有 4 行的角色在快照里 `finance=rw`，与今天手写 fallback 的 cashier（2026-06-11 演示预跑那条注释）要逐格 diff 贴出来，差异由 owner 认。
- 基线 19 → 12（接口键 3 + store 数组 4 归零）。

### 刀 D：角色权限页补 6 列（−12，UI 变宽）

`RoleController.DISPLAY_MODULES` 与 `roles/list.vue.allPermissionModules` 各加 `analytics 数据分析 / inventory 库存 / operations 运营 / rd 研发 / scheduling 排产 / work_report 报工`（两份逐字相同，闸钉着）。
- 用户可见：角色权限对话框从 11 列变 17 列；`operations` / `work_report` / `report` 在 web 没有页面但权限本身存在（RN 用），列上照显示 L1 值。
- 或者更彻底：`DISPLAY_MODULES` 改为从 L1 现算（`platformRepo.findByDeletedAtIsNull()` 的模块码 − 餐饮），list.vue 从接口取列——那就消灭了这两份清单（−12 且以后不漂）。**推荐这一种**，多一次查询无代价。
- 基线 12 → 0。
