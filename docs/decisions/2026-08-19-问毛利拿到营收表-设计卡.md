# 设计卡 · 问毛利拿到营收表 —— 契约闸被一句「建议」满足了

**日期**: 2026-08-19
**口径**: MOCK_REST / prod / `_metric_not_served`（4 轮逐轮一致）+ `_margin_by_channel_full`（贴全文）
⚠️ 评测题库，⛔ 不是真实流量。

---

## 一 · 老板看到的（修前，prod 原文）

问：**「最近30天外卖和堂食的毛利分别是多少」**

```
**堂食 vs 外卖（2026-07-21 至 2026-08-19）：**
| 渠道 | 营收 | 营收占比 | 单量 | 单量占比 |
| 堂食 | ¥13,386,440 | 63.6% | 36,381 | 62.2% |
…
往下可以拆开看：堂食和外卖各自的每单平均消费、**毛利分别是多少**。
```

▎全文 1031 字，「毛利」只出现 **1 次**、在第 **942** 字 —— 而且是在**建议**里。
▎**产品把他刚问的那个问题，当成「下一步可以问什么」推荐回给了他。**

## 二 · 系统**知道**，只是没说

```
requested_metrics = ['gross_margin']   wants_margin = True
系统知道他要毛利 = 4/4      最终没给毛利的数 = 4/4
阳性对照: 能给毛利的问句 2/2 真给了
```

⇒ 知识在 `spec` 里，**没有投影到用户侧** —— 形态 B 又一例。

## 三 · 🔴 既有的契约闸为什么放行

`answer_contract._request_coverage_present` **已经在遍历** `requested_metrics`：

```python
for requirement in spec.requested_metrics:
    tokens = _REQUEST_TEXT_TOKENS.get(requirement, ())
    if tokens and not _contains_any(answer_text, tokens):   # ←「提到了这个词」
        return False
```

`gross_margin` 的 token 是「毛利率 / 毛利 / 利润」，而**那句建议里有「毛利」两个字** ⇒ 闸过。

▎**同一个子串陷阱，这次在生产代码里：「提到」≠「给了数」。**

## 四 · 修法（⛔ 不动那道闸）

那道闸管着**全部指标 × 全部答案**；把它收紧 ⇒ 闸红 ⇒ 老板拿到的是**拒答**，
而不是「营收表 + 一句说明」。⇒ 这里只做**投影**（`_metric_gap_note`）。

- 判据是**结构**的：表头含该词，**或**该词近旁 24 字内真有一个数
- token **复用** `answer_contract._REQUEST_TEXT_TOKENS`（⛔ 不造第二份）
- 判不了的指标（token 表里没有）**一律不动**
- 标签取**他自己问句里的那个词**（问「毛利率」就说「毛利率」）
  ⛔ 不用 `METRICS.label` —— 实测 `METRICS` 里**根本没有** `gross_margin`
  这个键（14 项，与 `requested_metrics` 的 key 空间不是同一套；
  那是既有的形态 D，本卡**不动它**，但也不依赖它）
- ⛔ **不编机制**、⛔ **不给假出路**（今天刚栽过一次「建议他做他已经做过的事」）

## 五 · prod A/B

```
修前  正文第一句: 「**堂食 vs 外卖（…）：**」        ← 他问毛利，一个字没提
修后  正文第一句: 「**这次这条路给不了毛利的数**，下面是它能算的那些。」
```

⚠️ 探针的「给了毛利的数 = 4/4 False」**修后没变，而那是对的** ——
它量的是**能不能给**，我修的是**说不说**。两件事，⛔ 不能折叠。
⇒ 守望那条改成同时守两半：`没给毛利·已说明` /（退化）`没给毛利·没说明` /
（能力补上）`给了毛利`。
