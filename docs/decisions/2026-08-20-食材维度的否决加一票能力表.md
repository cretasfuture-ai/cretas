# 食材维度的否决：加一票能力表（⛔ 不是删掉它）

**日期**: 2026-08-20
**文件**: `backend/python/smartbi/gold/restaurant/restaurant_intent.py`（`_build_spec`）
**口径**: 本刀的证据是**本地单测对照**；prod E2E 的读数是「**观察不到差异**」，
⛔ 不是「量到了改善」。理由见下面「开火面」。

---

## 交给我的方向，与我实测到的东西不一致 —— 先说这个

交接件写的是：

> 真问题在上游 —— **没有 resolver 服务 ingredient 粒度**。删掉这 6 个词的否决，
> 让能力表 + 已有的 `_partial_grain_note` 说实话。

**这条链实测接不上。** 我先照着做了（删掉整段），然后量了一次：

```
q = 「水煮牛肉的成本是多少」  LLM 计划 dimensions=["ingredient"] dish="水煮牛肉"

删掉之后:
  spec.dimensions = ('ingredient', 'dish')   plan = ('RESTAURANT_OPS_GROSS_MARGIN',)
  _drop_unanswerable_mislabeled_dimensions -> dims=('ingredient','dish')  dropped=()
  _query_names_an_ingredient('水煮牛肉的成本是多少') = True   ← 「牛肉」是「水煮牛肉」的子串
  _partial_grain_note(...) = ''
```

`ingredient` **没有**被下游剥掉，因为下游的点名判定
`_query_names_an_ingredient` 在菜名里子串命中食材名，**假阳性**，
判成「老板点名了食材 ⇒ 不许剥」。于是 `dropped=()`、note 空、
最终落到执行前口径闸的整份拒答（prod 实测同形状 60 字：
「我准备算的东西跟你问的对不上，所以这次我没敢算。」）。

▎**删它 = 把「答非所问」换成「不回答」** —— 本模块自己裁定过那不是修复。

---

## 两种立场（按要求都写出来）

### 立场 A（代码自己的）：现状更好

「把答非所问换成不回答不是修复。」剥掉之后老板至少拿到菜品层的一份真数
（prod 实测 1107 字，含成本卡覆盖率与异常提示）；不剥掉他拿到 60 字拒答。

**支持它的读数**：上面那条链。删掉之后**确实**变成拒答。

### 立场 B（交接件的）：静默降级更贵

「他问食材层，拿到菜品层而**没有一句话**解释，下一次会以为那就是食材层的答案。」
这条立场在本仓已经被 owner 采纳过一次 —— `_partial_grain_note` 整个函数
就是为它写的。

**支持它的读数**：同一份 LLM 计划、只差「食材」二字，结局完全不同，且前者无声：

```
「水煮牛肉的成本是多少」     -> dims=('dish',)               无声改写成 GROSS_MARGIN
「水煮牛肉的食材成本是多少」  -> dims=('ingredient','dish')   撞口径闸, 60 字拒答
```

### 我选的：**都不选整个** —— 只做严格收窄

两种立场分歧在「剥不剥」，而它们**都同意**一件事：
**决定权不该在 6 个中文词手上**。所以这一刀只动那一票：

```python
if (
    deterministic_dish
    and "ingredient" in dimension_list
    and not any(token in effective_query for token in (
        "食材", "原料", "配料", "采购", "领料", "库存"))      # ← 照旧，理由见下
    and not _resolver_serves_dimensions(code, ("ingredient",))  # ← 新增的那一票
):
    dimension_list.remove("ingredient")
```

净效果：开火面**只小不大**，而变小的那一块正是
「**LLM 对了、而且选中的 resolver 真能按食材出**」的那一块。

| 输入 | 今天 | 改后 |
|---|---|---|
| 菜名 + `RECIPE_COST`（能力表 `{dish}`） | 剥 | 剥（**未碰到的那一半**） |
| 菜名 + `SUPPLIER_PRICE`（能力表含 `ingredient`） | **剥** | **不剥** ✅ |
| 说了「食材」 | 不剥 | 不剥 |
| 没有 `deterministic_dish` | 不进这条 if | 不进 |

---

## ⛔ 为什么那 6 个词**不能**换掉（第二个被否掉的方案）

我也试过「把 6 个词**换成**能力表」。**当场制造回归**：

```
extract_dish_candidate('按食材拆一下这个月的成本')  ->  '按食材拆一下'
extract_dish_candidate('这个月食材成本是多少')      ->  '食材'
```

`deterministic_dish` 在**纯食材问句**上是假阳性，今天正是那 6 个词在挡它。
换掉它们，`按食材拆一下这个月的成本`（prod 实测今天答得好好的，303 字食材成本表）
会被剥成菜品层。

🔑 **那 6 个词不是随手写的逃生口，它在补上游抽取器的假阳性。**
真正的修法在 `restaurant_ops_router.extract_dish_candidate` —— ⛔ 不是本文件
（本轮明确只碰 `restaurant_intent.py`）。

## 开火面（⛔ 不吹大）

prod MOCK_REST 评测题库、34 次运行，这一刀**开火 0 次**：
需要 `deterministic_dish`（句式匹配的菜名）与 LLM 给 `ingredient` 同时成立，
而实测模型在**点了菜名**的句子上一律给 `product`、只在**没点菜名**时给 `ingredient`
—— 两个条件在真实模型输出上几乎互斥。

⇒ 本刀的 E2E 前后对比是「**观察不到差异**」。
  能拿出的证据是单测里那对同计划、不同 resolver 的对照。
  ⚠️ 这也解释了交接件读到的「51 对里只开火 8 次、全在同一个问句上」。

## 变异对照

`/tmp/mut1.py` 撤回那一票能力表（锚点恰好 1 次；文本模式 + `newline=''`）。

**先证明行为真的变了**：

```
变异后  dims=('dish',)               intent=RESTAURANT_OPS_GROSS_MARGIN
撤回后  dims=('ingredient','dish')   intent=RESTAURANT_OPS_SUPPLIER_PRICE
```

断言：**1 红 6 绿**。红的正是那条承重（能力表说能出就不许剥）；
6 绿是前提断言 + 三条对照 + 两条「把被否掉的方案钉住」的读数 ——
它们在两侧都该绿。

⚠️ 按本仓 2026-08-19 的教训（「往判据的 AND 链里加第三个条件后，
原来守着另外两半的阴性对照全部变红 0 条」），三条对照的输入是**分别**
落在被测的那一半上的，且各带一条前提断言（`test_the_pieces_of_the_criterion_are_not_constants`）。

## 🔴 两个未了的半边（⛔ 不假装解决了）

### (a) 静默降级还在

剥掉这一层仍然**一个字都不说**。投影点 `_partial_grain_note` 在
`restaurant_intent_service.py`，本轮不碰那个文件（有并行线在改）。

**解冻条件**：能在 `restaurant_intent_service` 侧把「`_build_spec` 剥掉的粒度」
也喂进 `_dropped_grains` 时，把它接上，然后本条作废。

### (b)「说没说食材二字」仍然改变结局

根因是 `restaurant_ops_router.extract_dish_candidate` 的假阳性。

**解冻条件**：该函数不再把 `按食材拆一下` / `食材` 当菜名之后，
这 6 个词就可以撤掉，那时**同一份计划同一个结局**。
⇒ 这条被 `test_why_the_six_words_cannot_go` 钉住了：那两个读数一变，测试当场红，
下一个人会被带回这张卡。

### 还有 (c)：「直接删掉」的解冻条件

`_query_names_an_ingredient` 不再把菜名里的食材子串当成点名之后，
「删掉整段、交给下游剥并说」那条路才成立。
⇒ 被 `test_why_not_just_delete_it` 钉住。
