# 设计卡 · 同一句话问两次，一次给答案一次反问

**日期**: 2026-08-19
**租户/口径**: MOCK_REST（10 店 / 101,768 笔 POS），prod `47.100.235.168:8083`，`smartbi_prod_db`
**探针**: `smartbi.scripts._flipflop_layers`（五层逐轮记全 + 派生谓词层）
**A/B**: `smartbi.scripts._flipflop_supplier_ab`（两棵源码树，`diff -rq` 证明只差 1 个文件）
**变异**: `smartbi.scripts._flipflop_mutate`（4 条 × 全部 12 条断言，三层全过）

**分支**: `codex/claude-flip-flop`，基底 `dc2f56d864`

## 〇 · 一句话结论

> **翻面本身发生在模型侧（L0/L1），代码各层是确定性的；
> 但把「模型换了一个词」放大成「两种完全不同的产品行为」的那一段，在代码里。
> 本轮修掉了可以修的那一段，另一段登记挂账 —— 因为它现在没有可信的验收窗口。**

## 一 · 现象（老板会看到的）

```
Q04 这个月比上个月好还是差   r1=answer(1306字)  r2=clarification
Q10 我要不要关掉最差的那家店  r1=clarification   r2=answer(2081字)
Q18 哪个供应商报价最贵      r1=clarification(45字) r2=answer(196字)
```

▎老板问一次拿到答案、再问一次被反问。**那比稳定地拒答更难建立信任。**

---

## 二 · 翻面发生在哪一层（实测，⛔ 不是读码）

五层各自逐轮记全，⛔ 没有 TRACKED 白名单：
`L1` 记模型原始 dict 的**全部键**，`L3` 记 dataclass 的**全部字段**。

| 层 | 记了什么 | 实测 |
|---|---|---|
| L0 | `call_chain` 的 prompt / 返回体 / model / temperature | `deepseek-v4-flash`、`temperature=0`，**同一句话每轮返回体指纹都不同** |
| L1 | `_semantic_spec_from_t3` 收到的模型原始 dict（含 `missing_fields`，⛔ 它到不了 `_build_spec`） | **翻面在这里已经存在** |
| L2 | `_build_spec` 的每一个 kwarg | 是 L1 的确定性函数 |
| L3 | `RestaurantQuerySpec` 的每一个字段 | 同上（`plan_hash` 相同 ⇒ 计划相同） |
| L4 | `kind` / 字数 / contract / 答案指纹 | 同上 |

▎**判据**：为每个翻面的问句找「组内恒定 + 组间不同」的字段。
▎每个问句都找得到，而且**最上游的那个在 L1** ⇒ 代码各层没有引入新的不确定性。

### 🔴 加了派生谓词层才看得见根因

第一轮把 `dimensions` 判成了「噪声」——因为作答那一组内部就有 `[ingredient]` 和 `[]`
两种值。**确定性在翻的不是字段的值，是字段上的一个谓词。**
补上 `L1p:*_in_vocab` / `L1p:missing_has_*` 之后当场对齐。

## 三 · 翻的是哪一维（逐轮读数，⛔ 不折叠）

### 轴 A · `missing_fields` 里有没有 `metric`（Q04 / Q10）

`ff_cold` 8 轮，MOCK_REST，冷编译，每轮清 4 个缓存，独立 session_key：

```
Q04 这个月比上个月好还是差
  L1:missing_fields        r1=[metric] r2=[store_scope] r3=[store_scope] r4=[store_scope]
                           r5=[store_scope] r6=[metric] r7=[metric] r8=[metric]
  L1p:missing_has_metric   True  False False False False True True True
  L4:kind                  反问  作答  作答  作答  作答  反问 反问 反问     ← 逐格对齐
```

```
Q10 我要不要关掉最差的那家店
  L1p:missing_has_metric   False True  False False False False False False
  L4:kind                  作答  反问  作答  作答  作答  作答  作答  作答     ← 逐格对齐
```

⚠️ Q10 的 `L1:missing_fields` **原始值**是噪声
（`[time_range,metric]` / `[time_range]` / `[time_range,store_scope]` 三种），
因为 `store_scope` 那一项会被 2026-08-18 那条改动摘掉、`time_range` 有默认窗口接住。
**只有 `metric` 那一项没有出路** ⇒ 谓词才是那一维。

### 轴 B · `dimensions` 在不在词表里（Q18）

```
Q18 哪个供应商报价最贵
  L1p:dimensions_in_vocab   True False True True True True True True
  L1p:dimensions_offenders  []  [supplier] [] [] [] [] [] []
  L3:planner_authority      llm  llm_contract_incomplete  llm ×6
  L4:kind                   作答 反问 作答 ×6              ← 逐格对齐
```

模型那份 JSON **除了这一格全都逐字相同**
（`intent=RESTAURANT_OPS_SUPPLIER_PRICE` / `confidence=0.95` / `aggregation=extremes`）。
`supplier` **不在** `_SEMANTIC_DIMENSIONS`（实测 16 个维度里没有它；prompt 里写着
「dimensions 只能使用: …」，所以这是模型不听话，⛔ 不是我们没告诉它）。

▎后果：整份计划作废，老板收到 45 字的
▎**「我还没有完整理解这句话，本次没有按关键词猜测，也没有执行查询。」**
▎—— **那句话是假的。系统理解得好好的**，它只是不认识 `supplier` 这个词。

### 对照组（⛔ 没有它就分不清「这三条特殊」和「所有问句都在翻」）

`哪家店卖得最好` / `按门店看领料趋势` / `一共有多少家店` —— **每一次跑都 100% 稳定作答**
（累计 8+8+8+10+8+12+8 = 62 轮 × 3 条，零翻面）。

## 五 · 🔴 仪器缺陷（两条，先修仪器再看读数）

### ① session_key 跨次复用 ⇒ 量的不是「同一句问两次」

`restaurant_pending_clarifications` 是 **Postgres 表**，主键 `(factory_id, session_key)`，
**跨进程、跨天存活**。探针原来用 `ff-r{轮}-q{下标}` —— 只跟轮次有关。
第二次跑时，上一次留下的「待澄清」把这一次的同一句话当成了**用户在回答上一次的反问**：

```
is_clarification_continuation = True
resolver_query_seed = 「这个月比上个月好还是差 这个月比上个月好还是差」   ← 同一句拼两遍
```

▎**那时量到的不是「同一句问两次」，是「回答上一次的反问」——换了被测对象。**

已修：`PROBE_RUN_ID` 前缀 + 一条阳性对照「续接条数必须为 0，否则 rc=2」。
⚠️ 同形的 key 命名 **`_panorama24` 也有**（`p24-r%d-q%d`）——见第八节。

⛔ **但它不是翻面的成因**：拿同一个 `PROBE_RUN_ID` 跑第二次（故意撞 key）与第一次对比，
两次的续接条数都是 0、翻面数 0 vs 1。**A/B 否掉了这个假设**，⛔ 不是「看着不像」。

### ② 阴性对照挂错了对象

第一版写「被测问句里出现过 clarification，否则 rc=2」——那会把**「本轮没复现」**
误判成仪器坏了。改成一组**真的没指定**的对照问句（`生意下滑了怎么办` / `怎么提升营收`），
它们反问是**对的**行为，只用来证明那条路通，⛔ 不进任何比例的分母。

## 六 · 三个选项

### 选项 1 · 让模型稳下来（收紧 prompt / 换模型 / 加重试投票）

- **代价**：`temperature=0` 已经设了，模型名逐轮相同，prompt 里已经写着
  「dimensions 只能使用: …」。**该说的都说了，它照样不听。**
  重试投票要 2~3 倍 token 和延迟，而单跳预算只有 6s。
- ⛔ **不采纳**。「让模型稳定」是在跟固有性质较劲；该问的是**哪一层吸收它**。

### 选项 2 · 让「要不要问指标」这件事由代码算出来 —— 轴 A

判据从模型的自报 `missing_fields` 换成「这个 intent 的 resolver 有没有无歧义的指标」。

- **代价**：它离已裁定的红线**只差一层皮**。
  2026-08-07 撤回过的那条是「有默认值就压掉澄清」，代价 5 条交互契约；
  2026-08-18 的设计卡也白纸黑字写着「**指标没有无歧义的默认值**，
  补错等于给一个看着像答案的错答案 —— 这两次反问是**对的**」。
  而 Q04（「好还是差」）、Q10（「关不关店」）恰恰是指标真的没定的两句。
- 🔴 **更硬的一条：现在没有可信的验收窗口**（第四节）。
  今天做这个改动，A/B 会显示「反问从 8/36 掉到 0/48」——而**不改也是 0/48**。
- ⏸ **本轮不做，挂账**（解冻条件见第八节）。

### 选项 3 · 不让「一个不认识的词」作废整份计划 —— 轴 B ✅ 采纳

```python
list_contracts = (                     # 成员闸: 值必须在取值域里
    ("requested_metrics", _SEMANTIC_METRICS),
    ("missing_fields", _SEMANTIC_MISSING_FIELDS),
)
shape_only_list_contracts = ("dimensions",)   # 形状闸: 只要求是字符串列表
```

**为什么这是「核对」而不是「放水」**：闸放行之后**紧接着的那一行**本来就是

```python
dimensions = _validated_semantic_tuple(parsed.get("dimensions"), _SEMANTIC_DIMENSIONS)
```

它逐个丢掉不在取值域里的值。**闸和编译器对同一件事有两套规则（形态 D），
而闸那套严格到把整份计划一起扔掉。** 改完之后判据只剩编译器一处。

**净效果**：`["supplier"]` 编译成 `()`，与模型自己另外那两种输出
**同一个 `plan_hash`、同一个答案指纹**。⛔ 没有发明任何新行为。

**⛔ 只放宽 `dimensions` 一个字段**：
- `requested_metrics` 的未知值一旦被丢掉 = 「少算了一项还装作算全了」（降级处理）
- `missing_fields` 的未知值被丢掉 = 「还缺什么」这件事本身失真

（硬约束 8：`_SEMANTIC_DIMENSIONS` 在生产代码里共 **2 处**读者 —— 本闸 + 编译器。
改 1 处，**显式登记不改的那 1 处**及理由。AST 数出 `_validated_semantic_*` 调用点 8 处，
本次一处未动。）

## 七 · 验收（⛔ 不依赖抖动窗口）

### 7.1 A/B：两棵源码树，只差一个文件

```
rsync 两份 prod 源码树 → 只替换 restaurant_intent.py → diff -rq 输出恰好 1 行
同一个 8083 进程的 environ / 同一个 venv 解释器 / 同一个租户 / 同一份输入
输入 = 探针在 prod 抓到的那份模型输出，**逐字**（⛔ 不手搓一份差不多的）
```

| | base（修前） | patched（修后） |
|---|---|---|
| `planner_authority` | `llm_contract_incomplete` | `llm` |
| `intent` | `""` | `RESTAURANT_OPS_SUPPLIER_PRICE` |
| `plan_hash` | `7f8830ef…` | `1255e0d3…` |
| `kind` / 字数 / 答案指纹 | clarification / 45 / `d927f1c9` | **answer / 196 / `b216e623`** |
| 老板看到 | 「我还没有完整理解这句话…」 | 见下 |

**阳性对照**（同一份输入把 `dimensions` 换成 `[]` —— 模型自己的另一种输出）：
两棵树都作答，`plan_hash=1255e0d3…`、答案指纹 `b216e623`。
⇒ 修后那一格与阳性对照**逐字相同**；⛔ 也证明这条链在这个进程里跑得动，
base 那侧的拒答不是「探针起不来」。

**修后老板看到的**（反目标自查：他去查会不会一无所获）：

```
2026-05-22 至 2026-08-19 有 24 条采购报价（24 种食材），但每一条都没记是哪家供应商，
所以比不了价。缺的是采购单据里的供应商这一栏 —— ⛔ 不是「每种食材只有一家」，
是这一栏根本没填。你要做的：让采购在录单据时把供应商填上。
```

▎它**仍然答不出那个数**（数据里真的没有供应商），但它说清了**缺什么、怎么拿到**。
▎⛔ 这不是把拒答换成假数据，是把**一句假话**换成**一句真话**。

### 7.2 变异对照（4 条 × 全部 12 条断言，三层一条不省）

每条变异都**带自己的行为探针输入** —— 共用一个输入时只有 M1 证得了「行为真的变了」，
另外三条会打出「行为没变」，那时 ① 那一层等于没做。

| 变异 | 守的行为 | ① 行为真的变了 | ② 点名命中 | ③ 不该红的没红 |
|---|---|---|---|---|
| M1 把 `dimensions` 挪回成员闸 | 未登记的维度值不许作废整份计划 | `llm` → `llm_contract_incomplete` | **4/4** | ✓ |
| M2 形状闸整块失效 | 放宽的是成员、⛔ 不是形状 | `llm_contract_incomplete` → `llm` | 1/1 | ✓ |
| M3 把 `requested_metrics` 也放宽 | 指标的未知值不许被静默丢掉 | `llm_contract_incomplete` → `llm` | 1/1 | ✓ |
| M4 把 `missing_fields` 也放宽 | 缺项的未知值不许被静默丢掉 | `llm_contract_incomplete` → `llm` | 1/1 | ✓ |

锚点每条恰好命中 1 次 → `compile()` 通过 → 落盘复核 → 跑完还原并逐字比对。
本轮 **0 条**红在 `NameError`/`SyntaxError` 上。

### 🔴 M1 当场抓到一条我自己写的恒真断言

第一版有一条

```python
assert "supplier" not in tuple(_compile().dimensions)
```

M1 变异下**纹丝不动** —— 而行为可观测量已经证明变了。
真相：**整份计划作废时 `dimensions` 同样是空的**，两条路都满足它。
⛔ 不是变异没生效，是这条断言在守空气。改成守「计划还活着 **且** 那一维被丢掉」，
M1 下立刻变红（3/4 → 4/4）。

## 八 · 没做的 + 为什么 + 解冻条件

| 没做 | 为什么 | 解冻条件（⛔ 写死，不写「以后看看」） |
|---|---|---|
| **轴 A：`metric` 缺项的翻面**（选项 2） | 判据离已裁定红线只差一层皮；且**现在没有可信的验收窗口** —— 不改也是 0/48 | 先把「翻面率」变成一条**每天固定时间跑**的读数（`_flipflop_layers` 冷编译 12 轮 + 阴性对照，三态 rc）。**连续 7 天拿到 ≥3 天「阴性对照通过 且 轴 A 翻面 >0」**，才谈动它。⛔ 在那之前任何 A/B 都读不出净效果 |
| **查清「反问率漂到近零」的成因** | 本轮只有现象：同两句对照问句 8-18 是 3/6 和 2/6，8-19 后半段是 0/6，而代码 md5 逐字未变（6 个文件全对上） | 同上那条跑批的第二个输出：把**阴性对照命中率**单独记一条时间序列。它跌破 1/6 时单独告警，措辞与「有翻面」不同（硬约束 4 的 `rc=2` 那一态） |
| **prompt 是不是逐轮相同** | 探针取 `raw_calls[0]`，而**上一轮答案的质量判定是个后台任务**，会落进下一轮的窗口 ⇒ 有时 `raw_calls[0]` 是判定员那次调用，不是规划器那次。本轮**没有干净地量到** | 钩 `ri._build_t3_prompt`（只有规划器那条路会调它）拿 planner 那一次的 prompt，再按它去 `raw_calls` 里配对。⚠️ 这不影响本卡结论：轴 A/B 的判据全在 L1（模型的原始 dict）及其下游 |
| **`_panorama24` 的同形 session_key**（`p24-r%d-q%d`） | 不在本线的改动范围，且它的读数口径由那条线负责 | 把 `PROBE_RUN_ID` 那一格抄过去 + 加同一条「续接条数必须为 0」的阳性对照。⚠️ 在那之前，**它跨次跑出来的「两轮不一致」要打折看**（第二次跑的每一轮都可能是「回答上一次的反问」） |
| **把 `supplier` 加进维度登记表** | 治得了这个词，治不了下一个（`vendor` / `purchase_channel` / 「供应商」）。同一形态本仓已裁定过一次：⛔ 不复活关键词路由，往词表加词是它的小号版本 | 出现「按供应商拆真的能出数」的需求时做 —— 那时要动的是 resolver 的能力声明，⛔ 不是这道闸 |
| **多租户验收** | 只跑了 MOCK_REST。按常设配置这是**冒烟不是验收** | prod 上除 MOCK_REST 外六家餐饮租户当前门店 0 / POS 0（`_probe_bootstrap` 已登记）。等有第二个活租户时在它上面重跑 A/B |
