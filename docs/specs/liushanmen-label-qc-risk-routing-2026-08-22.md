# 六扇门标签质检风险队列与训练队列分流

## 目标

把“客户是否需要处理质检风险”和“平台是否需要补充训练真值”拆成两个互不替代的流程：

- 客户队列只出现缺白标、缺彩标、无法判断、分析失败或其他明确风险。
- 受信任流水线分析成功、每张照片至少识别到一个可核查盒子且没有风险候选的任务进入 `AUTO_PASSED`，在客户端计入已完成，但不显示为人工审核；未识别到盒子本身属于风险。
- 平台训练取样仍可从全部照片中选择模型分歧、低置信、漏框、重复框、困难负样本和新分布样本；AI 框只是预填建议，只有平台或工厂人工确认后才成为真值。
- 已用于开发的真实缺标、合成缺标和冻结时间点后的新增盲测证据分别计数，不以图片总数替代独立泛化证据。

## 状态与数据边界

| 状态 | 客户含义 | 是否进入人工审核队列 | 是否等同人工真值 |
|---|---|---:|---:|
| `AUTO_PASSED` | AI 未发现需要处理的风险 | 否 | 否 |
| `NEEDS_REVIEW` | AI 发现风险或部分图片无法判断 | 是 | 否 |
| `ANALYSIS_FAILED` | 整单分析失败 | 是 | 否 |
| `REVIEWED` | 人工逐图确认并保存 | 否 | 是，限已保存的人审对象 |

`AUTO_PASSED` 不写 `reviewedBy`、`reviewedAt`、`objectReviewedBy` 或人工对象快照；原始图片、AI 初筛明细和模型版本继续保留，供后续平台侧主动学习只读取样。平台训练导出仍只接受明确的人审真值。

当前可追溯数据口径：累计人审 68 个缺标盒，来自 34 张照片、33 个任务；白标缺失 50 个、彩标缺失 36 个，存在同一盒双缺。多组合成集是同源的受控消融，不相加冒充独立真实样本。冻结时间点后的 7 个新增独立缺标任务是最终晋级证据门槛，不是现有缺标总数。

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像

工厂质量检验员 — 熟悉现场产品但不应承担模型训练判断 — 在手机端快速确认真正有风险的照片，希望正常任务不占用审核时间。

平台标注员 — 熟悉盒子、白标和彩标框规则 — 在 Web 端处理主动学习样本和人工真值，不应被客户任务是否通过限制。

### 用户旅程

| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|------|---------|---------|---------|
| 1 | 拍照提交后的分析状态 | 无需额外操作 | AI 自动分析并保留模型与初筛明细 |
| 2 | 无风险任务显示“AI 检查通过” | 返回列表或继续拍照 | 自动计入已完成，不出现人工审核按钮 |
| 3 | 风险任务显示风险类型和上下文 | 打开并逐图修正 | 只处理有风险或无法判断的内容 |
| 4 | 平台独立训练队列 | 选择模型分歧/困难样本并标注 | 人工确认后才进入训练集 |

### 摩擦点清单

| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|-----------|---------|---------|
| F1 | 目前所有分析成功任务都进入待审核，正常图淹没真实风险；反过来若“一个盒子也没识别到”被当作正常，会造成静默漏检 | HIGH | 信息密度 / 防呆原则 |
| F2 | 若把自动通过显示成“人工审核完成”，会让客户误解结果来源 | HIGH | fool-proof Rule 2 |
| F3 | 若客户自动通过同时删除平台取样机会，会损失困难负样本和模型分歧 | HIGH | 数据边界 |
| F4 | 分析失败或部分失败若被自动通过，会造成漏检 | HIGH | fool-proof Rule 1 |
| F5 | 已参与开发的数据若被计作新增盲测，会虚增模型可信度 | HIGH | 数据隔离门禁 |

### 每个摩擦点的设计回应

- F1 → 仅在受信任流水线显式确认、零风险候选、所有照片分析成功且每张至少识别到一个盒子时进入 `AUTO_PASSED`；未识别到盒子生成整图 `UNJUDGEABLE` 风险，其余状态保持人工处理。
- F2 → 客户端使用“AI 检查通过 / 未发现需处理风险”，`REVIEWED` 才显示“人工审核完成”。
- F3 → 保留照片、AI 初筛、模型版本和训练状态；平台选择逻辑不依赖客户待审核状态。
- F4 → 任一照片失败都不得自动通过；整单失败显示可重试和人工检查入口。
- F5 → 回执分别记录训练/验证/保护/盲测和合成来源，合成只进训练。

## 上线与回滚

先以新路由做离线生产回放和 PT/ONNX 一致性，再发布 Python 模型路由；Java/RN/Web 状态改动通过目标测试后发布。上线前对既有六扇门待审核任务做只读预览，只把“AI 候选数为 0、所有照片分析成功、尚未人工处理”的任务列为可自动通过目标；写回必须限定工厂和精确任务条件并记录数量。任一步失败立即恢复旧模型目录、旧服务版本和旧队列行为。
