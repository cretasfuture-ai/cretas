# 六扇门标签拍检拍摄质量门禁

## 目标

在工厂质检员创建标签拍检任务时，把照片质量问题挡在上传之前。门禁只判断照片是否具备人工审核和模型初筛的基本可用性，不替代白标/彩标业务判断。

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 1. 用户画像（User Persona）

- 用户：六扇门现场 QC、班组长或工厂管理员。
- 环境：生产现场，可能戴手套、光线有顶灯反射，通常单手持手机快速完成拍检。
- 技术熟练度：低到中等；不要求理解清晰度分数、模型置信度或图片参数。
- 目标：拍到能看清白标/彩标的照片，快速提交，不因门禁丢失已录入的批次信息。

### 2. 用户旅程（User Journey）

| 步骤 | 用户动作 | 系统反馈 | 下一步 |
| --- | --- | --- | --- |
| 1 | 选择 SKU、填写批次与日期 | 保留现有字段校验和已填状态 | 进入拍摄区 |
| 2 | 点击“拍摄照片” | 在应用内直接打开相机；画面只保留整桌梯形引导框和“最下排完整入框”提示 | 对齐并拍摄 |
| 3 | 按下快门 | 自动检查分辨率、明显模糊、是否检测到托盘以及左右边缘托盘是否被裁切 | 通过后自动收图；失败则留在相机内重拍 |
| 4 | 查看照片列表 | 每张通过门禁的照片显示“已自动检查” | 继续拍摄或提交 |
| 5 | 提交拍检 | 只有至少一张通过门禁的照片才可提交；上传失败保留原状态 | 重试或进入提交完成页 |

### 3. 摩擦点清单（Friction List）

- 现场人员容易忽略长说明；拍前弹窗、编号步骤和拍后清单都会增加停顿。
- 系统相机无法稳定叠加符合六扇门整桌构图的取景引导。
- 图片尺寸合格仍可能运动模糊，或者最下排左右托盘被画面边缘裁掉。
- 数字变焦不能真正扩大视野，不能把“0.5×”做成没有物理超广角镜头的假按钮。
- 门禁若误卡、退出相机或清空表单，会打断生产并诱导员工绕过流程。
- Web 一次选择多张照片时，不能让未通过检查的照片混入已通过列表。

### 4. 设计响应（Design Responses）

- 使用应用内相机，把整张托盘桌放进接近真实照片透视的梯形框；底边单独高亮并只显示“最下排完整入框”。
- 不显示 1/2/3 步骤，不增加拍前弹窗和拍后人工检查页；界面只有关闭、补光、可用时的物理超广角切换和一个快门主动作。
- 先用设备元数据硬门禁：短边至少 960 像素、长边至少 1280 像素。
- 服务端使用生产托盘检测器判断是否看到了足够托盘以及左右边缘是否被裁切；只做拍摄质量判断，不参与白标/彩标业务判定。
- 明显模糊使用统一缩放后的拉普拉斯方差门禁。阈值 500 基于最近 300 张六扇门真实照片校准：明显模糊样本低于阈值，正常样本第 5 百分位约为 544；指标只用于自动门禁，不向员工展示。
- 检查未通过时保持相机和已填表单不变，只显示一条说明原因及下一动作的重拍提示；通过后自动收图。
- 只有设备真实上报物理超广角镜头时才显示 0.5×。当前 Expo 接口仅在 iOS 暴露物理镜头选择；Android 不伪造数字广角。
- 质量服务或托盘模型不可用时失败关闭并要求稍后重试，不能绕过门禁收图。
- Web 多选照片按顺序自动检查；任何照片都不能跳过门禁直接进入列表。

## 验收标准

- 低分辨率、明显模糊、未检测到足够托盘和左右边缘托盘被裁切时均被明确拦截。
- 失败照片不计入照片数量，移动端保持在相机内并显示一条可执行的重拍提示。
- 通过检查的照片不再进入人工清单，自动出现在列表并显示“已自动检查”。
- 拍摄页只保留真实构图梯形、底边高亮和“最下排完整入框”；不出现编号牌照或额外文字检查。
- 支持的 iPhone 上仅在系统上报物理超广角镜头时显示 0.5×；不支持的设备不显示。
- 提交按钮只统计已通过门禁的照片；上传重试语义保持不变。
- 触控目标不小于 44pt，错误信息说明发生了什么以及如何解决。
