# App 报工录入工序工艺标准参数

**日期**: 2026-11-03
**承接**: #1373 (web 工序表录参数 + 超标确认 + paramChecks 快照)
**目标**: 一线在 App 产出报工时，也能按工序配置填写工艺参数（油温 / 时间 / 水分等），
当场看到标准和上下限，超标时提示并在提交前确认；服务端与 web 同口径校验并留快照。

## 现状（只读核查结论）

- 操作员 / yield_operator / 车间主任报工唯一的活路径：`YieldStepReportScreen`
  → `POST /production/batches/{batchId}/reports` → `YieldReportServiceImpl.submitReport`。
- 这条路径目前**不收、不校验、不快照**自定义字段；参数逻辑只在 web 两条路径
  (`ProcessSheetServiceImpl` / `ClerkProcessEntryServiceImpl`) 里。
- 工序任务 (`WorkProcessTaskDTO`) 已带 `workProcessId`，但没带 `customFieldSchema`。
- 同屏已有 CCP 读数段 (`CcpReadingsSection`) —— 按工序拉检查点、录数字、提交时并入请求，
  是本功能的直接样板；确认弹窗用 `appAlert`（Expo Web 上 `Alert.alert` 是空操作）。

## 方案

**后端**
1. `WorkProcessTaskDTO` 增加 `customFieldSchema`（只读，来自已经 join 的 WorkProcess）。
2. `YieldReportRequest` 增加 `customFields: Map<String, Object>`。
3. `YieldReportServiceImpl`：只在 OUTPUT 报工上处理；用该任务的 WorkProcess schema 做
   `ProcessCustomFieldValidation.checkKeys`（未知键 400），`ProcessParamCheck.evaluate` 生成快照；
   写入报工 `customFields.clerkCustomFields` 与 `customFields.paramChecks` —— 与 web 同一命名空间与形状，
   下游读者零改动。超标**不拦**（记录实际发生），判定只在服务端。

**App**
4. 新组件 `ProcessParamsSection`（仿 `CcpReadingsSection`）+ 纯函数工具（与 web `processParamCheck.ts` 同口径：
   判定、标准文案、超标清单），挂在产出报工区，只显示 enabled 字段；没配置就整段不出现。
5. 提交产出报工时：把填了的参数放进同一个请求（不另发请求，避免幂等键轮换问题）；
   有超标项时，在现有确认弹窗里列出超标明细，按钮「按实际值报工」/「返回修改」。

## UX Flow Analysis（ux-flow 门控产出，不可删除）

### 用户画像
车间操作员 / 产出报工员（operator / yield_operator）—— 文化程度不一、年纪偏大，手机上单手操作，
戴手套或手上有油水 —— 在炒锅 / 卤锅边做完一锅后，当场在手机上报产量，顺手记下这锅的油温、时间。

### 用户旅程
| 步骤 | 用户看到 | 用户操作 | 期望结果 |
|------|---------|---------|---------|
| 1 | 「工序」页里自己被分配的工序任务（产品名 + 批次号 + 工序名） | 点进要报工的工序 | 进入该工序的报工页 |
| 2 | 产出数量输入框；其下「工艺参数（按这锅实际填写）」卡，每行：参数名 + 单位、大号数字输入框、下方一行灰字「标准 155℃，范围 150–160℃」 | 填产出数量；照着实际读数填油温等参数 | 每个参数旁边始终能看到标准，不用去问 |
| 3 | 填入值超出范围时，该行灰字变红：「偏高 · 标准 155℃，范围 150–160℃」 | 看到红字，可以改，也可以不改（实际就是这么炒的） | 当场知道超标，不是提交后才被告知 |
| 4 | 点「提交产出」后的确认弹窗：原有的数量确认 + 红色「工艺参数超出标准：油温 165℃，高于标准…」 | 选「按实际值报工」或「返回修改」 | 返回修改 → 回到页面、已填内容不丢；按实际值报工 → 提交成功 |
| 5 | 提交成功提示；这次填的参数随报工一起保存 | — | 车间主任 / 品控事后能看到每锅参数和是否超标 |

### 摩擦点清单
| # | 摩擦点描述 | 严重程度 | 来源规则 |
|---|-----------|---------|---------|
| F1 | 不知道标准是多少，只能凭记忆或问人 | HIGH | fool-proof Rule 1（预先显示边界） |
| F2 | 超标了也无法提交（实际已经炒完了），只能乱填一个合格值 | HIGH | fool-proof Rule 1 / 「禁止降级」—— 记录要反映真实 |
| F3 | 小字号输入看错 / 按错小数点 | MED | 内联 UX 规则：数字输入 ≥ 24px、numeric 键盘 |
| F4 | 字段多时信息过载，分不清哪些必须填 | MED | 内联 UX 规则：每屏只暴露当前步骤需要的信息 |
| F5 | 参数配置加载失败时整页报不了工 | MED | 内联 UX 规则：网络失败显示重试，不显示空白 |
| F6 | 点「返回修改」后已填内容被清空 | MED | 内联 UX 规则：错误后保留已填数据 |
| F7 | 不清楚自己在给哪一锅 / 哪道工序填参数 | LOW | fool-proof Rule 2（上下文带身份信息）—— 页面头部已有产品 + 批次 + 工序，参数卡标题沿用工序名 |
| F8 | 一个工序多次报产出（先保存、后补报），不知道每次都要填 | LOW | 内联 UX 规则：信息密度 |

### 每个摩擦点的设计回应
- F1 → 每个数字参数输入框下方常驻一行「标准 X单位，范围 a–b单位」（只配了上限/下限时显示「不高于 / 不低于」），与 web 同一文案函数。
- F2 → 超标**不禁用**提交；只在提交确认弹窗里列出超标明细并要求二次确认（「按实际值报工」），服务端快照记下 HIGH/LOW。
- F3 → 输入用 Paper `TextInput` + `keyboardType="decimal-pad"`，字号 ≥ 24px；单位贴在输入框右侧；非数字输入时该行提示「请填数字」，不进提交。
- F4 → 只显示 enabled 字段；数字参数按配置顺序排列；卡标题写明「按这锅实际填写，没测的可以不填」——参数非必填（与 web 一致）。
- F5 → 参数定义随工序任务一起返回（不另发请求），没有单独的加载失败面；任务本身加载失败沿用页面现有的重试。
- F6 → 「返回修改」只关弹窗，页面状态（数量 + 参数）原样保留。
- F7 → 参数卡标题「{工序名} 工艺参数」；页面头部已有产品名 + 批次号。
- F8 → 每次产出报工都显示参数卡、都可以填；填了才记录，不强制每次都填。

## 验收

- 后端：真 Spring + H2 合同测试走 `YieldReportController` 入口 —— 超标值落 `paramChecks`（HIGH/LOW/OK 带标准快照）、
  值落 `clerkCustomFields`、未知键 400、INPUT 报工不处理；变异验证（去掉快照那一行测试必须红）。
- App：组件 / 工具单测（标准文案、超标判定、确认弹窗内容、返回修改不丢值）；
  真界面验收（Expo Web）：F006 一条配了标准参数的工序任务，看到标准、超标变红、确认弹窗、提交后库里有快照；阴性对照：未配参数的工序不出现参数卡。
