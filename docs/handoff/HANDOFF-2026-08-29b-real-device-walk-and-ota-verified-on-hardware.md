## 二、🔴 真机揪出的缺陷：「可投上限约 0」(已修, 已上线, PR #320)

```
工序 SOP-20260817-01-黄油鸡-原料处理, 计划数量 0.04 kg
弹窗:      「计划 0.04 kg, 可投上限约 0 (含 30% 超收)」
实际提交 0.04 kg -> 成功
```

`Math.round(0.04 × 1.3)` = `Math.round(0.052)` = **0**。
真正生效的 `plannedMax` **没取整**，只有显示取整了 ⇒ **界面说的和系统拦的是两个数**，且不报错。
凡是计划量 < 约 0.385 的工序，工人看到的都是「可投上限约 0」——那不是近似值，是「一点都不能投」。

⚠️ 它能活这么久，是因为组件 docstring 里唯一的例子是 `计划 998 → 1297`，那个量级取整无害。
⇒ 新闸同时钉小量级（新行为）和大量级（证明没把旧的弄坏）。变异两条各打红不同断言。

📌 **既有的 `yieldToleranceSingleSourceContract` 闸自己写着**：
「扫的是源码文本，证明不了用户真的看到了正确的百分比 —— **那要真机走一遍**」。
这次就是那一遍，而它确实抓到了源码闸看不见的东西。

## 四、⚠️ 两个我报错了、又自己推翻的判断（留痕）

**这一节比上面三节更值得读。**

### 推翻 1：「闸的作用域错了，它是全厂级不是仓库级」

我先看到：唯一的 `INITIATED` 记录 `ST-202608-ED55F497` 在**成品仓**，而我选的是**原料仓** ——
于是准备报「闸说『该仓库』但实际是全厂扫」。**查源码后是错的**：

```java
stocktakeRepo.countActiveStocktakeForWarehouseAndMonth(factoryId, req.getWarehouseId(), periodMonth)
```
```sql
AND s.warehouseId = :warehouseId AND s.status NOT IN ('APPLIED', 'REJECTED')
```

真因在 `NOT IN ('APPLIED','REJECTED')` —— 原料仓有一条 **APPROVED** 的 `ST-202608-6B907387`，
APPROVED 不在排除名单里，所以被算作「进行中」。**闸是对的，作用域也是对的。**

⇒ 剩下的真问题是**措辞**（未修，留给下一位判断）：
- 闸说「**进行中**，请**完成或拒绝**」
- 而盘点记录里那条显示的是「**已审批**」

工人照提示去找「进行中」的，对不上号；而「已审批待生效」他多半也无权处置。

### 推翻 2：「被拒之后按钮变哑了」

我确实两次看到点击无反应。但用「弹窗 → 知道了 → 再点」的干净路径连测两次，**每次都正常弹窗**。
⇒ **没能复现，不作为缺陷报出。** 前面那两次多半是我自己的点击/导航状态问题。

📌 教训：**真机上「点了没反应」是最容易误判成缺陷的读数** ——
它和「我点歪了」「控件还没挂载」「导航栈没回到位」长得一模一样。
判它之前先用一条能稳定复现的路径走两遍。
