## 二、一屏出错掀掉整棵导航树（已修）

逐角色走查：17 个角色 **552 条路由**，**89 条**在不带参数打开时抛
`Cannot destructure property 'xxxId' of 'route.params'`。

`AppErrorBoundary` 包的是**整个 `<AppNavigator />`** ⇒ 一屏出错，导航器整个卸载，
用户看到的不是「这一页打不开」，是**整个应用只剩一张错误卡**。

⇒ 用 react-navigation v7 的 `screenLayout`，按 **navigator（76 处）** 而不是
按 **屏（272 处）** 挂屏级边界。

**同一条命令、同一个仪器，分母不变：**

```
改前  走过 552  出错 89   ☠️ 整树 89 / ▫️ 单屏 0
改后  走过 552  出错 89   ☠️ 整树  0 / ▫️ 单屏 89
```

### 那 40 个屏（去重后）要不要逐个改？—— 量完之后判定：不改

| 量的东西 | 读数 |
|---|---|
| 不带参数的 `navigate/push/replace('X')` | **0** |
| 对象式 `navigate({name:'X'})` 且无 params | **0** |
| **阳性对照**：带参数导航到这些屏的调用 | **75** |
| 深链 | **未配置**（`app.json` 无 `scheme`/`intentFilters`；无 `linking`） |

⇒ **真实用户走不到**；我能打开它们只因为走查工具直接调 `navigationRef.navigate`。
⇒ 屏级边界是相称的修法。结论**有保质期** ⇒ 配闸
`noParameterlessNavigationToDetailScreens.test.ts` 钉住。

## 三、真机走查抓到的（web 看不见的那一面）

驱动方式：`adb screencap` + 视觉判读（MIUI 上 `uiautomator dump` 产出空文件，换这条路绕开）。

1. **「0 总批次 / 1 已完成 / 0.0% 完成率」** —— 前两个量的是**不同事件**
   （`createdAt` vs `endTime`），卡片把它们摆成父子关系；「完成率」是**两端各兜一次 0**。
2. **「¥0 总成本」而同屏「总产出 8 kg」** —— 46 个生产计划的成本列**一个都没填**。
   ⚠️ 而营收 ¥0 是**对的**（0 条出货记录）——「有没有生产计划」这个判据是数据定的。
3. **「¥0.00 单件成本 / 0 工人数」** —— 前者是除以 0；后者**数值对、标签错**
   （实为「计件人数」，而工厂有 22 名在册工人）。
4. **一个我自己引入的回归**：null 比率喂给图表库 → `Cannot read property 'toFixed' of null`
   → 整屏打不开。**被这一轮加的屏级边界兜住**。
   根因是**类型声明说谎**（`otifRate: number` 而后端发 null），tsc 因此成了瞎子。

## 五、仪器坏了 7 次，每次都长成「结论」

| # | 长相 | 真相 |
|---|---|---|
| 1 | 改完重跑仍报 2 崩 | **Metro 在发陈旧 bundle**；而「去主 bundle 里 grep 新串」在 lazy 分包下**本身无效** |
| 2 | 「走过 5 条 \| 0 崩」 | 重启 Metro **漏了 `ENVFILE`** → `@env` 空 → 登录失败停在登录栈。救回来的是「5 条 vs 45 条」这个旁证 |
| 3 | 文本闸报 `3 passed` | 而文件是**语法错**的（机械改写把 import 插进多行 import 中间）。是 tsc 抓的 |
| 4 | 全仓一条都匹配不到 | CRLF 下 `$` 前还有 `\r` |
| 5 | operator1 从 2 虚涨成 9 | `getByTestId(...).count()` 把**上一屏**留在 DOM 里的边界一起数了；`:visible` 拦不住 |
| 6 | 「13 个编造常量」 | **没数全** —— 枚举脚本把 `0/1/100` 当噪音过滤，而缺陷值正好是 **100** |
| 7 | 「有 1 处真实无参导航」 | 没剥注释，把注释里写的 `navigate("StocktakeEntry")` 数成真实调用（同形第三次） |

▎第 5 条特别值得记：它让修复**看起来更糟**而不是更好，反而不容易被当成「修好了」放过去。
